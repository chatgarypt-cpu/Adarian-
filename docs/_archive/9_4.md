# Adarian Phase 1 重构任务上下文（Snapshot）

## 🎯 当前目标

对 Phase 1（世界生成 + Agent 初始化）进行架构重构：

从：
- 单体 Generator（超长 Prompt + 多职责）

升级为：
- 分层结构（可扩展、可维护、可并发）

---

## 🚨 当前核心问题

### 1. Generator 职责过载
单个 Prompt 同时承担：

- event_entities 抽取
- opinion_spreaders 生成
- I / P / susceptibility 分配
- percentage 控制
- persona / personality / phrases 生成
- 关系合法性约束

👉 导致：
- Prompt 过长
- 字段互相干扰
- 扩展困难

---

### 2. 规则分裂（严重问题）

规则分布在：

- Prompt（隐式规则）
- Validator（显式规则）
- PostProcess（修复逻辑）

👉 系统真实逻辑不统一

---

### 3. 不该由 LLM 生成的字段

当前存在问题：

- P（其实是 I 的函数）
- percentage（本质是分布计算问题）
- can_speak / original_statement（已由代码修复）

👉 说明：
**代码比 LLM 更可信**

---

### 4. Phase 1 越界

当前 Phase 1 已经在生成：

- persona_name
- occupation
- personality
- motivation
- typical_phrases

👉 这些属于：
**表达层（应延后或独立）**

---

## 🧠 目标架构（目标状态）

Phase 1 拆为四层：

### Layer 1：Entity Extractor（事实层）
- 提取 event_entities
- 提取 relations
- 不涉及 opinion_spreader

---

### Layer 2：Group Planner（结构层）
- 生成 opinion_spreader 骨架
- 字段：
  - group_name
  - related_entity
  - I
  - susceptibility

👉 不生成：
- P
- percentage
- persona

---

### Layer 3：Persona Writer（表达层）
- 生成人设字段
- 可并发执行

---

### Layer 4：Assembler / Rules Engine（收口层）
- P 推导（代码）
- percentage 归一化（代码）
- 去重
- 合法性校验

---

## ⚠️ 关键设计原则

1. LLM 只负责语义生成  
2. 规则一致性必须由代码保证  
3. 不用 Prompt 修复结构问题  
4. 先结构正确，再优化生成质量  

---

## 🚧 当前决策（重要）

Phase 1 重构不会一次完成，而是拆为三个迭代：

---

### Iteration A（第一阶段）
目标：架构解耦

- 拆 Entity Extractor
- 拆 Group Planner
- 引入 orchestrator
- 保持系统可运行
- 暂不并发
- 暂不迁移所有规则

---

### Iteration B（第二阶段）
目标：规则收口

- P 改为代码推导
- percentage 改为统一归一
- 简化 Validator
- 将 PostProcess 升级为 Rules Engine

---

### Iteration C（第三阶段）
目标：表达层独立 + 并发

- Persona Writer 独立
- 并发执行
- 多样性控制
