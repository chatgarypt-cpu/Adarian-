## 三、Gate 体系映射表

v0.3 定义了 9 级 Gate（Gate 0-8），能力蓝图定义了 7 级 Gate。两者并非互斥，而是视角不同。以下为映射关系：

| v0.3 Gate | 能力蓝图 Gate | 说明 |
|-----------|--------------|------|
| Gate 0: Context Gate | — | v0.3 新增：上下文完整性确认 |
| Gate 1: Plan Gate | Intake Gate | 方案确认门 |
| Gate 2: DAG Gate | — | v0.3 新增：节点拆解合理性的 Owner 确认 |
| Gate 3: Node Gate | — | v0.3 新增：单节点完成验收 |
| Gate 4: AI Repair Gate | — | v0.3 新增：AI 修复闭环的裁决（pass/retry/escalate） |
| Gate 5: Stage Gate | Data Quality Gate / Sample Gate | 阶段间过渡门，对应能力蓝图的"数据质量"和"样张" |
| Gate 6: Product Gate | Product Gate | 成品验收门 |
| Gate 7: Retrospective Gate | Retrospective Gate | 归盘复盘门 |
| Gate 8: Promotion Gate | Promotion Gate | 升格判断门（B → A 线） |

能力蓝图中的 Artifact Gate 在 v0.3 体系中被拆分进了 Node Gate（单节点产物验收）和 Product Gate（最终成品验收）。

## 六、矛盾与缺口汇总

### 6.1 版本号混乱

| 问题 | 说明 |
|------|------|
| v0.2 文件名含"v0.2"但正文标题写"v0.1" | 章节编号重复（两个 §12），约 70% 原文保留 |
| 三套迭代路线不兼容 | v0.3 自有一套、v0.2 自有一套、能力蓝图自有一套 |
| 能力蓝图 v0.1 与 DAG v0.1 同日期 | 两者关系从未在文档中说明 |

### 6.2 目录协议冲突

| 文件 | 层数 | 结构 |
|------|------|------|
| v0.1 | 8 层 | 00_task_brief/ → 07_retrospective/ |
| v0.2 §12.8 | 9 层 | 00_task_brief.md(文件) + 01_dag_plan/ → 08_retrospective/ |

| v0.3 | **无** | 完全缺失 |

### 6.3 其他缺口

| 缺口 | 影响 |
|------|------|
| 并行化协议缺失 | 无法标准化描述 fan-out/fan-in |

### v0.3 需求逐项支撑评估

| v0.3 需求 | Relay Runtime 支撑 | 缺口 |
|-----------|-------------------|------|
| 单 Agent 长程执行 | ✅ R1 充分支撑 | 无 |

| AI 修 AI 闭环 | ⚠️ tmux 可支持，但无 Issue Packet 机制 | 需要 Issue Packet 标准 |
| 分层验收 | ⚠️ result.json 可支持节点级，无上层 | 需要多层验收协议 |
| 记忆隔离 | ❌ 无 scope recall 实现 | 需要 Lane Context 注入 |
| 归盘与升格 | ⚠️ 部分（retrospective 可由 Agent 完成） | 需要升格判断协议 |
