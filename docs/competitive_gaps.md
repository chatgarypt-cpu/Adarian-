# Adarian 系统薄弱环节分析 — 对标学术界前沿

> 生成日期：2026-06-08
> 目的：识别 Adarian 当前 bypass 验证阶段与学术界/业界前沿的差距，
>       为产品化路线提供技术输入。

---

## 1. Agent 认知架构

### Adarian 现状

- Agent 只有单一的 `stance_score`（-10 ~ +10）
- 无记忆模块，每轮 tick 独立产出
- 无情绪/情感模型，只有立场数值

### 学界前沿怎么做

**POSIM (DeepCogLab, 2026)** — BDI (Belief-Desire-Intention) 认知架构：

```
Agent
  ├── Belief:    对事件事实的认知状态（多维度：事实信念、因果信念）
  ├── Desire:    行为倾向（表达、转发、沉默）
  └── Intention: 具体行动（发言内容、互动对象）
```

每轮 tick 更新路径：`新信息 → Belief 更新 → Desire 更新 → Intention 生成 → 行动`

**DualMind (WWW'26)** — 认知-情感双通道模型：

```
Agent State
  ├── Cognitive Channel (慢通道)
  │   ├── 事实记忆（长期）
  │   └── 逻辑推理（逐步演化）
  └── Affective Channel (快通道)
      ├── 即时情感反应（愤怒/支持/嘲讽）
      └── 情绪级联（一条评论触发情绪传染）
```

两条通道耦合：情绪可以压制认知（fact-resistant opinions），认知可以修正情绪。

### 差距程度

**大。** 这是 Adarian 与学界最显著的差距。单维度 stance 无法模拟：
- 事实抗拒型舆论（"我不听事实，我就信我信的"）
- 情绪级联（愤怒传播比理性论证快 10 倍）
- 舆论反转（先愤怒后了解真相）

### 工程建议

不引入完整的 BDI（太重），但在 Phase 3 的 tick 循环里加入：
- `emotion`: 情绪标签（愤怒/支持/嘲讽/中立/焦虑）
- `memory_scene`: 短期记忆（最近 N 条互动）
- `conviction`: 信念固化度（高信念 agent 更抗拒改变）

每轮 tick LLM prompt 增加这几项输入，不改变管线结构，增量添加。

## 2. 社会网络拓扑

### Adarian 现状

- Phase 2 构建基础社交网络（小世界模型 / 随机图）
- 无平台算法模拟
- 无回音室/信息茧房机制
- 网络结构静态（不随时间演化）

### 学界前沿怎么做

**POSIM (2026):**
- 真实社交媒体拓扑（基于 Weibo 用户关注关系）
- 推荐算法模拟（内容热门度 → 推荐概率）
- 信息流剪裁（用户只看到算法推荐的内容，不是全量信息）

**AgentSociety (清华, 2025):**
- 城市级移动网络（agent 在物理空间中移动并相遇）
- 群组动态形成（兴趣群组、话题群组随时间聚合/分裂）
- 多层网络（熟人关系 + 兴趣关系 + 地理位置三重叠）

**SoMe (2025):**
- 8 类社交媒体任务仿真
- 9 million 条真实社交媒体数据
- 32 个平台的真实交互模式

### 差距程度

**中。** 你的基础拓扑是对的，但缺少两个关键变量：
- 推荐算法（决定了 agent 能看到什么信息）
- 回音室（决定了立场极化如何被放大）

### 工程建议

在 Phase 2 增加 `PlatformSimulator`：
- 不需要真实社交图，用参数化模型
- `echo_chamber_strength`: 回音室系数（0=全随机 see，1=只看同类）
- `recommendation_bias`: 推荐算法偏好（热度/立场/随机）
- 这些作为 dataset 中的实验参数，不改变 Phase 3 的 tick 循环

## 3. 真实数据注入

### Adarian 现状

- 全部依赖 LLM 从 seed 文本生成实体和群体
- 无外部数据源注入
- 实体 / 群体 / 立场都是 LLM 猜出来的

### 学界前沿怎么做

**FDE-LLM (2024):**
- 从 Weibo 提取真实舆论领袖（opinion leader）的发言数据
- 领袖用 LLM 角色扮演，但立场变化受真实数据约束
- 跟随者用 CA + SIR 模型驱动，不是 LLM

```
真实 Weibo 数据
  ├── 提取 opinion leader 的 stance + timeline
  ├── 提取话题的传播路径（谁转发了谁）
  └── 提取情感曲线（愤怒/支持随时间变化）
        ↓
LLM Agent 在真实立场轨迹上做角色扮演，
而不是从 0 开始生成
```

**POSIM (2026):**
- 全量使用 Weibo 真实数据集（完整用户交互链）
- 验证阶段：模拟产出 vs 真实舆论曲线对比
- 用多个统计指标（JS 散度、DTW 距离）量化模拟 fidelity

### 差距程度

**中。** 你知道这一步要做什么（架构里已经用 `source_context` 预留了），但还没做。

### 工程建议

三步走：
1. **快速验证**：用已有的 `source_context` schema，手写一个真实事件的数据注入（不接 API，先 mock），看 phase 3/4 消费端能跑通
2. **数据管道**：建 `data/weibo/` 目录 + 抽取脚本，输出格式对齐 `EntityExtractionOutput`
3. **选择器**：Phase 1 入口判断"有真实数据就 bypass LLM 直接喂，没有就走 LLM"

## 4. 推演 fidelity 验证体系

### Adarian 现状

- 无验证数据集
- 无 fidelity 指标
- "跑通 = 成功"，不验证模拟结果是否接近真实

### 学界前沿怎么做

**POSIM, SoMoSiMuBench (2025-2026):**

| 指标 | 测量什么 | 学界的用法 |
|------|---------|-----------|
| JS Divergence | 立场分布差异 | 模拟 vs 真实分布对比 |
| DTW (Dynamic Time Warping) | 时序演化一致性 | 模拟 vs 真实曲线对齐 |
| Polarization RMSE | 极化指数误差 | 每轮极化指数对比 |
| Stance Accuracy | 个体立场命中率 | agent 立场 vs 真人立场 |
| Emotion Trajectory Corr | 情感演化相关度 | 愤怒/支持曲线对比 |

每个论文都跑这些指标证明"我们的模拟 fidelity 更高"。

### 差距程度

**大。** 这是你现在最大的盲区。没有 benchmark 你就无法回答"推演准不准"——产品端问这个问题时你只能答"跑通了"。

### 工程建议

不建完整的 benchmark suite，但加两个最关键的：

1. **事件复现验证**：选一个真实舆情事件（微博热搜），让多模型跑推演 → 对比各模型的舆论场 vs 真实舆论分布
2. **稳定性验证**：同一个 seed + 同一个模型跑 3 次 → 看立场分布方差（好的模拟应该稳定）

这两项可以在 bypass 阶段手动做，不需要自动化 CI。

## 5. 多模型并发的方法论贡献

### Adarian 现状

- 你在这个领域是开创性的
- 学术界没人做"多模型对比推演"
- 所有论文都是"一个模型跑一轮，看 fidelity"

### 学界为什么不做

不是技术原因，是学术发表文化：
- 论文需要讲一个"我们的方法更好"的故事
- 多模型对比暴露了"不同模型建构成不同舆论场"——论文无法声称"我们的方法对"
- 他们就绕过去了，只用一个模型、说自己调参调得好

### 你的方法论贡献

如果你们发 paper/tech report，核心叙事应该是：

> **"舆论场不是客观存在的，它取决于哪个模型建构它。多模型对比比单模型 fidelity 更有信息量。"**

这不是技术对抗，是认识论对抗。学术界假设"有一个真实舆论场，我们在逼近它"。你的系统假设"舆论场是建构的，不同模型建构不同版本的现实"。

| 社会网络拓扑 | 中 | 推演 realism | ⭐⭐ | 加平台算法参数成本低 |
| 多模型并发 | **领先** | — | — | 你在这个维度碾压学界 |
