# Adarian MVP PRD v0.1

## 面向政府决策部门的公共事件舆情风险推演与研判报告系统

## 1. 产品一句话定义

Adarian 是一个面向政府决策部门的公共事件舆情风险推演 MVP，用于从一段公共事件材料出发，模拟不同意见群体的多轮观点演化，并输出可解释、可复盘、可辅助决策的舆情风险报告。

---

## 2. 产品定位

Adarian 当前不是完整舆情监测平台，也不是实时爬虫系统。

当前产品定位是：

```text
公共事件舆情风险推演沙盘
```

它服务的核心场景是：

```text
当一个公共事件刚刚出现，政府决策部门需要快速判断：
这个事件会不会发酵？
哪些群体会激化？
风险来自哪里？
哪些问题需要优先回应？
如果不处理，舆论可能如何演化？
```

Adarian 不承诺“预测真实未来”，而是提供一种**可解释的情景推演结果**，帮助决策人员形成早期研判。

## 4. 核心业务需求

政府决策部门面对公共事件时，最需要的不是“生成评论”，而是形成一份可用于判断和行动的风险报告。

核心业务需求包括：

```text
1. 快速识别事件中的关键主体
2. 判断事件中可能形成哪些意见群体
3. 观察不同群体在多轮传播中的观点变化
4. 判断舆情是否出现极化、对立、负面偏移
5. 找出推动风险上升的关键群体和关键议题
6. 输出一份可解释、可复盘、可给决策层阅读的舆情风险报告
```

---

## 5. 用户场景

### 场景 1：公共事件早期风险研判

用户拿到一段事件材料，例如：

```text
新闻报道
官方通报
微博热搜描述
网民爆料整理
舆情摘要
```

用户希望快速知道：

```text
事件中谁是当事方？
哪些主体可以公开回应？
哪些群体会支持、质疑、观望或对立？
事件是否会引发公信力风险？
舆论可能向哪里偏移？
```

---

### 场景 2：决策前情景推演

在正式发布回应、通报或处置方案前，用户希望模拟：

```text
如果只发布程序性回应，公众是否会继续质疑？
如果没有回应核心争议，哪些群体会进一步激化？
如果强调依法处理，是否能稳定中立群体？
如果忽略程序争议，是否会扩大公信力风险？
```

当前 MVP 暂不直接模拟“政策干预方案”，但可以通过报告提示风险来源和回应重点。

---

### 场景 3：事后复盘与报告生成

事件处置后，用户可以使用系统输出的：

```text
tick_logs.json
final_report.md
final_report.json
run.log
timing_summary.json
run_meta.json
```

复盘一次推演的过程，判断：

```text
系统为什么给出这个风险等级？
哪些群体发生了变化？
哪些阶段出现拐点？
最终报告依据哪些模拟结果生成？
```

---

## 6. 输入

当前 MVP 的输入是：

```text
一段本地公共事件文本
```

典型输入包括：

```text
事件背景
争议焦点
当事人陈述
官方回应
媒体报道
网民质疑点
已有舆论摘要
```

当前不接入：

```text
实时爬虫
数据库
社交平台 API
MCP / Web Search / RAG
多模态图片 / 视频材料
```

---

## 7. 输出

Adarian 的输出分为两类：**决策报告输出**和**复盘证据输出**。

### 7.1 决策报告输出

面向政府决策部门阅读：

```text
final_report.md
final_report.json
```

报告应包括：

```text
事件概要
关键主体
意见群体结构
多轮观点演化
极化指数变化
关键拐点
主要风险点
风险等级
处置建议
舆情态势判断
```

### 7.2 复盘证据输出

面向分析人员和系统开发者：

```text
entities_and_relations.json
social_graph.json
tick_logs.json
run.log
timing_summary.json
run_meta.json
```

用于回答：

```text
这次报告基于哪次运行？
用的是什么 seed？
使用了哪个模型？
Phase 1-4 是否完整跑通？
哪些 agent 发言？
哪些 agent 沉默？
立场如何变化？
报告是否可追溯？
```

## 8. 核心业务流程

```text
用户输入公共事件材料
    ↓
系统识别事件实体和意见群体
    ↓
系统构建主体 / 群体关系网络
    ↓
系统进行多轮观点演化模拟
    ↓
系统计算极化、均值、风险变化
    ↓
系统生成舆情风险报告
    ↓
用户基于报告进行研判和决策
```

---

## 9. MVP 当前能力

当前 v1.2.1 基线已具备：

```text
1. 从 seed 文本启动一次 E2E 推演
2. 生成事件实体和意见传播者
3. 构建社会关系图
4. 执行 Tick 0-N 多轮观点推演
5. 输出群体发言、立场变化和全局指标
6. 生成 Markdown / JSON 风险报告
7. 将一次运行产物归档到独立 run_dir
8. 生成 run.log / timing_summary.json / run_meta.json
```

当前适合作为：

```text
研究原型
内部演示 Demo
政府舆情研判产品雏形
可解释多 Agent 推演样机
```

---

## 10. MVP 成功标准

当前 MVP 不以功能数量作为成功标准，而以“能否形成可用的舆情风险研判闭环”为标准。

成功标准包括：

```text
1. 输入一段公共事件材料后，系统可端到端跑通
2. 系统能生成事件实体、意见群体和关系网络
3. 系统能输出多轮观点演化日志
4. 系统能计算并展示极化趋势和风险等级
5. 系统能生成一份面向决策层的舆情风险报告
6. 报告背后有 tick_logs / run.log / timing_summary 可复盘
7. 每次运行产物归档在独立 run_dir 中，避免证据污染
```

---

## 11. 政府决策部门最关心的问题

Adarian 的报告必须优先回答以下问题：

```text
1. 这个事件当前风险等级是什么？
2. 主要矛盾焦点是什么？
3. 哪些群体正在推动风险上升？
4. 哪些群体仍可被沟通或争取？
5. 舆论是否正在极化？
6. 是否存在公信力风险、程序正义风险、群体对立风险？
7. 如果不及时回应，风险可能往哪里发展？
8. 应优先回应哪些议题？
```

---

## 12. 报告质量要求

面向政府决策部门的最终报告不能只是“模拟日志总结”，必须具备决策价值。

报告应满足：

```text
1. 结论先行
2. 风险等级明确
3. 关键群体明确
4. 风险来源明确
5. 证据链可追溯
6. 避免空泛建议
7. 避免只复述事件材料
8. 避免把模型生成内容当作真实舆情事实
```

报告措辞应区分：

```text
事实材料
模型推演结果
风险判断
处置建议
```

## 13. 当前已知限制

当前系统仍存在以下产品限制：

```text
1. 不能代表真实舆情预测，只能作为情景推演参考
2. 输入材料质量会显著影响推演结果
3. 当前不具备联网检索和事实补全能力
4. 当前无法自动获取当事人完整公开发言
5. 当前 speaker 为什么发言 / 沉默 / 被阻断的解释仍不足
6. 当前 stance_delta 的语义原因仍不足
7. 当前 saw_posts_from 只能说明看到谁，不能证明被谁影响
8. 当前报告存在“解释强于底层证据链”的风险
```

其中第 5 点是 v1.2.2 的优先治理方向。

## 14. v1.2.2 产品目标

v1.2.2 的产品目标不是提升模拟效果，而是提升白盒解释能力。

版本名称：

```text
v1.2.2 - White-box Observability for Speaker Behavior
```

目标：

```text
让系统能解释每个 agent 为什么发声、为什么沉默、为什么被阻断。
```

拟新增观测字段：

```text
speaker_status
speaker_reason
decision_source
selector_score
selector_rank
candidate_count
selected_count
speaker_budget
selection_policy
can_speak_reason
speech_availability
source_basis
```

v1.2.2 明确不做：

```text
不做 influence_trace
不做 stance_delta 语义解释
不接 MCP / Web Search / RAG
不做 logging migration
不做 CLI
不改 speaker selector 策略
不改发言生成逻辑
```

解决：


解决：

```text

是否标记 direct_quote / reported_speech / no_source？
```

基于 `outputs/runs/<run_id>/` 实现：

```text
adarian runs list
adarian runs show <run_id>
adarian report <run_id>
adarian timing <run_id>
```

## 17. 产品原则

```text
1. 面向决策，不面向炫技
2. 报告优先，不是聊天优先
3. 可解释优先，不是规模优先
4. 可复盘优先，不是生成效果优先
5. 先保证一次运行可信，再考虑多次运行对比
6. 先补白盒证据链，再优化模拟质量
7. 所有模型结论必须能追溯到 run artifacts
```
