## 🎯 本次修复目标

### 问题 1：已故/匿名实体不应发言
**现象**：
- 胖猫（已故）在 Tick 0 发言："我只是一個普通網遊玩家..."
- 当事学生（匿名）在 Tick 0 发言："我坚决维护事实真相..."
- 违背现实逻辑，降低模拟可信度

**解决方案**：
- 为 Entity 增加 `can_speak` 字段（bool，无默认值）
- LLM2 根据实体类型判断：机构默认 true，个人根据是否已故/匿名判断
- LLM3 校验 `can_speak` 合理性（检测关键词）
- Tick 0 只让 `can_speak=true` 的实体发言

### 问题 2：Tick 0 未提取种子材料中的原始发言
**现象**：
- 种子材料："南通文旅在评论区留下'哪位少爺吸了'一句"
- 系统生成："该评论为不当言论，已严肃处理。"（事后声明）
- 应该是："哪位少爺吸了"（原始发言）

**解决方案**：
- 为 Entity 增加 `original_statement` 字段（Optional[str]）
- LLM2 从种子材料中提取原始发言（优先直接引语）
- Tick 0 优先使用 `original_statement`，无则 LLM 生成

### 任务 1：修改 schemas.py - 新增字段

**功能**：为 Entity 增加发言能力和原始发言字段

class Entity(BaseModel):
    name: str

### 任务 2：修改 phase1_entity_extraction.py - LLM2 输出格式

**功能**：LLM2 为每个事件实体标注 `can_speak` 和提取 `original_statement`

**修改位置**：`src/phase1_entity_extraction.py` 中的 `LLM2_SYSTEM_PROMPT`

**输入**：
- 种子材料文本
- LLM1 输出的事件参数

**输出**：
```json
{
  "event_entities": [
    {
      "name": "胖貓",
      "type": "individual",
      "role": "事件当事人",
      "entity_category": "event_entity",
      "can_speak": false,
      "original_statement": null
    },
    {
      "name": "南通文旅",
      "type": "organization",
      "role": "评论引发争议的官方账号",
      "entity_category": "event_entity",
      "can_speak": true,
      "original_statement": "哪位少爺吸了"
    }
  ]
}
```

**LLM Prompt 要点**：
- `can_speak` 判断规则：
  * 机构/组织：默认 true
  * 个人：已故 → false，匿名 → false，具名在世 → true
- `original_statement` 提取规则：
  * 优先提取"直接引语"（带引号的发言）
  * 如果有多条，提取"引发舆情的那一条"
  * 如果没有直接引语但有转述，提取转述内容
  * 如果完全没有，设为 null

**技术要求**：
- `can_speak` 必须为 bool 类型，不能为 null
- `original_statement` 可以为 null

---

### 任务 3：修改 phase1_entity_extraction.py - LLM3 校验规则

**功能**：LLM3 校验 `can_speak` 和 `original_statement` 的合理性

**修改位置**：`src/phase1_entity_extraction.py` 中的 `LLM3_SYSTEM_PROMPT`

**输入**：
- LLM2 输出的实体数据
- 种子材料文本

**输出**：
- 校验通过：返回 `{"valid": true}`
- 校验失败：返回 `{"valid": false, "errors": ["错误描述"]}`

**LLM Prompt 要点**：
- `can_speak` 合理性校验：
  * 检查种子材料中是否有"已故"、"去世"、"死亡"、"离世"、"身亡"等关键词
  * 如果有，检查对应实体的 `can_speak` 是否为 false
  * 检查是否有"匿名"、"佚名"、"当事人"、"受害者"、"网友"等匿名表述
  * 如果有，检查对应实体的 `can_speak` 是否为 false
- `original_statement` 合理性校验：
  * 如果 `original_statement` 不为 null，检查种子材料中是否确实有该发言
  * 如果种子材料中没有，报错要求修正或设为 null

**技术要求**：
- 校验失败时，LLM2 需要重新生成

### 任务 5：修改 phase3_tick_simulation.py - EVENT_ENTITY_POST_SYSTEM_PROMPT

**功能**：优化 Prompt，禁止生成"事后声明"

**修改位置**：`src/phase3_tick_simulation.py` 第 68 行

**输入**：
- entity_name, entity_type, entity_role, event_summary, seed_text

**输出**：
```json
{
  "comment": "你的声明内容（100字以内）",
  "reasoning": "你为什么这样说（30字以内）"
}
```

**LLM Prompt 要点**：
- 这条声明应该是"事件起点"，而不是"事后回应"
- **禁止生成"道歉声明"、"澄清说明"、"事后回应"**
- 错误示例："该评论为不当言论，已严肃处理"
- 正确示例：基于你的角色和立场的初始表态

**技术要求**：
- 输出必须为 JSON 格式
- comment 不超过 100 字

### 任务 6：修改 phase4_report_agent.py - 区分发言/被讨论实体

**功能**：报告中区分"发言实体"和"被讨论实体"

**修改位置**：`src/phase4_report_agent.py` 中生成报告的 Prompt

**输入**：
- Phase 1 输出的实体数据（包含 `can_speak`）
- Tick 0 的发言记录

**输出**：
- Markdown 报告，包含两个实体列表

**输出格式**：
```markdown
## 事件实体

### 发言实体（2个）
| 实体 | 角色 | Tick 0 发言 |
|------|------|------------|
| 南通文旅 | 评论引发争议的官方账号 | "哪位少爺吸了" |
| 兵團禁毒 | 发布普法视频的官方机构 | "我们始终坚决打击毒品犯罪..." |

### 被讨论实体（1个）

**LLM Prompt 要点**：
- 发言实体：在 Tick 0 发布声明的实体
- 被讨论实体：不可发言，但被其他实体讨论的实体（如已故人物、匿名个体）

**技术要求**：
- 报告格式为 Markdown
