## 🎯 本次迭代目标

### 问题描述

* 当前存在的问题：

  * 当前 Phase 3 仍采用 **Tick 1+ 全量发言** 模式，所有 opinion spreader 每轮都会进入发言生成流程，复杂度随传播者数量线性上升。
  * 当前 `AGENT_POST_SYSTEM_PROMPT` 和 `AGENT_POST_USER_PROMPT` 直接消费完整 persona 档案、事件背景、关注对象发言和最近 5 轮历史，单次发言 prompt 过重。
  * 直接改成“固定抽样发言”会在小规模 agent 条件下导致每轮内容变薄，削弱报告可解释性和微观演化观感。
  * 当前系统还没有显式的传播状态层，但未来若要与 SEIR 思路对齐，需要把“谁发言”从硬编码规则改成可由态度和传播状态驱动的调度行为。SEIR 文献明确强调：传播强度受公众态度调制，系统呈现多阶段扩散与再爆发特征。
* 影响范围：

  * Phase 3 运行时长
  * 小规模场景下的内容密度
  * 后续 state machine / SEIR adapter 演进路径
  * 当前 normal 模式可用性
* 是否为结构性问题（是/否）：**是**

---

### 解决目标

* 本次希望达成的效果：

  * 将 Phase 3 从“固定全员发言”升级为“**自适应发言调度**”
  * 在小规模 agent 条件下保留较高内容密度，在中规模条件下降低无效重复发言
  * 引入 `Adaptive Speaker Selector`
  * 引入 `Simulation Card / Persona Projection`
  * 裁剪上下文窗口，降低单次发言成本
  * 将 `run_tick()` 内部解耦，为下一版 state machine 做准备
* 是否允许 breaking change：**否**
* 本次是否涉及架构调整（是/否）：**是**

# 🧠 架构变更说明（新增关键模块）

### 当前结构问题

* 当前 `run_tick()` 仍以“遍历所有 spreader → 每人生成发言 → 更新状态”的方式推进，发言调度、上下文构造、状态写回全部耦合在一起。结合当前 Phase 3 源码，这一点已经非常明显。
* 当前 Phase 3 没有区分：

  * 哪些 agent 需要公开发言
  * 哪些 agent 只需要状态更新
  * 哪些 agent 虽未发言，但仍然应在宏观统计中体现
* 当前系统的 Phase 3 输出仍主要围绕 `TickLog.entries + global_metrics(x(t), std, polarization)` 组织，还没有进入显式的传播状态建模阶段。

---

### 目标结构（本次之后）

列出模块划分：

* **Module A：Adaptive Speaker Selector**

  * 根据 `spreader_count + tick阶段 + activity/exposure` 自适应决定本轮 speaker 数量
  * 不再固定“全员发言”
  * 也不采用死板的固定 top-k

* **Module B：Simulation Card Builder**

  * 将完整 persona 投影为 Phase 3 专用轻量画像
  * 降低 prompt 体积

* **Module C：Context Builder**

  * 负责裁剪：

    * followed comments
    * 历史发言
    * 事件摘要
  * 统一构造轻量上下文

* **Module D：Silent Agent Updater**

  * 对未被选中的 agent 做轻量数值更新
  * 不调用 LLM

* **Module E：Tick Assembler**

  * 汇总 speakers 与 silent agents 的本轮结果
  * 输出兼容现有 `TickLog`

# 🔄 数据流变化（新增关键模块）

### 旧流程

（简述旧数据流）

`Tick t -> all spreaders speak -> full persona prompt -> LLM x N -> update all states -> TickLog`

特点：

* 所有人都说
* 所有人都走完整 prompt
* 内容密度高，但复杂度不受控

---

### 新流程（本次迭代后）

（简述新数据流）

`Tick t -> adaptive speaker selection -> build simulation cards -> build lightweight contexts -> generate posts for selected speakers -> update silent agents -> assemble tick log`

特点：

* 不是“减少发言”，而是“按规模与阶段自适应发言”
* 保证小规模下内容不稀
* 保证中规模下复杂度不爆

# 📦 字段职责迁移（新增关键模块）

### 从重 Prompt 输入中移除（改为 projection / 摘要）

* 字段：

  * `age_range`
  * `occupation`
  * `full motivation`
  * `communication_style`
  * `full typical_phrases`
  * `full description`
* 原因：

  * 这些字段对每一轮发言的边际价值低于 token 成本
  * 当前 Phase 3 超时，优先级应是控制复杂度而不是保留完整档案

# 🔧 详细修改指令（给 Codex）

## 任务 1：

**目标**：实现 Adaptive Speaker Selector

**输入**：

* `tick`
* `spreader_count`
* 当前 spreader 列表
* 当前 activity / exposure / stance 波动信息

**输出**：

* `selected_speakers`
* `silent_agents`

**实现要求**：

* 不允许再默认“所有 spreader 都发言”
* 必须采用自适应规则，而不是固定 top-k

### 自适应规则（必须实现）

#### 小规模（≤ 8 spreaders）

* Tick 1：100% 发言
* Tick 2：80% ~ 100%
* Tick 3+：≥ 60%

#### 中规模（9 ~ 15 spreaders）

* Tick 1：80%
* Tick 2：60% ~ 70%
* Tick 3+：50%

### 最小发言保障（强制）

```python
min_speakers = max(4, ceil(spreader_count * 0.5))
```

### 选择公式

```python
num_speakers = max(min_speakers, ceil(spreader_count * ratio))
```

### score 计算（初版允许简化）

```python
score = activity_level + exposure_level + novelty_score + random_noise
```
