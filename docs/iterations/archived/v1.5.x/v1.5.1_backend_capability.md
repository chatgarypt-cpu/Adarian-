# v1.5.1 — 后端真实能力补全：Review / Report / World Detail / Observability

> 四层工作流。独立归档。v1.5.x 后端能力对前端承诺的补全版。
> v1.5.0 做了 mock→真实 API 的替换，但 review 返回占位文字、report 文件下不了、per-world 细节不可见。
> v1.5.1 把这些缺口补上，并将已有 CLI/runtime 观测能力统一暴露给前端运行台。

## 第 1 层：Owner Brief

**1. 这轮干嘛？**

改善后端真实能力，对齐前端已有功能承诺：

- **Review**：`GET /api/review/:batch_id` 不再返回"已生成 simulation_dataset"这种占位文字，改为从 `simulation_dataset.json` 解析 `risk_verdict`、`risk_type_classification`，做多模型风险对比。
- **Report**：v1.5.1 只保留报告占位和已有报告文件下载能力；报告生成/重构进入 v1.5.2（只走受控 download endpoint，不挂载整个 outputs 静态目录）。
- **World Detail**：新增 API 暴露每 world 的 tick 级数据（agent 发言、智能体数量、时间线），前端新增 world detail 页面做多粒度对比。
- **运行事件与观测 API**：复用已有 `run.log` / `run_meta.json` / `tick_logs.json` / `scheduler_batch.log` / `TokenTracker` 产物，统一归一化为前端运行台需要的 batch event stream、world event stream、metrics summary、error reason library。

**2. 这轮不再做什么？**

- DS 集群问题（`100.89.3.80:8006` 后端未开，非代码事项）
- 修改 pipeline 内部（phase/analysis/parser/llm_client）
- 不新增第二套 runtime logger / token tracker / event bus
- cancel/retry（已从 v1.5 系列移出）
- SSE 实时推送（后续迭代）
- 在线报告编辑（后续迭代）

**3. 这轮为什么现在做？**

v1.5.0c 已打通 API + SQLite + 前端入口链路，所有端点的骨架都在。但：
- Review 页的"主要风险对比"表里是硬编码占位文字（"已生成 simulation_dataset"），用户看不出和分析结果
- Report 页生成的 JSON 前端拿不到（url 是本地路径）
- Run 页只能拿到粗粒度 `logs: string[]`，缺少结构化事件、world 级日志、错误原因归类、耗时/token 汇总

v1.5.1 补这些缺口后，前端的 8 个页面才算"真能用"，并能支撑后续真实运行台体验。

### 2. Goals & Boundaries

#### 2.1 Goal 1: Review 真实风险数据

**现状**：`GET /api/review/:batch_id` 返回每 world 的 `risks` 为 `"已生成 simulation_dataset，可进入报告阶段"`，`level` 为 `"可用"`。

**目标**：从已完成 world 的 `simulation_dataset.json` 读取：

```python
# 读取路径
dataset = json.loads(Path(state.dataset_path).read_text())
sim = dataset.get("simulation_result", {})
risk_verdict = sim.get("risk_verdict", {})
risk_type = sim.get("risk_type_classification", {})
source_context = dataset.get("source_context", {})
event_entities = source_context.get("event_entities", [])
opinion_spreaders = source_context.get("opinion_spreaders", [])
agent_stance_matrix = sim.get("agent_stance_matrix", [])
```

返回给前端的 `RiskComparison` 包含：
- `risks`：`risk_type_classification.type_labels` 中文逗号分隔
- `level`：`risk_verdict.level` 转中文（低风险/中风险/高风险/严重）
- `entities`: `len(event_entities)` 智能体数量
- `opinions`: 优先 `len(agent_stance_matrix)`，缺失时回退 `len(opinion_spreaders)`
- `evidence`: `dataset_path` + `run.log` 尾部 20 行

**不做什么**：
- 不新增 LLM 调用
- 不改 simulation_dataset 的 schema
- 不改 review API 的响应结构（只填真实数据）

#### 2.2 Goal 2: Report 占位 + 已有文件可下载

**现状**：Report 页需要保留入口，但报告生成逻辑将在 v1.5.2 重构；v1.5.1 只要求已有报告文件可下载，不能用 fake 报告冒充真实生成。

**唯一方案**：新增受控下载 endpoint，不挂载整个 `outputs/runs/`。
```python
from flask import send_from_directory

@serve_bp.get("/api/report/<batch_id>/files/<filename>")
def download_report_file(batch_id, filename):
    """Serve generated report files."""
    batch = db.get_batch(batch_id)
    if not batch:
        return {"code": "BATCH_NOT_FOUND", ...}, 404
    run_dir = Path(batch["batch_dir"])
    return send_from_directory(run_dir, filename)
```

返回给前端的 `url` 改为可访问的相对路径，如 `/api/report/<batch_id>/files/report.json`。如果 batch 没有已有报告文件，`POST /api/report` 返回 `REPORT_GENERATION_DEFERRED`，提示报告生成在 v1.5.2 重构。

**边界**：
- 不修改 `src/adarian/serve/static.py`。
- 不提供 `/outputs/<path:path>` 之类的泛静态访问。
- 只允许下载当前 batch 目录下白名单报告文件。

**验收**：前端点击已有报告文件能下载到本地；没有报告文件时展示 v1.5.2 占位说明；任意目录遍历、非报告文件、跨 batch 文件请求必须拒绝。

#### 2.3 Goal 3: Per-World Detail API + 前端页面

**新增组件**：

**后端** `GET /api/run/<batch_id>/worlds`：
- 返回 world 列表（不含详细数据，只有摘要）

**后端** `GET /api/run/<batch_id>/worlds/<world_idx>/summary`：
- 返回该 world 的 simulation_dataset 摘要：
  - event_entities 数量
  - opinions 数量
  - risk_verdict (level, basis, scores)
  - risk_type_classification (primary_types, type_labels, primary_domain)
  - source_context 中的原始事件文本
  - run 耗时

**后端** `GET /api/run/<batch_id>/worlds/<world_idx>/ticks`：
- 返回 tick_logs.json 内容（每轮的 tick 数据 + speaker 发言）

**后端** `GET /api/run/<batch_id>/worlds/<world_idx>/log`：
- 返回 run.log 尾部 120 行（通过 `serve/observability.py` 读取，不复用旧服务代码）

**实现要求**：
- `world.py` 不直接散落 JSON parsing 逻辑；统一调用 `serve/observability.py` 的 artifact reader。
- world 定位统一使用 SQLite `db.list_worlds(batch_id)` 的 `world_index`，禁止从目录名猜测。
- 对缺失产物返回结构化 `missing` 状态，不返回 fake 内容。
- `ticks` 端点返回原始 tick 数据时要保留 speaker 发言字段；前端产品化摘要由前端或 event normalizer 做，不改 `tick_logs.json`。

**前端** `/world` 页面（新增第 9 页）：
- 选择 batch 和 world
- 分 tab 视图：摘要 / Ticks / 日志
- 摘要 tab：卡片展示实体数、立场数、风险等级、类型标签
- Ticks tab：每轮列出 speaker 及其发言，支持展开/折叠
- 日志 tab：逐行可滚动 run.log

**前端** Review 页的每行增加"查看详情"按钮，跳转到对应 world 的 detail 页面。

**不做什么**：
- 不做 timeline 动画对比
- 不做多 world 同框对比（后续版本）
- 不改 tick_logs 和 simulation_dataset 的文件结构

#### 2.4 Goal 4: 统一运行事件与观测 API

**现状**：
- `scheduler_batch.log` 在 `execute_session()` 最后一次性写入，运行时 `GET /api/run/:id/status` 的 `logs` 字段经常为空。
- 每个 world 的 `run.log` 已包含 `RUN START/END`、`PHASE START/END`、`LLM START/END`、`TICK END`、`ERROR`。
- `run.log` 尾部已有 `RUN SUMMARY` / `PHASE SUMMARY` / `TICK SUMMARY` / `TOKEN SUMMARY` / `ERROR SUMMARY`。
- `run_meta.json` 已包含 run status、elapsed、model、输出路径等元数据。
- `tick_logs.json` 已包含 Phase 3 每轮 speaker 发言与 stance 变化。
- 这些能力目前只存在于 CLI/文件产物里，前端 API 没有统一契约。

**目标**：新增唯一 serve 层归一化 helper：`src/adarian/serve/observability.py`。它只读取已有产物，不重新采集、不新增第二套 logger。

**统一输出四类数据**：

1. **Batch Event Stream**
   - 批次启动、调度、运行中、完成数、失败数、最长运行 world、总耗时、下一步建议。
   - 不包含 world 内部 agent 发言。

2. **World Event Stream**
   - 单个 world 的 phase start/end、tick end、LLM call、ERROR、run end。
   - Phase 3 的 agent 发言来自 `tick_logs.json`，不是从 raw log 文本里猜。

3. **Metrics Summary**
   - batch：total elapsed、completed/running/failed、可用报告数。
   - world：run elapsed、phase elapsed、tick count、LLM call count。
   - token：total tokens、prompt/completion tokens、per phase、per model。

4. **Error Reason Library**
   - 将 raw error 归类为稳定枚举，供前端展示和后续重试策略复用：

```python
error_reason = Literal[
    "timeout",
    "keyboard_interrupt",
    "api_auth",
    "api_network",
    "api_rate_limit",
    "model_not_found",
    "dataset_missing",
    "parser_failed",
    "report_failed",
    "unknown",
]
```

**数据源优先级**：

| 数据 | 权威来源 | 说明 |
|------|----------|------|
| batch 状态 | SQLite batch/world rows + `scheduler_batch.log` | API 级总览 |
| world phase/LLM/error | `run.log` | 复用 `RuntimeLogger` 既有格式 |
| world metrics | `run_meta.json` + run.log summary | 不新增 timing 文件 |
| token metrics | run.log `TOKEN SUMMARY`，后续可由现有 TokenTracker summary 落结构化文件 | 本轮先解析现有摘要，不新增 tracker |
| agent 发言 | `tick_logs.json` | 禁止从 log 文本反推 |
| review 风险 | `simulation_dataset.json` | 与 Goal 1 同源 |

**batch.py 最小改动**：
- 保留 `BatchSession.log()` 作为唯一 batch scheduler 事件入口。
- 新增/调整 `_flush_scheduler_log(session)`：每次 `session.log(...)` 后或每个 world 状态变化后 flush 到 `scheduler_batch.log`。
- 不新增另一套 batch event recorder。

**验收**：
- batch 运行时刷新 status 能看到 batch raw log tail。
- `GET /api/run/<id>/events?scope=batch` 返回 batch 级事件，不展示 agent 发言。
- `GET /api/run/<id>/worlds/<idx>/events` 返回该 world 的 phase/tick/agent/error 事件。
- `GET /api/run/<id>/metrics` 返回总耗时、局部耗时、token 汇总。
- `GET /api/run/<id>/errors` 返回稳定错误分类与建议。

### 3. Architecture Decisions

#### 3.1 数据源权威

所有 review / world detail / observability API 唯一数据源是 SQLite world row + filesystem 上的已验证产物文件：
- `simulation_dataset.json` → risk/review/entity/summary 数据
- `tick_logs.json` → per-tick agent 数据
- `run.log` → 时间线/日志
- `run_meta.json` → 元数据

通过 `db.list_worlds(batch_id)` 获取每 world 的 `run_dir`，再由 `serve/observability.py` 读 filesystem。不改现有关联逻辑。

#### 3.2 Review 风险数据空处理

如果某个 world 的 `simulation_dataset.json` 不存在或缺少 `risk_type_classification`：

```python
risks = "待检测"  # 如果 world 还在 running
level = "待定"
entities = 0
opinions = 0
```

如果 world 已 `completed` 但 dataset 缺失，`risks` 标注"产物缺失"。

#### 3.3 Report 下载安全

- 只允许下载 `report.*`（`.json` / `.md`）文件，不允许目录遍历
- `filename` 校验：`"report"` 开头且不含 `..`

```python
SAFE_REPORT_PREFIXES = ("report.json", "report.md", "final_report.json", "final_report.md")
```

#### 3.4 观测能力单源规则

**唯一允许新增的观测归一化模块**：

```text
src/adarian/serve/observability.py
```

职责边界：
- 读取现有产物：`scheduler_batch.log`、`run.log`、`run_meta.json`、`tick_logs.json`、`simulation_dataset.json`。
- 归一化为前端 API 数据结构。
- 归类错误原因。
- 汇总 batch/world metrics。

明确禁止：
- 禁止新增 `runtime_logger_v2.py`、`event_bus.py`、`token_tracker_v2.py` 等平行实现。
- 禁止在 `api/run.py`、`api/world.py`、`api/review.py`、`api/report.py` 里各自写一套 artifact parsing。
- 禁止从 `run.log` 反推 agent 发言；agent 发言只来自 `tick_logs.json`。
- 禁止以 mock 数据填补缺失产物；缺失必须返回 `missing` / `unavailable` 状态。

#### 3.5 前端运行台消费原则

- `/run` 总览消费 batch event stream 和 batch metrics，只展示总体阶段、耗时、成功/失败/运行数量。
- `/run` 单 world 视图消费 world event stream 和 tick speaker events，展示 phase 与 agent 信息流。
- `运行日志` 面板消费 raw log tail；它是工程排查视角，不承担产品化总结。
- 切换 world 不重放历史流；只切换当前筛选视图并定位最新事件。只有用户主动点击"重播/回放"才重放。
- v1.5.1 接入真实接口后，当前 fake preview 只能作为 empty-state/demo fallback，不能与真实 batch 数据并列展示。
