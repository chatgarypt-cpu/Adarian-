## 🎯 本次修复目标

### 目标 1：拆分 event_temperature 职责
**问题**：`event_temperature` 同时决定人数规模和极端派比例，职责混杂
**解决方案**：拆分为 `event_scale`（规模）+ `event_controversy`（争议性）

### 目标 2：引入 IPC 框架
**问题**：当前 stance_score 单一维度，无法清晰表达立场方向和强度
**解决方案**：引入 SEIR Paper 的 I（强度）/ P（方向）/ C（一致性）三维度

### 目标 3：废除 confirmation_bias_level
**问题**：该参数设计初衷是"调节 agent 发言多样性行为"，但从未正确实现
**解决方案**：废除该参数，变化幅度全由 susceptibility 接管

### 目标 4：合并 group_distribution_strategy
**问题**：group_distribution_strategy 与 event_controversy 功能重叠
**解决方案**：合并进 event_controversy，由其统一控制 P 的分布

## 🔧 详细修改指令

### 任务 1：schemas.py 数据结构改造

**功能**：改造数据结构以支持 IPC 框架

**步骤**：

1. 在 `EntityExtractionOutput` 中：
   - 废除 `event_temperature: float`
   - 废除 `event_intensity: float`
   - 新增 `event_scale: float`（0.0-1.0）
   - 新增 `event_controversy: float`（0.0-1.0）
   - 新增 `event_type: str`

2. 在 `OpinionSpreader` 中：
   - 废除 `stance_score: float`
   - 废除 `confirmation_bias_level: str`
   - 新增 `I: float`（1-10）
   - 新增 `P: int`（+1 或 -1）
   - 保留 `susceptibility: float`

3. 新增计算属性：
   ```python
   @property
   def C(self) -> float:
       """C = P × (I/10)，系统固定推导"""
       return self.P * (self.I / 10)

   @property
   def stance_score(self) -> float:
       """兼容属性：将 I/P 映射回 1-10 分数"""
       if self.P == +1:
           return self.I
       else:
           return 11 - self.I
   ```

4. 更新 `model_dump()` 输出，确保 C 和兼容属性不进入 JSON（仅内存使用）

**技术要求**：
- I ∈ [1, 10]，P ∈ {+1, -1}，由 Validator 保证
- C 不作为存储字段，仅作为计算属性

### 任务 2：Analyzer Prompt 重写

**功能**：Analyzer 输出 event_scale + event_controversy + event_type

**Prompt 要点**：

1. **event_scale 定义**（替代原 event_temperature 的"人数"维度）：
   ```
   【event_scale（事件规模）】
   - 0.0 = 个人事件，几乎无人讨论
   - 1.0 = 全社会事件，全民关注
   - 判断标准：
     - 涉及范围：个人(0.2) < 群体(0.5) < 全社会(0.8)
     - 参与多样性：单一群体(0.2) < 多个群体(0.5) < 全民参与(0.8)
   - event_scale 用于决定 Agent 总人数
   ```

2. **event_controversy 定义**（合并原 event_temperature 的"争议性"维度和 group_distribution_strategy）：
   ```
   【event_controversy（事件争议性）】
   - 0.0 = 事实清晰、对错分明
   - 1.0 = 高度对立、黑白颠倒
   - 判断标准：
     - 是非清晰度：事实清晰(0.2) < 存在争议(0.6) < 高度对立(0.9)
     - 道德判断：明确对错(0.2) < 灰色地带(0.5) < 黑白颠倒(0.8)
   - event_controversy 用于决定 P（立场方向）的分布比例
   - 高争议 + 官方拒不承认 → 极低支持者比例
   ```

3. **event_type 定义**：
   ```
   【event_type（事件类型）】
   - 分类：食品安全、医疗事故、校园暴力、官员不当行为、环境灾害、产品质量问题、政策争议、学术不端、普通事故、明星娱乐等
   - 用途：作为可调参接口，影响争议性偏移系数（后续版本实现）
   - 当前版本：event_type 仅记录，不影响计算
   ```

4. **输出 JSON 格式**：
   ```json
   {
     "event_scale": 0.0到1.0之间的浮点数,
     "event_controversy": 0.0到1.0之间的浮点数,
     "event_type": "事件类型",
     "event_summary": "一句话概括（50字以内）",
     "reasoning": "简要说明参数判断依据"
   }
   ```

**技术要求**：
- event_scale 和 event_controversy 各自独立评分，不再混合
- group_distribution_strategy 不再作为独立字段输出

### 任务 3：Generator Prompt 重写

**功能**：Generator 输出 I + P，接收 IPC 上下文和分布约束

**Prompt 要点**：

1. **IPC 定义上下文**（内嵌）：
   ```
   【I（Intensity，立场强度）1-10】
   - I 越高，越不容易被说服改变立场
   - I=8-10：极度坚定
   - I=4-6：中等坚定
   - I=1-3：极易动摇

   【P（Position，立场方向）】
   - +1 = 支持/维护
   - -1 = 反对/批评
   - 由 I 决定：I ≥ 6 → P=+1；I ≤ 5 → P=-1

   【C（Consistency）】
   - 由系统计算：C = P × (I/10)
   - 你不需要生成 C，系统会自动推导
   ```

2. **约束传递**（event_scale + event_controversy → I/P 分布）：
   ```
   【分布约束】
   - event_scale: {event_scale} → 决定 I 分布和人数：
     * < 0.3：3-5 人，I 偏中立（3-6 为主）
     * 0.3-0.7：5-7 人，I 中等分布（4-7 为主）
     * ≥ 0.7：7-10 人，I 高度分化（3-10）
   - event_controversy: {event_controversy} → 决定 P 分布：
     * < 0.3：反对 40% / 支持 60%
     * 0.3-0.7：反对 55% / 支持 45%
     * > 0.7：反对 70% / 支持 30%
   ```

3. **输出 JSON 格式**：
   ```json
   {
     "event_entities": [...],
     "opinion_spreaders": [
       {
         "group_name": "群体名称",
         "related_event_entity": "关联事件实体",
         "description": "人设描述",
         "I": 1.0到10.0之间的浮点数,
         "P": +1 或 -1,
         "susceptibility": 0.0到1.0之间的浮点数,
         "estimated_percentage": 0到100之间的整数,
         "communication_style": "说话风格",
         "entity_category": "opinion_spreader"
       }
     ],
     "relations": [...]
   }
   ```

4. **废除内容**：
   - 移除 `stance_score` 字段
   - 移除 `confirmation_bias_level` 字段

**技术要求**：
- Generator 在约束范围内自主判断 I 和 P 的具体值
- I ∈ [1, 10]，P ∈ {+1, -1}

### 任务 4：Validator Prompt 重写

**功能**：校验 I/P 格式合理性

**Prompt 要点**：

1. **校验规则更新**：
   ```
   【校验规则】
   1. I 必须为 1.0-10.0 之间的浮点数
   2. P 必须为 +1 或 -1
   3. susceptibility 必须为 0.0-1.0 之间的浮点数
   4. opinion_spreaders 总数 ≤ 15
   5. estimated_percentage 之和 ≈ 100（允许 ±10 误差）
   6. 至少有一个 P=+1 和一个 P=-1（确保双向对立）
   ```

2. **C 的合理性**：由系统计算保证，Validator 无需校验

3. **废除校验**：
   - stance_score 不再存在
   - confirmation_bias_level 不再存在
