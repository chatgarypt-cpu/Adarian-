### 问题 1：stance_score 语义混乱（🔴 致命）

**现象**：
```json
// tick_1.json 实际结果
{"group_name": "花西子死忠粉", "previous_stance": 8.5, "current_stance": 1.5, "stance_delta": -7.0}
{"group_name": "维权消费者",   "previous_stance": 2.5, "current_stance": 8.5, "stance_delta": +6.0}
```

**问题分析**：
- "花西子死忠粉"初始 stance = 8.5（支持品牌），但 tick_1 直接降到 1.5
- "维权消费者"初始 stance = 2.5（批评品牌），但 tick_1 直接升到 8.5
- 高分和低分的语义在 Phase 3 的 Prompt 中从未被明确定义
- LLM 自行解释 stance_score 的方向，导致每次运行结果不一致

**根本原因**：
- Phase 3 的 Agent 发言 Prompt 中缺少 stance_score 的语义锚定
- LLM 不知道"高分代表支持还是批评"，自由发挥导致逻辑混乱

**修复方案**：
- 在 Phase 3 的每次发言 Prompt 中，明确注入 stance_score 的语义定义
- 同时告知 Agent 当前自己的立场含义（"你当前的立场分为 X，这意味着你[支持/中立/批评]品牌"）

// tick_1.json：confirmation_bias_level = "strong" 的 Agent

**修复方案**：
- 在 Phase 3 的 Prompt 中，将 `confirmation_bias_level` 翻译为具体的变化上限指令
- 在 Phase 3 的代码层面，增加 stance 变化的硬性约束（不依赖 LLM 自觉遵守）

### 任务 A1：修改 `phase2_topology_builder.py` - 跨圈层关注机制

**修改位置**：构建 `edges` 列表的逻辑部分

**当前逻辑（错误）**：
```python
# 只建立同群体内部连接
for agent in periphery_agents:
    edges.append({"source": agent.id, "target": core_agent.id, "type": "follows"})
```

**修改后的逻辑**：
```python
import random

def build_edges(agents: List[GraphNode]) -> List[Dict]:
    """
    构建社交网络边，引入跨圈层关注机制

    为什么这样做（Why）：
    - 真实社交媒体中，用户不只关注同立场的人
    - 跨圈层关注是"群体极化"和"沉默的螺旋"的前提条件
    - 没有跨圈层连接，不同立场的 Agent 永远无法互相影响

    修改于：v1.1.3
    """
    edges = []

    # 按 archetype_index 分组
    groups = {}
    for agent in agents:
        idx = agent.archetype_index
        if idx not in groups:
            groups[idx] = {"core": [], "periphery": []}
        if agent.role == "core":
            groups[idx]["core"].append(agent)
        else:
            groups[idx]["periphery"].append(agent)

    # 获取所有 Core 节点（用于跨圈层连接）
    all_cores = [a for a in agents if a.role == "core"]

    # 规则 1：每个 Periphery 必须关注自己群体的 Core
    for idx, group in groups.items():
        for periphery in group["periphery"]:
            for core in group["core"]:
                edges.append({
                    "source": periphery.id,
                    "target": core.id,
                    "type": "follows"
                })

    # 规则 2：每个 Periphery 以 50% 概率额外关注 1-2 个其他群体的 Core
    for agent in agents:
        if agent.role != "periphery":
            continue
        # 获取其他群体的 Core（排除自己群体）
        other_cores = [
            c for c in all_cores
            if c.archetype_index != agent.archetype_index
        ]
        if not other_cores:
            continue
        # 50% 概率触发跨圈层关注
        if random.random() < 0.5:
            # 随机选 1-2 个其他群体的 Core 关注
            num_cross = random.randint(1, min(2, len(other_cores)))
            cross_targets = random.sample(other_cores, num_cross)
            for target in cross_targets:
                edges.append({
                    "source": agent.id,
                    "target": target.id,
                    "type": "follows_cross_group"  # 区分跨圈层连接
                })

    # 规则 3：Core 节点之间以 30% 概率互相关注
    for i, core_a in enumerate(all_cores):
        for core_b in all_cores[i+1:]:
            if core_a.archetype_index == core_b.archetype_index:
                continue  # 跳过同群体
            if random.random() < 0.3:
                edges.append({
                    "source": core_a.id,
                    "target": core_b.id,
                    "type": "follows_core_cross"
                })

    return edges
```

### 任务 A2：修改 `phase2_topology_builder.py` - Agent 个体差异化

**修改位置**：Agent 实例化部分（将 archetype 转化为具体 Agent 的逻辑）

**修改逻辑**：
```python
import random

def instantiate_agents(archetypes: List[Archetype]) -> List[GraphNode]:
    """
    将 archetype 实例化为具体 Agent，添加个体差异化随机扰动

    为什么这样做（Why）：
    - 同一群体内部不应该完全一致，真实群体中有激进派和温和派
    - 添加随机扰动后，同群体的 Agent 会产生差异化行为
    - Core 节点扰动小（代表群体核心，观点稳定）
    - Periphery 节点扰动大（代表群体边缘，观点易变）

    扰动规则：
    - Core 节点：stance ±5%，susceptibility ±5%
    - Periphery 节点：stance ±15%，susceptibility ±15%

    修改于：v1.1.3
    """
    agents = []
    agent_id = 0

    for arch_idx, archetype in enumerate(archetypes):
        # 确定该 archetype 的 Agent 数量（根据 estimated_percentage）
        num_agents = calculate_agent_count(archetype.estimated_percentage)

        for i in range(num_agents):
            role = "core" if i == 0 else "periphery"

            # 根据 role 确定扰动范围
            jitter_range = 0.05 if role == "core" else 0.15

            # 添加随机扰动
            raw_stance = archetype.stance_score
            jitter_stance = raw_stance * random.uniform(-jitter_range, jitter_range)
            new_stance = round(
                max(1.0, min(10.0, raw_stance + jitter_stance)), 2
            )

            raw_susceptibility = archetype.susceptibility
            jitter_susc = raw_susceptibility * random.uniform(-jitter_range, jitter_range)
            new_susceptibility = round(
                max(0.0, min(1.0, raw_susceptibility + jitter_susc)), 2
            )

            agents.append(GraphNode(
                id=agent_id,
                group_name=archetype.group_name,
                archetype_index=arch_idx,
                related_entity=archetype.related_entity,
                role=role,
                stance_score=new_stance,
                susceptibility=new_susceptibility,
                confirmation_bias_level=archetype.confirmation_bias_level  # ← 透传
            ))
            agent_id += 1

    return agents
```

### 任务 B1 + B2 + B3：修改 `phase3_tick_simulation.py` - Prompt 修复与硬性约束

**修改位置 1**：Agent 发言 Prompt 模板

**完整的新 Prompt 模板**：

```python
STANCE_SEMANTICS = """
【立场分（stance_score）语义定义 - 必须严格遵守】
- 1.0 ~ 3.0：强烈批评（你对品牌/相关方持负面态度，支持维权、质疑品牌）
- 4.0 ~ 6.0：中立观望（你不偏向任何一方，保持理性分析）
- 7.0 ~ 10.0：强烈支持（你对品牌/相关方持正面态度，维护品牌形象）

注意：立场分的高低方向在整个模拟过程中保持不变。
"""

CONFIRMATION_BIAS_PROMPTS = {
    "strong": """
【确认偏差指令 - 强】
你有极强的确认偏差。
- 如果你看到的发言与你的立场一致，你会更加坚定，立场分可以小幅增强（最多 +0.3）
- 如果你看到的发言与你的立场相反，你会完全忽略甚至反驳，立场分几乎不变（最多 ±0.3）
- 你的立场变化幅度在任何情况下都不超过 ±0.3
""",
    "weak": """
【确认偏差指令 - 弱】
你有轻微的确认偏差。
- 如果你看到的发言与你的立场一致，你会比较认同，立场分可以适度增强
- 如果你看到的发言与你的立场相反，你会有所保留，但可能略微被影响
- 你的立场变化幅度不超过 ±1.0
""",
    "none": """
【确认偏差指令 - 无】
你没有明显的确认偏差，是一个理性的观察者。
- 你会认真考虑你看到的每一条发言，无论是否与你的立场一致
- 如果对方的论点有说服力，你愿意改变自己的看法
- 你的立场变化幅度不超过 ±2.0
"""
}

def build_agent_prompt(
    agent: GraphNode,
    saw_posts: List[Dict],
    entities_context: str,
    event_summary: str
) -> str:
    """
    构建 Agent 发言 Prompt

    为什么这样做（Why）：
    - v1.1.2 的 Prompt 缺少 stance 语义定义，导致 LLM 自由解释分数方向
    - v1.1.2 的 confirmation_bias_level 只是文本标签，没有转化为行为约束
    - 本版本通过明确的语义定义 + 变化上限指令，约束 LLM 的输出范围

    修改于：v1.1.3
    """

    # 1. stance 语义解释
    stance = agent.stance_score
    if stance <= 3.0:
        stance_meaning = f"你当前立场分为 {stance}，这意味着你【强烈批评/不信任】相关品牌或主播"
    elif stance <= 6.0:
        stance_meaning = f"你当前立场分为 {stance}，这意味着你【中立观望】，尚未明确站队"
    else:
        stance_meaning = f"你当前立场分为 {stance}，这意味着你【强烈支持/信任】相关品牌或主播"

    # 2. 确认偏差指令
    bias_instruction = CONFIRMATION_BIAS_PROMPTS[agent.confirmation_bias_level]

    # 3. 看到的发言
    if saw_posts:
        posts_text = "\n".join([
            f"- [{p['group_name']}] {p['comment']}"
            for p in saw_posts
        ])
        posts_section = f"你刚刚看到了以下发言：\n{posts_text}"
    else:
        posts_section = "你还没有看到其他人的发言，这是你的第一条评论。"

    prompt = f"""
你正在扮演一个真实的中国社交媒体用户，参与以下事件的讨论：

【事件背景】
{event_summary}

【相关实体信息】
{entities_context}

【你的身份】
- 群体：{agent.group_name}
- 你关注的核心实体：{agent.related_entity}
- {stance_meaning}

{STANCE_SEMANTICS}

{bias_instruction}

{posts_section}

【你的任务】
请根据你的身份、立场和上述确认偏差规则，完成以下输出：

1. comment（你发布的一条社交媒体评论，50字以内，符合你的立场和人设）
2. reasoning（你为什么这样发言，10-20字）
3. new_stance_score（你的新立场分，必须是 1.0-10.0 之间的浮点数，必须符合你的确认偏差约束）

请严格按照以下 JSON 格式输出，不要输出其他内容：
{{
  "comment": "...",
  "reasoning": "...",
  "new_stance_score": 数字
}}
"""
    return prompt
```

**修改位置 2**：stance 变化硬性约束（代码层面，不依赖 LLM 自觉遵守）

```python
STANCE_CHANGE_LIMITS = {
    "strong": 0.3,
    "weak": 1.0,
    "none": 2.0
}

def apply_stance_constraint(
    previous_stance: float,
    proposed_stance: float,
    confirmation_bias_level: str
) -> float:
    """
    在代码层面强制约束 stance 变化幅度

    为什么需要代码层约束（Why）：
    - LLM 可能无法严格遵守 Prompt 中的数字约束
    - 代码层的 clip 操作是最后一道防线
    - 确保无论 LLM 输出什么值，最终写入的变化都在合理范围内

    新增于：v1.1.3
    """
    max_change = STANCE_CHANGE_LIMITS.get(confirmation_bias_level, 1.0)
    delta = proposed_stance - previous_stance

    # 如果变化超出限制，截断到最大变化幅度
    if abs(delta) > max_change:
        clipped_delta = max_change if delta > 0 else -max_change
        final_stance = previous_stance + clipped_delta
    else:
        final_stance = proposed_stance

    # 确保在 1.0-10.0 范围内
    return round(max(1.0, min(10.0, final_stance)), 2)
```

**修改位置 3**：在主循环中调用约束函数

```python
# Phase 3 主循环中，每次更新 stance 时调用约束
def process_agent_tick(agent: GraphNode, saw_posts: List[Dict], ...) -> TickEntry:
    """
    处理单个 Agent 的一个时间步

    修改于：v1.1.3
    修改历史：
    - v1.1.0: 初始实现
    - v1.1.2: 增加实体信息注入
    - v1.1.3: 增加 stance 语义定义、确认偏差约束、硬性变化限制
    """
    # 构建 Prompt
    prompt = build_agent_prompt(agent, saw_posts, entities_context, event_summary)

    # 调用 LLM
    response = llm_client.call(prompt)

    # 解析 LLM 输出的新 stance
    proposed_stance = response["new_stance_score"]

    # ← 新增：代码层硬性约束
    final_stance = apply_stance_constraint(
        previous_stance=agent.stance_score,
        proposed_stance=proposed_stance,
        confirmation_bias_level=agent.confirmation_bias_level
    )

    return TickEntry(
        agent_id=agent.id,
        group_name=agent.group_name,
        saw_posts_from=[p["agent_id"] for p in saw_posts],
        previous_stance=agent.stance_score,
        current_stance=final_stance,
        stance_delta=round(final_stance - agent.stance_score, 2),
        comment=response["comment"],
        reasoning=response["reasoning"]
    )
