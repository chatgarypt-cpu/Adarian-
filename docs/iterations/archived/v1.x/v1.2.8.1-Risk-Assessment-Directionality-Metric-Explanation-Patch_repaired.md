## 10. Expected Risk Logic

### 10.1 计算组件

```python
final_x = x_t_sequence[-1]
start_x = x_t_sequence[0]
negative_pressure = max(0, 5.0 - final_x)
negative_trend = max(0, start_x - final_x)
final_pol = polarization_timeline[-1]
max_negative_shift = max opinion spreader start-to-end negative shift; if unavailable, None and ignored

max_negative_shift SHALL be computed by reusing the logic in
_build_code_owned_agent_stance_matrix() to obtain per-agent initial_stance and
final_stance, then taking max(0, initial_stance - final_stance) across all agents.

If fewer than 2 tick_logs with entries exist, or if no agent appears in both start
and end ticks, max_negative_shift SHALL return None and be ignored in assess_risk().

Codex must not modify Phase 3 tick_logs structure, must not add new speaker/entity
classification fields, and must not hard fail the report pipeline when this value
is unavailable.

prior_floor = derived from event_scale / event_controversy; risk_type_labels only participates when an existing stable whitelist is available
```

### 10.2 MEDIUM 候选条件

```text
满足任一条件可进入 MEDIUM 或至少 prior_floor：

1. final_x <= 4.7
2. negative_trend >= 0.4
3. final_pol >= 0.30
4. max_negative_shift >= 1.2
5. event_scale >= 0.7 and event_controversy >= 0.7
6. sensitive risk_type_labels 命中（仅限当前已有稳定白名单；否则不启用该条件）
```

### 10.3 HIGH 候选条件

```text
满足任一条件可进入 HIGH：

1. final_pol >= 0.45 且存在 negative_trend 或 max_negative_shift。
2. max_negative_shift >= 2.0 且 sensitive risk_type_labels 命中（仅限当前已有稳定白名单）。

4. event_scale >= 0.7 and event_controversy >= 0.7 and final_pol >= 0.40。
```

### 10.4 CRITICAL 候选条件

3. max_negative_shift >= 2.5
4. event_scale >= 0.7 or event_controversy >= 0.8 or sensitive risk_type_labels 命中（仅限当前已有稳定白名单）
