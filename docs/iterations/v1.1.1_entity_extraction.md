## 🎯 本次修复目标

### 问题 1：Agent 生成缺少事件结构化信息作为锚点

**现象**：
- 当前 Phase 1 直接让 LLM 凭空想象"这个事件会有哪些人群"
- 生成的 Agent 可能与事件核心实体无关（如"防晒霜重金属超标事件"生成了"网红博主"）
- 缺少事件本身的结构化信息（实体、关系）作为生成约束

**解决方案**：
- 新增 Phase 0：从种子文本中提取核心实体（人物、组织、地点）和实体间关系
- Phase 1 基于实体生成 Agent，确保每个 Agent 都通过 `related_entity` 字段与某个核心实体关联
- 这样生成的 Agent 更"接地气"，符合事件的真实利益相关方结构

---

### 问题 2：Agent 数量和极端程度无法根据事件热度动态调整

**现象**：
- 所有事件都生成固定数量的 Agent（当前为 5-15 个），无论事件规模大小
- 极端立场 Agent 的比例固定，无法反映事件的争议性和社会影响力
- "防晒霜超标"和"武大图书馆冲突"的舆论烈度完全不同，但生成的 Agent 结构却一样

**解决方案**：
- Phase 0 输出 `event_temperature`（0.0-1.0 浮点数），表示事件的"热度/烈度"
- `event_temperature` 由 LLM 根据以下维度综合判断：
  - **涉及范围**：个人事件 < 群体事件 < 全社会事件
  - **争议性**：事实清晰 < 存在争议 < 高度对立
  - **社会影响**：局部影响 < 行业影响 < 全国关注
- Phase 1 根据 `event_temperature` 动态决定：
  - Agent 总数（低温 3-5 个，中温 5-7 个，高温 7-10 个）
  - 极端派占比（低温 < 20%，高温 30-50%）

---

### 问题 3：Agent 缺少"确认偏差强度"字段，无法模拟"死忠粉"

**现象**：
- 当前 Agent 只有 `susceptibility`（易感性），表示"容易被他人影响的程度"
- 但缺少"确认偏差（Confirmation Bias）"的显式建模
- 导致所有 Agent 在看到反对意见时，都可能改变立场，无法模拟"铁杆支持者"或"坚定反对者"

**理论依据**：
- 参考论文《Simulating Opinion Dynamics with Networks of LLM-based Agents》
- 论文发现：LLM 天生倾向于收敛到"科学真相"，无法模拟抗拒事实的人群
- 解决方法：通过 Prompt 注入确认偏差指令（Weak/Strong Confirmation Bias）

**解决方案**：
- Phase 1 输出增加 `confirmation_bias_level` 字段（取值：none/weak/strong）
- 分配规则：
  - `stance_score` 极端（< 3 或 > 7）且 `susceptibility` 低（< 0.5）→ `strong`
  - `stance_score` 中立（4-6）且 `susceptibility` 高（> 0.7）→ `none`
  - 其他情况 → `weak`
- 为后续 Phase 3 的 Agent 发言 Prompt 注入确认偏差指令做准备

### 任务 1：新增 `src/phase0_entity_extraction.py`

**功能**：从种子文本中提取核心实体、实体关系和事件热度参数

**输入**：
- `seeds/event.txt`（种子文本文件路径）

**输出**：
- `outputs/entities_and_relations.json`

**输出格式**：
```json
{
  "event_summary": "某知名美妆品牌防晒霜被曝重金属超标，客服回应引发争议",
  "core_entities": [
    {
      "name": "某美妆品牌",
      "type": "organization",
      "role": "事件主体"
    },
    {
      "name": "消费者",
      "type": "group",
      "role": "受影响方"
    },
    {
      "name": "监管部门",
      "type": "organization",
      "role": "监管方"
    }
  ],
  "relations": [
    {
      "source": "某美妆品牌",
      "target": "消费者",
      "type": "销售关系"
    },
    {
      "source": "监管部门",
      "target": "某美妆品牌",
      "type": "监管关系"
    }
  ],
  "event_temperature": 0.75,
  "event_type": "产品质量危机"
}
```

**LLM Prompt 设计要点**：

```
[System]
你是一位资深的事件分析专家。你的任务是从一段新闻/事件材料中提取核心信息。

你必须严格按照以下 JSON 格式输出，不要输出任何其他内容：
{
  "event_summary": "一句话概括事件（50字以内）",
  "core_entities": [
    {
      "name": "实体名称",
      "type": "individual | organization | group",
      "role": "在事件中的角色"
    }
  ],
  "relations": [
    {
      "source": "实体A的名称",
      "target": "实体B的名称",
      "type": "关系类型（如：雇佣、监管、销售）"
    }
  ],
  "event_temperature": 0.0到1.0之间的浮点数,
  "event_type": "事件类型（如：产品质量危机、校园冲突、政策争议）"
}

约束条件：
1. core_entities 数量必须在 3-5 个之间（只提取最核心的实体）
2. 实体类型说明：
   - individual: 具体的个人（如"肖同学"）
   - organization: 组织机构（如"武汉大学""某品牌"）
   - group: 群体（如"消费者""学生群体"）
3. event_temperature 的判断标准：
   - 涉及范围：个人事件(0.2) < 群体事件(0.5) < 全社会事件(0.8)
   - 争议性：事实清晰(0.3) < 存在争议(0.6) < 高度对立(0.9)
   - 社会影响：局部(0.2) < 行业(0.5) < 全国(0.8)
   - 综合三个维度取平均值
4. relations 必须基于 core_entities 中的实体，source 和 target 必须是已提取的实体名称

[User]
请分析以下事件材料：
{seed_text}
```

**技术要求**：
- 使用 `llm_client.py` 中的统一 LLM 调用接口
- 使用 Pydantic 的 `EntityExtractionOutput` 模型校验输出
- 如果 LLM 输出格式不合法，自动重试，最多 3 次
- 如果 3 次都失败，抛出异常并记录错误信息
- 函数签名：
  ```python
  def extract_entities(seed_file: str) -> EntityExtractionOutput:
      """
      从种子文本中提取核心实体和关系
      
      为什么需要这个模块（Why）：
      - 当前 Phase 1 直接生成 Agent，缺少事件结构化信息作为锚点
      - 通过先提取实体，可以确保生成的 Agent 与事件核心利益相关方对齐
      
      新增于：v1.1.1
      """
  ```

```json
      }
    ]

```

**LLM Prompt 改进要点**：

```
[System]
你是一位资深的社会舆情分析师。你的任务是基于事件的核心实体和关系，
推断出在社交媒体上会参与讨论的典型人群。

事件信息：
- 事件摘要：{event_summary}
- 核心实体：{core_entities}（JSON 列表）
- 实体关系：{relations}（JSON 列表）
- 事件热度：{event_temperature}（0.0=冷门事件，1.0=全网热议）
- 事件类型：{event_type}

你必须严格按照以下规则生成人群画像：

1. 人群必须与核心实体有直接或间接关系
   - 例如：如果实体是"武汉大学"，可以生成"武大在校生""武大校友""教育工作者"
   - 禁止生成与实体无关的人群（如"网红博主""海外华人"）

2. 人群数量由事件热度决定：
   - event_temperature < 0.3：生成 3-5 个 archetype
   - 0.3 <= event_temperature < 0.7：生成 5-7 个 archetype
   - event_temperature >= 0.7：生成 7-10 个 archetype

3. 极端立场人群（stance_score < 3 或 > 7）的占比由事件热度决定：
   - event_temperature < 0.5：极端派总占比 < 20%
   - event_temperature >= 0.5：极端派总占比 30-50%

4. confirmation_bias_level（确认偏差强度）的分配规则：
   - stance_score < 3 或 > 7（极端立场）且 susceptibility < 0.5 → "strong"
   - stance_score 在 4-6 之间（中立）且 susceptibility > 0.7 → "none"
   - 其他情况 → "weak"

5. 每个 archetype 必须包含 related_entity 字段，值必须是 core_entities 中某个实体的 name

输出格式：
{
  "event_summary": "事件一句话摘要",
  "conflict_axes": ["冲突轴1", "冲突轴2"],
  "archetypes": [
    {
      "group_name": "群体名称",
      "related_entity": "关联的实体名称（必须在 core_entities 中）",
      "description": "50字以内的人设描述",
      "stance_score": 1.0到10.0之间的浮点数,
      "susceptibility": 0.0到1.0之间的浮点数,
      "confirmation_bias_level": "none | weak | strong",
      "estimated_percentage": 0到100之间的整数,
      "communication_style": "该群体的典型说话风格"
    }
  ]
}

约束条件：
1. archetypes 数量必须符合上述规则 2
2. 所有 estimated_percentage 之和必须等于 100
3. 至少包含一个 stance_score < 3.0 的群体和一个 > 7.0 的群体
4. 极端派占比必须符合上述规则 3
5. confirmation_bias_level 的分配必须符合上述规则 4

[User]
请分析以下事件材料：
{seed_text}

核心实体信息：
{entities_json}
```

### 任务 3：更新 `src/schemas.py`

**新增数据模型**：

```python
from pydantic import BaseModel, Field, validator
from typing import List, Literal

# ========== Phase 0 相关模型 ==========

class Entity(BaseModel):
    """
    事件核心实体
    
    新增于：v1.1.1
    """
    name: str = Field(..., description="实体名称")
    type: Literal["individual", "organization", "group"] = Field(
        ..., description="实体类型"
    )
    role: str = Field(..., description="在事件中的角色")


class Relation(BaseModel):
    """
    实体间关系
    
    新增于：v1.1.1
    """
    source: str = Field(..., description="关系起点实体名称")
    target: str = Field(..., description="关系终点实体名称")
    type: str = Field(..., description="关系类型")


class EntityExtractionOutput(BaseModel):
    """
    Phase 0 输出：实体提取结果
    
    新增于：v1.1.1
    """
    event_summary: str = Field(..., description="事件摘要")
    core_entities: List[Entity] = Field(
        ..., min_items=3, max_items=5, description="核心实体列表"
    )
    relations: List[Relation] = Field(..., description="实体关系列表")
    event_temperature: float = Field(
        ..., ge=0.0, le=1.0, description="事件热度参数"
    )
    event_type: str = Field(..., description="事件类型")

    @validator("core_entities")
    def validate_entity_count(cls, v):
        if not (3 <= len(v) <= 5):
            raise ValueError("core_entities 数量必须在 3-5 个之间")
        return v


# ========== Phase 1 相关模型（修改）==========

class Archetype(BaseModel):
    """
    Agent 原型画像
    
    修改于：v1.1.1
    修改历史：
    - v1.1.0: 初始实现
    - v1.1.1: 增加 related_entity 和 confirmation_bias_level 字段
    """
    group_name: str
    related_entity: str = Field(
        ..., description="关联的核心实体名称（必须在 Phase 0 的 core_entities 中）"
    )  # ← 新增字段
    description: str
    stance_score: float = Field(ge=1.0, le=10.0)
    susceptibility: float = Field(ge=0.0, le=1.0)
    confirmation_bias_level: Literal["none", "weak", "strong"] = Field(
        ..., description="确认偏差强度"
    )  # ← 新增字段
    estimated_percentage: int = Field(ge=0, le=100)
    communication_style: str


class Phase1Output(BaseModel):
    """
    Phase 1 输出：Agent 画像列表
    
    修改于：v1.1.1
    """
    event_summary: str
    conflict_axes: List[str]
    archetypes: List[Archetype] = Field(min_items=3, max_items=10)

    @validator("archetypes")
    def validate_percentage_sum(cls, v):
        total = sum(a.estimated_percentage for a in v)
        if total != 100:
            raise ValueError(f"所有 archetype 的 estimated_percentage 之和必须为 100，当前为 {total}")
        return v
```
