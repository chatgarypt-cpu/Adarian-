## 3. v1.2.8 核心产品原则

### 3.1 默认政府舆情治理视角

```text
所有报告默认面向政府舆情治理、宣传网信、公共管理或相关主管部门阅读。
```

即使事件触发主体是：

```text
企业 / 学校 / 行业协会 / 媒体 / 个人
```

报告也不得写成该主体的公关建议书。

---

### 3.2 明确政府主体优先

如果事件中出现明确政府主体，并且该主体存在舆情承压风险，则报告应优先围绕该政府主体展开。

示例：

```text
深圳公交站劝烟执法争议：
  明确政府承压主体：深圳公安 / 涉事执法部门
  报告视角：执法程序争议、公安公信力、属地治理风险

OPPO母亲节营销争议：
  无明确政府承压主体
  报告视角：政府舆情治理、行业规范、公序良俗、平台传播、价值议题外溢
```

**判断政府承压主体的条件**（满足任一即视为明确政府承压主体）：

```text
a) 事件直接涉及政府执法/审批/监管/公共管理行为；
b) 舆论已点名批评具体政府部门或公职人员；
c) 事件暴露出政府侧程序、制度或治理能力缺陷。
```

不满足以上任一条件的事件，按无明确政府承压主体处理，从公共舆情治理角度展开。

中间地带示例：

```text
食品安全事件涉及市场监管部门执法延迟：
  满足条件 a) 和 c) → 明确政府承压主体（属地市场监管部门）
  报告视角：执法效率、监管程序、属地治理责任

学校事件涉及教育局监管责任：
  满足条件 a) 和 c) → 明确政府承压主体（属地教育主管部门）
  报告视角：行业监管、校园安全治理、公共价值引导
```

### 3.3 对策建议使用政府治理动作语言

默认动作语言：

```text
关注
研判
跟踪
协调
督促
预置回应口径
提示风险
监测外溢
引导讨论
避免过度介入
```

明确政府主体承压时，可使用：

```text
说明
回应
补齐程序
统一口径
公开节点
协同处置
复盘整改
上级指导
```

禁止默认写成：

```text
建议OPPO澄清……
建议品牌方……
建议品牌……
建议企业……
建议学校公关……
建议涉事企业……
```

**兜底禁止规则**：任何以”建议+涉事主体名称”（包括但不限于企业名、品牌方、品牌、学校、协会、当事人）开头的句子，均视为企业/涉事方公关视角，禁止出现。

**扩展禁止表达**：

```text
【PR 行业词汇禁止】
- 危机公关 / 品牌修复 / 舆情洗白 / 形象修复 / 公关策略

【第二人称禁止】
- 贵司 / 贵校 / 贵单位

【空洞治理语言禁止】
- “加强舆情监测”（必须加具体风险维度和观察对象）
- “做好舆论引导”（必须加具体引导方向和目标群体）
- “积极应对舆情”（必须加具体应对动作和主体）
```

除非报告明确说明该动作是”政府侧督促相关主体补齐说明”，而不是替主体写 PR。

```text

高度对立
低极化
中等分化

高分化
显著负向偏移
剧烈立场迁移
```

指标只能作为判断依据，不能成为段落主体。

### 7.3 提示词优先级层级

v1.2.8 新增约 15 个常量，总 prompt 体积将从 ~600 tokens 膨胀至 ~2400 tokens。为防止硬约束被稀释，所有规则必须按以下优先级组装：

```text
T0（永不违反）：模拟推演口径 + 禁止伪造引语
  - SIMULATION_DISCLAIMER 始终置于 prompt 最前
  - 禁止生成带引号的虚构公众发言

T1（硬合同 — 不可变）：code-owned 标签 + 五章模板 + 禁止短语
  - risk_level_label / risk_type_labels 必须逐字复制
  - 五章模板结构不可变
  - FORBIDDEN_REALITY_PHRASES / FORBIDDEN_EQUIVALENT_PHRASES 不可违反

T2（视角规则）：政府视角 + 治理动作语言
  - 默认政府舆情治理视角
  - 对策建议使用政府治理动作语言
  - 禁止企业 PR 视角

T3（叙事质量 — 尽力而为）：阶段叙事 + 结构性展开 + 指标标签转译
  - 演化分析 2-3 阶段叙事
  - 风险研判 2-3 结构性风险点
  - 指标业务标签转译
  - 标题短化
```

Prompt 组装时，T0/T1 规则必须放在最前面，T3 规则放在最后。模型在长 prompt 中的注意力衰减倾向于遗忘尾部规则，因此禁止项和硬合同不得放在末尾。

### 8.4 演化分析规则

```text
【演化分析写作要求】

演化分析不得逐项罗列 tick 数据，也不得只解释数值变化。

必须将模拟过程组织为 2-3 个阶段。

每个阶段应包含：

1. 阶段名称：
   例如“争议触发期”“群体分化期”“风险固化期”“缓和观察期”。

2. 阶段特征：
   说明该阶段舆论结构发生了什么变化。

3. 关键群体：
   指出推动变化的主要群体，如风险放大器、缓冲层、摇摆变量。

4. 机制解释：
   解释为什么这些群体会推动风险变化，而不是只报数。

5. 治理含义：
   简要说明该阶段对政府舆情治理意味着什么。

可以引用少量关键数值作为依据，但数值必须服务于判断，不得成为段落主体。

**禁止形式示例**（逐 tick 报数叙述）：

```text
❌ 禁止：

Tick 4 降至 4.65。整体情绪波动较大，呈现先升后降趋势。"

✅ 正确（阶段叙事）：
"第一阶段整体情绪从基线水平快速升温，批评声量在价值敏感群体中率先聚集。
第二阶段情绪出现分化，理解型群体起到缓冲作用，但负向群体的立场持续固化。"
```

### 8.5 风险研判规则

```text
【风险研判写作要求】

风险研判必须保留 code-owned 风险等级和 code-owned 主要风险类型，不得自行修改或新增风险类型标签。

但风险解释不能只写一段概括。

必须展开为 2-3 个结构性风险点。

每个风险点必须包含：

1. 风险名称：
   用业务语言描述风险表现，不替代 code-owned risk_type_labels。

2. 触发机制：
   说明该风险为什么会产生。

3. 关键群体：
   说明哪些群体推动、放大或缓冲该风险。

4. 升级路径：
   说明如果风险升级，可能沿什么路径扩散。

5. 缓释条件：
   说明什么回应或治理动作可以降低风险。

注意：
风险点名称可以用业务语言，但”主要风险类型”列表只能使用输入中的 risk_type_labels。

**风险名称与风险类型标签的边界**：

```text
【主要风险类型】（code-owned，不可变）：
  必须逐字复制输入中的 risk_type_labels，如”负面叙事聚合风险””社会情绪外溢风险”。
  不得新增、删除、改写或发明新的风险分类名词。

【结构性风险点名称】（业务语言，可自由描述）：
  是对已列出的 code-owned 风险类型的具体表现描述，不得出现 risk_type_labels
  中未列出的风险分类名词（如 code-owned 列表中无”公信力风险”，则不得在风险点
  名称中发明”公信力风险”这一新分类）。

  正确示例：
    code-owned risk_type_labels = [“负面叙事聚合风险”]
    → 风险点名称：”个案争议向公共价值议题外溢” ✓（是”负面叙事聚合”的具体表现）

  错误示例：
    code-owned risk_type_labels = [“负面叙事聚合风险”]
    → 风险点名称：”执法公信力风险” ✗（发明了 code-owned 列表中不存在的新分类）
```

### 8.6 对策建议规则

```text
【对策建议写作要求】

对策建议必须面向政府舆情治理、宣传网信、属地公共管理或相关主管部门。

不得默认写成涉事企业、学校、协会或个人的公关建议。

如果事件中没有明确政府承压主体，建议应围绕：

1. 监测外溢风险

3. 协调行业主管或相关主体

1. 补齐程序说明

7. 上级或协同部门统一指导口径并建立跨部门通报机制，防止条块分割导致

## 9. Section-level Few-shot

v1.2.8 运行时使用 2 段企业品牌事件 few-shot（无明确政府承压主体场景），直接覆盖 test8 暴露的所有产品问题。政府执法争议事件 few-shot 见 §9.4 附录，defer 至 patch-06 或 v1.2.9。

### 9.1 演化分析 few-shot（企业品牌事件）

```text
【演化分析参考写法 — 企业品牌事件（无明确政府承压主体）】

本轮模拟大致可分为三个阶段。

第一阶段为价值议题激活期。争议内容发布后，批评声量首先在价值敏感群体
中快速聚集，个案被迅速锚定为公共价值议题而非单纯的营销表达失误。此阶段
治理观察重点是判断该议题是否具备向公序良俗、行业规范等宏观议题外溢的传播
条件，而非仅关注品牌方回应速度。

第二阶段为群体立场分化期。随着行业协会、关联机构等外部主体相继发声，讨论
从个案行为扩展至责任归属与行业规范。部分理解型群体起到缓冲作用，但高敏感
群体负面立场持续强化，形成显著的立场二元分化。此时治理策略应从个案关注
转向群体结构监测，防止对立情绪固化为长期负面认知。

第三阶段为议题外溢观察期。模拟后期整体风险烈度仍处于可控区间，但群体分化
格局已经形成。需重点关注两类外溢路径：一是争议话题向行业监管、公共价值等
宏观议题迁移；二是平台二次传播素材（截图、二创、嘲讽内容）可能重新激活
已缓和的讨论。本阶段治理应以监测为主、避免政府侧过度介入企业个案。

（以上参考写法仅为段落结构和展开层次的格式示范，不得直接复制其中的事件描述、
数值判断和风险结论。实际报告须基于本轮模拟的具体数据和参数生成。）
```

### 9.2 风险研判 few-shot（企业品牌事件）

```text
【风险研判参考写法 — 企业品牌事件（无明确政府承压主体）】

风险等级：[code-owned label]

主要风险类型：
[code-owned risk_type_labels，不得自行新增]

结构性风险点一：个案争议向公共价值议题外溢

事件的敏感性不在于营销表达本身，而在于其触发的公共价值判断。部分群体在
模拟中呈现显著负向立场迁移，说明该议题具备从个案讨论向公序良俗、行业规范
等公共价值议题转化的传播条件。触发机制为价值敏感群体将个案上升为价值符号
进行跨圈层讨论。升级路径为争议话题标签化后在多平台形成共振。缓释条件包括
涉事主体尽早完成事实说明、避免使用辩解性或娱乐化表述，同时政府侧协调行业
主管部门督促相关方规范信息披露。

结构性风险点二：多主体发声导致群体对立与叙事碎片化

当行业协会、关联机构、意见领袖相继介入时，事件解释权从原始主体外溢至公共
讨论场，不同群体对同一事件的理解和立场出现显著分化。这一分化本身构成独立
风险：叙事碎片化意味着舆情引导难度上升，单一的官方口径难以覆盖多元受众
关切。触发机制为外部主体发声引入新的讨论维度。升级路径为讨论碎片化后形成
互不兼容的叙事阵营，进而诱发更广泛的公共价值站队。缓释条件为政府侧协调
相关主管部门建立信息共享机制，避免多头表态导致信息混乱。

（以上参考写法仅为段落结构和展开层次的格式示范，不得直接复制其中的事件描述、
数值判断和风险结论。实际报告须基于本轮模拟的具体数据和参数生成。）
```
