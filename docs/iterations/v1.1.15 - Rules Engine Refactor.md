## 🎯 本次迭代目标

### 问题描述

在 v1.1.14 完成 Phase 1 解耦后，系统仍存在关键问题：

### 1️⃣ 结构性字段仍由 LLM 控制

包括：

* `P`
* `estimated_percentage`

👉 问题：

* 不稳定（不同 run 波动大）
* 难以约束（总和≠100、分布异常）
* 难以解释（无法追溯生成逻辑）

---

### 2️⃣ 规则分散

当前规则分布在：

* Prompt
* Validator
* Postprocess

👉 问题：

* 一致性不可控
* Debug 困难
* 修改成本高

---

### 3️⃣ Phase 1 仍然“生成主导”

虽然 v1.1.14 已拆模块，但：

👉 本质仍是：
**LLM 决定结构 → 代码修补**

---

### 解决目标

本版本目标：

👉 **建立 Rules Engine，将关键结构控制权收回代码层**

具体目标：

* 将 `P` 从 LLM 移出，改为代码推导
* 将 `estimated_percentage` 从 LLM 移出，统一归一
* 建立集中规则层（Rules Engine）
* 减少 Validator 修补职责
* 提升稳定性与可解释性
