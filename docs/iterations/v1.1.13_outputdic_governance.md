## 🎯 本次迭代目标

### 问题描述

* 当前存在的问题：

  * 输出文件直接平铺在 `outputs/` 根目录，单次运行缺乏独立边界
  * 普通运行输出与测试输出未分区，导致结果混杂
  * 输出目录命名缺乏统一规范，无法从目录名快速反查 seed / 时间 / 版本 / 测试轮次
  * `TASK_LOG.md` 同时承载任务执行记录与 benchmark/质量评测记录，职责混乱
* 影响范围：

  * 主流程输出归档
  * 版本回溯
  * 验收协作
  * 后续 benchmark 资产管理
* 是否为结构性问题（是/否）：**是**

---

### 解决目标

* 本次希望达成的效果：

  * 建立 run 级输出目录规范
  * 将输出分为 `normal` 和 `benchmark` 两大模块
  * 引入统一命名规则
  * 新增 `BENCHMARK_LOG.md`
  * 将 `TASK_LOG.md` 收口为任务执行日志
* 是否允许 breaking change：**否**
* 本次是否涉及架构调整（是/否）：**是（仅限输出层/工程治理层）**

# 🧠 架构变更说明（新增关键模块）

### 当前结构问题

* 目前输出结构是“散文件落盘”，不是“一次运行一个交付单元”
* 输出资产没有被组织成可回溯、可审计的 run 目录
* benchmark 结果长期写入 `TASK_LOG.md`，使执行日志与评测日志耦合
* 当前问题不在业务算法，而在输出治理层与日志治理层

---

### 目标结构（本次之后）

列出模块划分：

* **Module A：Output Manager**

  * 负责创建 run 目录
  * 负责 normal / benchmark 模式目录命名
  * 负责写入 `run_meta.json`
  * 负责复制 seed 到 run 目录
* **Module B：Run-based Output Routing**

  * 负责将 Phase 1~4 的输出统一重定向到当前 `run_dir`
* **Module C：Log Split Governance**

  * `TASK_LOG.md` 仅记录任务执行
  * `BENCHMARK_LOG.md` 仅记录 benchmark / 稳定性测试 / 回归测试

### 新流程（本次迭代后）

（简述新数据流）

`main.py -> create_run_directory() -> Phase 1/2/3/4 outputs -> write to run_dir`

目标目录结构：

```text
outputs/
├── normal/
│   └── {seed_stem}_{YYYYMMDD_HHMMSS}/
└── benchmark/
    └── {version}_run{N}_{seed_stem}/
```

每个 `run_dir` 必须至少包含：

```text
<run_dir>/
├── seed_input.txt
├── entities_and_relations.json
├── social_graph.json
├── tick_logs.json
├── final_report.md
├── run_meta.json
```
