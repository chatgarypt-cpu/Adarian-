## 🎯 本次修复目标

### 问题 1：报告缺少核心洞察
**现象**：
- 只有数据表格，没有分析
- 看不出"为什么极化指数下降"
- 看不出"舆论走向是什么"

**解决方案**：
- 增加"关键洞察"章节（3-6 条核心发现）
- 增加"舆论态势判断"章节（整体极化、矛盾焦点、演化趋势）
- 每个数据表格后增加简短分析

### 问题 2：拐点分析过于简单
**现象**：
- 只列出了 Tick 1 的一个拐点
- 没有解释"为什么这是拐点"

**解决方案**：
- 识别所有拐点（极化指数变化 > 0.05 或立场偏移 > 1.5）
- 每个拐点增加"影响分析"
- 突出显示最关键的拐点

### 问题 3：缺少立场演化展示
**现象**：
- 没有展示各群体的立场变化轨迹
- 看不出"谁的立场变化最大"

**解决方案**：
- 增加"最终立场变化"表格（初始 → 最终 → 变化 → 趋势）
- 增加"极化演化轨迹"可视化（文字版）
- 标注立场变化最大的群体

### 问题 4：缺少关键发言展示
**现象**：
- 只在拐点分析中展示了一条发言
- 看不出"每个 Tick 的代表性发言"

**解决方案**：
- 增加"Tick 0 事件实体发言"章节
- 增加"Tick 1-N 意见演化"章节（展示首尾 Tick 的代表性发言）
- 每条发言标注发言者群体

### 问题 5：风险评估过于笼统
**现象**：
- "存在潜在争议风险"太模糊
- 没有具体的风险点

**解决方案**：
- 风险评估增加具体维度（整体极化、矛盾焦点、演化趋势、风险提示）
- 根据极化指数和立场分布给出明确判断
- 增加"需关注的群体"提示

### 问题 6：报告结构不适合决策者
**现象**：
- 数据密集，不易快速抓住重点
- 缺少 Executive Summary

**解决方案**：
- 增加"事件概要"（一句话总结 + 核心指标）
- 调整章节顺序：概要 → 实体 → 拐点 → 演化 → 洞察 → 风险
- 使用 emoji 和视觉分隔符提升可读性

### 任务 1：重构报告结构

**功能**：调整报告章节顺序和内容

**修改位置**：`src/phase4_report_agent.py` 中的报告生成 Prompt

**输入**：
- Phase 1 输出（实体数据）
- Phase 3 输出（Tick 日志）
- x(t) 序列

**输出**：
```markdown
# 舆情演化洞察报告

---

## 📊 事件概要
指标 | 数值
事件温度 | 0.70（较高）
事件烈度 | 0.80（很高）
风险等级 | MEDIUM
最终极化指数 | 0.22
模拟耗时 | 52.8s

## 🗺️ 实体图谱
### 事件实体（2个）
### 意见传播者（6个）

## 🎬 Tick 0 · 事件实体发言
（展示事件实体的初始发言）

## 🔥 关键拐点 · Tick X
（识别并展示最关键的拐点）

## 📈 Tick 1-5 · 意见演化
（展示首尾 Tick 的代表性发言）

## 📊 最终立场变化（Tick 0 → Tick 5）
（展示各群体立场变化）

## 📉 极化演化轨迹
（文字版可视化）

## 💡 关键洞察
（3-6 条核心发现）

## 🎯 舆论态势判断
（整体极化、矛盾焦点、演化趋势、风险提示）
```

**LLM Prompt 要点**：
- 报告面向决策者，需要结论先行
- 每个章节标题使用 emoji 提升可读性
- 数据表格后增加简短分析
- 关键数字使用粗体标注

**技术要求**：
- 报告长度控制在 500-800 行
- Markdown 格式规范
- 表格对齐

### 任务 3：增加"关键拐点"识别逻辑

**功能**：自动识别舆论拐点并分析影响

**修改位置**：`src/phase4_report_agent.py` 中的拐点识别函数

**输入**：
- 所有 Tick 的 global_metrics
- 所有 Tick 的 AgentEntry

**输出**：
```markdown
## 🔥 关键拐点 · Tick 1

**网络调侃群体** 发声："南通文旅这波操作，有点硬核啊！"

- 立场偏移 **+1.69**（4.51 → 6.2）
- 极化指数骤降 **0.12**（0.46 → 0.34）

**影响分析**：
- 调侃群体从质疑转向认可，带动整体舆论缓和
- 极化指数大幅下降，说明观点开始趋同
```

**LLM Prompt 要点**：
- 拐点识别标准：
  * 极化指数变化 > 0.05（绝对值）
  * 或某个群体立场偏移 > 1.5（绝对值）
- 每个拐点包含：发言者、发言内容、立场变化、极化变化、影响分析
- 如果有多个拐点，只展示最关键的 1-2 个

**技术要求**：
- 拐点按影响力排序（极化变化 + 立场偏移）
- 影响分析由 LLM 生成（30-50 字）

### 任务 5：增加"最终立场变化"表格

**功能**：展示各群体从初始到最终的立场变化

**修改位置**：`src/phase4_report_agent.py` 中的报告生成逻辑

**输入**：
- Tick 0 的立场数据
- Tick N 的立场数据

**输出**：
```markdown
## 📊 最终立场变化（Tick 0 → Tick 5）

| 群体 | 初始 | 最终 | 变化 | 趋势 |
|------|------|------|------|------|
| 政策批评者 | 8.6 | 7.1 | -1.5 | ↓ |
| 社会观察者 | 8.02 | 7.4 | -0.62 | ↓ |
| 法律支持者 | 1.8 | 5.5 | +3.7 | ↑↑ |
| 粉丝群体 | 2.81 | 7.81 | +5.0 | ↑↑↑ |
| 网络调侃群体 | 4.51 | 8.5 | +4.0 | ↑↑↑ |
| 媒体评论员 | 4.63 | 5.1 | +0.47 | → |
```

**LLM Prompt 要点**：
- 趋势符号：
  * 变化 < -1.0：↓↓
  * 变化 -1.0 ~ -0.5：↓
  * 变化 -0.5 ~ +0.5：→
  * 变化 +0.5 ~ +1.0：↑* 变化 > +1.0：↑↑
  * 变化 > +2.0：↑↑↑
- 按变化幅度排序（绝对值）

**技术要求**：
- 从 Tick 0 和 Tick N 日志中提取
- 保留 2 位小数

### 任务 7：增加"关键洞察"生成逻辑

**功能**：LLM 分析数据，生成 3-6 条核心发现

**修改位置**：`src/phase4_report_agent.py` 中的报告生成 Prompt

**输入**：
- 所有 Tick 数据
- 立场变化数据
- 极化演化数据

**输出**：
```markdown
## 💡 关键洞察

1. **极化指数大幅下降**（0.46 → 0.22，降幅 52%），是三次测试中唯一舆论走向缓和的案例
2. **粉丝群体立场变化最剧烈**（2.81→7.81），从轻微支持转向强烈支持官方
3. **网络调侃群体从质疑转向支持**（4.51→8.5），"调侃"变成"力挺"
4. **政策批评者虽然略有下降**（8.6→7.1），但仍维持在高立场，对立持续
5. **法律支持者持续上升**（1.8→5.5），理性派逐渐占据主流
6. **标准差持续收窄**（2.32→1.44），显示观点逐渐趋同
```

**LLM Prompt 要点**：
- 洞察数量：3-6 条
- 每条洞察包含：现象描述 + 数据支撑
- 优先级：极化变化 > 立场变化 > 群体行为
- 使用粗体标注关键词

**技术要求**：
- 由 LLM 生成，不是模板填充
- 每条洞察 30-50 字

### 任务 8：增加"舆论态势判断"章节

**功能**：多维度判断舆论走向

**修改位置**：`src/phase4_report_agent.py` 中的报告生成 Prompt

**输入**：
- 最终极化指数
- 立场分布
- 演化趋势

**输出**：
```markdown
## 🎯 舆论态势判断

| 维度 | 判断 |
|------|------|
| 整体极化 | 快速下降，从高对立转向温和（0.22） |
| 矛盾焦点 | 政策公平性 vs 官方执行力 |
| 演化趋势 | 支持者比例上升，批评者比例下降 |
| 风险提示 | 低风险，但批评者仍存在（7.1），需关注后续发酵 |
```

**LLM Prompt 要点**：
- 整体极化：根据最终极化指数判断（<0.3 温和，0.3-0.5 中等，>0.5 高对立）
- 矛盾焦点：识别对立双方的核心争议点
- 演化趋势：描述立场变化的主要方向
- 风险提示：根据批评者立场和比例给出预警

**技术要求**：
- 由 LLM 生成
- 避免政治化表述（如"压制"、"主导"）
