**1. 这轮干嘛？**

### 2. Goal & Boundary

**做什么：**

1. **入口整合** — `adarian.sh serve` → `python -m adarian serve`（Flask 模式）；`start.command` 同步更新；`__main__.py` 确认从 `adarian.serve` 导入 `run()` + `create_app()`
2. **清理 `_legacy_serve.py`** — `git grep -l "_legacy_serve"` 全仓库检查无引用；干净环境 `python -m adarian serve` 跑通 ≥3 次后 `git rm`
3. **验收 8 场景（S1-S8）：**
   - S1: 1 模型正常推演 → 8 步全绿
   - S2: 幂等重复提交同一 batch_id
   - S3: 2 模型中 1 失败 → 混合结论显示，失败 world 有 `error_summary`
   - S4: 零模型 → 400 + `{"error": "...", "code": "NO_MODELS"}`
   - S5: 非法 JSON → 400
   - S6: 未知 batch_id on `/api/review` → 404
   - S7: 空 `outputs/runs/` → `GET /api/history` 返回 `[]`
   - S8: 完整链路 seed → run → review → report → history 出现条目
4. **Mock 残留审计** — E2E 前检查 `frontend/src/api/mock.ts`、store fallback 和页面状态调试入口；生产验收路径不得依赖 mock 数据，不得暴露开发用 loading/empty/error/populated 切换控件
5. **烟测脚本** — `scripts/smoke_api.sh` 覆盖 S1/S2/S4/S5/S6/S7；`scripts/smoke_e2e.sh`（Playwright）覆盖 S1/S2/S8
6. **版本标记** — 每节点 `git tag v1.5.0a-nodeN` / `v1.5.0b-nodeN` / `v1.5.0c-nodeN`
7. **`make rebuild` 规则** — `rm -rf frontend/dist && npm run build && python -m adarian serve`

**不做什么：**
- 不改前端组件结构或页面布局
- 不改 `batch.py`（除非紧急 bug）
- 不改 `phase*/` / `analysis/` / `parser.py` / `schemas/`
- 不接受 mock 数据驱动的“绿灯”作为真实 E2E 通过证据
