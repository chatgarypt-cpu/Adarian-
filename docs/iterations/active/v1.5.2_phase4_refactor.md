# v1.5.2 — Phase 4 重构：Skill 驱动的独立报告 Agent

> 四层工作流。独立归档。
> Phase 4 从"LLM 调用 + 格式化输出"重构为 skill 驱动的独立报告 agent。
> 纯消费端，不改 pipeline。

---

## 第 1 层：Owner Brief

**1. 这轮干嘛？**

把 Phase 4 从现有的函数链（`parse_llm_report_response` → `report_narrative` → `save_report`）完全重写为一个独立、高解耦的 Agent 框架。

**核心变化：**

- **新增 `Phase4ContextBuilder`** — 薄 adapter 层，纯代码（零 LLM）。读 N 个 `simulation_dataset.json`，提取关键字段，翻译成 agent-friendly 的中文叙述文本（事件背景、主体立场、推演过程、风险研判）。
- **Agent 不再读原始 JSON**，而是接收已经格式化好的、人类可读的上下文文本。
- **Agent 加载产品写的 SKILL.md**（五章报告写作规范），按 skill 指令撰写报告。
- **零新依赖** — 用已有 openai SDK 做 `function calling` 式的 agent loop。
- **产出真实五章 Markdown 报告**（对标产品已产出的 A/B/C 版 59KB 质量）。
- **CLI + API 双入口**。

**2. 不再做什么？**

- 不改 pipeline（phase/analysis/parser/llm_client）
- 不改 `simulation_dataset.json` 的 schema
- 不改 serve 层的 route registration
- 不引入外部 agent 框架（LangGraph/CrewAI/...）
- 不依赖 MCP 搜索（Phase 4 是纯消费端，上游已有补强）
- 不自动删除旧 `report_agent.py`（保持向后兼容，closeout 确认后清理）

**3. 这轮为什么现在做？**

现有 Phase 4：
- `parse_llm_report_response("", dataset)` — 传空字符串，虽然函数本身只读 dataset，但调用方式暴露了旧设计
- `report_narrative.py` 仍是 LLM 调用 + 格式化，不是 agent
- 产品已经用 Claude Code 产出了 59KB 的真实报告，Phase 4 应该能达到同样的质量
- v1.5.1 补完 review/report/world-detail 缺口后，最后一个产品级缺口就是报告质量

**4. 谁调度？谁执行？**

- 调度：Hermes
- 执行：Codex CLI single_node

### 2. Goals & Boundaries

#### 2.1 Goal 1: Phase4ContextBuilder（前置任务）

**定位**：纯代码层，零 LLM 调用。读 N 个 `simulation_dataset.json`，输出 agent-friendly 的格式化文本。

**输入**：`list[dict]` — 每个元素是一个 world 的 `simulation_dataset.json` 内容。

**输出**：结构化的中文叙述文本块，按 section 组织：

```
===== 平行世界总览 =====
共 3 轮平行推演，涉及模型: qwen36-35b, qwen3-30b-tke, minimax

===== World 1 (qwen36-35b) =====
事件: 校园食堂食品安全争议（手动录入）
涉及主体: 学生（反对）、家长（支持）、配餐公司（反驳）、校方（中立）
智能体数量: 6
推演步数: 5 轮
立场分布: 2 支持 / 1 中立 / 3 反对
极化指数: 0.73（高极化）
风险等级: 中风险（评分 0.60）
主要风险类型: 负面叙事聚集风险、平台外溢风险

推演过程摘要:
- 第1轮: 4 个发言者 — 家长谴责校方监管不力
- 第2轮: 5 个发言者 — 学生在抖音扩散，配餐公司发声明
- 第3轮: 6 个发言者 — 市监局介入、媒体跟进
- 第4轮: 4 个发言者 — 话题降温
- 第5轮: 3 个发言者 — 协商解决方向

===== World 2 (qwen3-30b-tke) =====
...
```

**实现要点：**
- 从 `dataset["event_entities"]` 计算主体立场分布
- 从 `dataset["simulation_result"]["opinions"]` 计算极化指数
- 从 `dataset["simulation_result"]["risk_verdict"]` 提取风险等级
- 从 `dataset["simulation_result"]["risk_type_classification"]` 提取类型标签
- 从 `dataset["tick_logs"]` 提取推演过程摘要
- 所有字段走 `.get("key", default)` 模式，兼容旧 dataset 缺少字段

**不做什么：**
- 不改 dataset 原始数据
- 不做 LLM 归约
- 不推测缺失数据

#### 2.2 Goal 2: Agent 主入口

**架构：**

```
CLI: python -m adarian.report --batch <batch_id>
  └─→ agent.run(batch_id, skill_path="config/default_skill.md")
        ├── 1. DB 查 worlds（batch_id → 世界列表 + run_dir）
        ├── 2. 读 N 个 simulation_dataset.json
        ├── 3. Phase4ContextBuilder → 格式化上下文
        ├── 4. 加载 skill.md → system prompt
        ├── 5. LLM 调用的 agent loop（openai SDK function calling）
        ├── 6. 保存 Markdown 报告
        └── 7. 返回 Phase4ReportOutput

API: POST /api/report {"batch_id": "..."}
  └─→ 调用 agent.run(batch_id)
        └─→ 返回 {files: [...], 多 world 概况}
```

**Agent loop 流程：**

```
system_prompt = skill.md 内容 + context_builder 输出

round 1: LLM 生成报告框架（五章结构）
  → 检查是否涵盖所有 section
  → 不满足就补充

round 2: LLM 撰写正文
  → 嵌入 dataset 中的关键数据（不要原始 JSON，用格式化文本）
  → 按 skill 的写作规则组织语言

round 3: 自检（LLM 评价自己产出的报告）
  → 是否满足 skill 要求的章节、语气、引用格式
  → 不满足就修订

最终输出: 完整的 Markdown 文件
```

**不做什么：**
- 不做多 agent 并行（一个 agent 读完 N worlds，综合写报告）
- 不做流式输出
- 不做外部搜索

#### 2.3 Goal 3: 配置 + Skill 结构

```
src/adarian/report/config/
├── default_skill.md    # 产品编写的默认技能（五章结构、写作规则）
└── run.yaml            # 运行时参数

src/adarian/report/models/
└── schemas.py          # Phase4ReportOutput, WorldSummary, TickSummary
```

**`default_skill.md` 来源**：产品用 Claude Code 写的 SKILL 文件，直接放到 config/ 目录。agent 启动时读全文。

**`run.yaml`**：
```yaml
model: qwen36-35b
temperature: 0.7
max_tokens: 8192
base_url: ""  # 空=从外部传入
api_key: ""
report_language: "zh-CN"
max_rounds: 3
```

### 3. Architecture Decisions

#### 3.1 不依赖 LLMClient

Phase 4 不 `from adarian.llm_client import LLMClient`。

原因：
- LLMClient 绑定 `adarian.config`（provider/base_url/api_key），Phase 4 应通过参数获取这些值
- LLMClient 的 provider 路由（`provider="qwen"`）对 Phase 4 无意义
- 函数签名不同：Phase 4 需要 function calling，LLMClient 只有 `generate(system, user)`

改用 `openai.OpenAI` SDK 直调 Qwen 内网集群，跟 LLMClient 同源但解耦。

#### 3.2 旧 Phase 4 目录的处理

- v1.5.2 开发期间：新旧共存，通过 `import` 区分
- closeout 前：确认 serve/report.py、__main__.py、全仓库无 `from adarian.phase4` 引用后，删除 `src/adarian/phase4/` 目录
- 旧的 `parse_llm_report_response` 如果还有引用，先用新 agent 包装兼容

#### 3.3 Agent loop 容错

| 故障 | 处理 |
|------|------|
| LLM 调用失败（网络/超时） | 重试 2 次，间隔 5s |
| LLM 输出不是合法 Markdown | 第 1 次修复重试，第 2 次 fallback 到 JSON + 模板 |
| dataset 文件缺失 | 跳过该 world，日志记录 |
| 无任何 world 完成 | 返回明确错误码 `NO_COMPLETED_WORLDS` |

#### 3.4 多 world 策略

agent 一次性读完所有 completed world 的 context，在 **一次 LLM 调用**（或一次 agent loop 的必要轮次）中综合撰写。不分 world 单独写再合并——那样会丢失跨世界对比价值。
