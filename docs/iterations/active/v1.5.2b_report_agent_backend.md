# v1.5.2b — 报告工作台完整产品化

> 四层工作流。独立归档。
> 基于 v1.5.2a 的真实 B 版无附录链路，补齐报告工作台产品能力。
> 本轮仍不采用 ClaudeCode skill 架构；产品交付物只作为规则资产来源。

---

## 第 1 层：Owner Brief

**1. 这轮干嘛？**

把 v1.5.2a 的最薄真实链路升级为完整报告工作台：

- A / B / C 报告版本按需多选。
- 附录模式按需选择：不附录 / 含附录 / 两份都要。
- `appendix_b.json` 始终生成，作为共享结构化审计产物。
- 支持报告写作 SKILL 切换。
- 支持 report job 轮询、会话恢复、失败/阻断可追踪。
- 完善质量审核和文件下载白名单。
- 报告模型配置接入 03-models / 08-settings 的 report model slot。

**2. 不做什么？**

- 不使用 ClaudeCode skill runtime。
- 不 spawn 子 agent。
- 不读取 `seed_input_path`。
- 不调用 MCP / 搜索 / 外部事实补全。
- 不使用 LLM 现实知识作为事实来源。
- 不修改 phase、parser、llm_client、simulation_dataset schema。
- 不默认生成所有版本。
- 不默认生成含/无附录双文件。

**3. 为什么现在做？**

v1.5.2a 已经证明"真实报告能生成"。v1.5.2b 再补完整产品能力，避免在还没看到报告质量前过早建设复杂工作台。

**4. 谁调度？谁执行？**

- 调度：Hermes / Owner
- 执行：Codex CLI single_node

### 2. Request Contract

```ts
type ReportVersion = 'A' | 'B' | 'C';
type AppendixMode = 'none' | 'included' | 'both';

interface ReportRequest {
  batch_id: string;
  client_session_id: string;
  versions: ReportVersion[];
  appendix_mode: AppendixMode;
  allow_partial: boolean;
  skill_id?: string;
  gateway_id?: string;
  model_id?: string;
  temperature?: number;
  max_tokens?: number;
}
```

规则：

- `versions` 至少 1 个。
- `appendix_mode=none`：每个已选版本只输出 `_无附录.md`。
- `appendix_mode=included`：每个已选版本只输出 `_含附录.md`。
- `appendix_mode=both`：每个已选版本输出 `_无附录.md` + `_含附录.md`。
- `appendix_b.json` 始终单独输出，不受 `appendix_mode` 控制。
- `allow_partial=false` 时，部分 failed world 必须 blocked。

### 3. Status / Output Contract

```ts
type ReportJobStatus = 'idle' | 'running' | 'completed' | 'blocked' | 'failed';

interface ReportJobStatusResponse {
  job_id: string;
  report_id?: string;
  batch_id: string;
  status: ReportJobStatus;
  progress: number;
  current_step: string;
  selected_versions: ReportVersion[];
  appendix_mode: AppendixMode;
  partial: boolean;
  completed_worlds_count: number;
  failed_worlds_count: number;
  skill_id: string;
  model: {
    gateway_id?: string;
    model_id?: string;
    temperature?: number;
    max_tokens?: number;
    resolved_from: 'payload' | 'settings' | 'env' | 'missing';
  };
  files: ReportFile[];
  appendix_b: {
    available: boolean;
    path?: string;
    worlds_count: number;
    confirmed_risks: number;
    preview: Record<string, unknown>;
  };
  audit_summary: ReportAuditSummary;
  error_code?: string;
  error_message?: string;
}

interface ReportFile {
  id: string;
  version: ReportVersion;
  appendix: 'none' | 'included' | 'data';
  name: string;
  url: string;
}

interface ReportAuditSummary {
  fatal: number;
  high: number;
  medium: number;

```

命名规则：

- 运行态一律使用 `job_id`。
- 最终产物可返回 `report_id`，但 API 路由和轮询主键都是 `job_id`。

### 4. Product Boundary

唯一正式输入：

- SQLite batch/world rows。
- completed worlds 的 `simulation_dataset.json`。
- dataset 内字段：`run_info.seed_text`、`source_context.event_summary`、`source_context.event_entities`、`source_context.opinion_spreaders`、`simulation_result.*`。

禁止数据源：

- 外部 `seed_input_path`。
- 浏览器上传的原始材料。
- 模型自带现实知识补事实。
- MCP / 搜索。
- 非 completed world 的臆造产物。

产品规则导入时必须改写：

- `writing_guide.md` 中"基于 seed_input + LLM 对现实舆情事件的了解"必须改为"基于 dataset 内 `run_info.seed_text` / `source_context.*` 概括"。
- `appendix_b_schema.yaml` 中 `input_json.event_name` / `input_json.worlds` 来源必须改为 batch + dataset 来源。
- 原产品 `input_spec.md` 不作为运行 contract，只可作为历史参考。

### 5. Internal Architecture

保留 v1.5.2a 的轻量包，按需扩展到 6 个核心文件：

```text
src/adarian/report/
  __init__.py
  runner.py              # API/CLI 统一入口；job 编排
  jobs.py                # job persistence, polling, session recovery
  appendix_builder.py    # datasets -> appendix_b.json；内部完成聚合
  writer.py              # SKILL 加载 + LLM 正文生成
  quality.py             # 质量审核 + 文件组装
  config.py              # 模型解析、路径、默认参数
  skills/
    default_government/
      skill.md
      quality_checklist.yaml
    enterprise_brief/
      skill.md
      quality_checklist.yaml
```

Ponytail 约束：

- 不拆 `aggregation.py`。
- 不拆 `countermeasures.py`，风险-对策闭环先放 `appendix_builder.py`。
- 不拆 `assembler.py`，文件组装先放 `quality.py`。
- 不拆 `model_config.py`，参数解析先放 `config.py`。
- `quality_checklist.yaml` 跟随 SKILL 放，不放全局 config，避免换 skill 时漏掉质量规则。
- 不新增依赖。

### 6. Appendix / Report Output

输出目录：

```text
<batch_dir>/reports/<job_id>/
  appendix_b.json
  A版/
    <safe_event_slug>_舆情风险研判_<YYYYMMDD>_v<N>_无附录.md
    <safe_event_slug>_舆情风险研判_<YYYYMMDD>_v<N>_含附录.md
  B版/
  C版/
```

规则：

- 未选版本不得创建目录。
- `_无附录.md` = 四章正文。
- `_含附录.md` = 四章正文 + 附录 A + 完整附录 B。
- `appendix_b.json` = 结构化审计文件，始终单独输出。
- 含附录报告里的附录 B 必须完整嵌入，不允许写"完整数据见源文件"。

|---------------|------|
| `none` | 每个已选版本只输出 `_无附录.md` |
| `included` | 每个已选版本只输出 `_含附录.md` |
| `both` | 每个已选版本输出 `_无附录.md` + `_含附录.md` |

### 8. Model / Skill Config

`skill_id` 解析优先级：

1. payload `skill_id`
2. `settings.report_skill_id`
3. env `ADARIAN_REPORT_SKILL_ID`
4. `default_government`

模型参数解析优先级：

1. payload `gateway_id` / `model_id` / 参数
2. settings report slot：
   - `settings.report_gateway_id`
   - `settings.report_model_id`
   - `settings.report_temperature`
   - `settings.report_max_tokens`
3. env：
   - `ADARIAN_REPORT_MODEL`
   - `ADARIAN_REPORT_BASE_URL`
   - `ADARIAN_REPORT_API_KEY`
   - `ADARIAN_REPORT_TEMPERATURE`
   - `ADARIAN_REPORT_MAX_TOKENS`
4. 缺失则返回 `REPORT_MODEL_NOT_CONFIGURED`

前端规则：

- 报告页只选择已配置好的 report model slot 或展示当前选择。
- API key 配置不出现在报告页。
- 03-models / 08-settings 负责模型服务配置。

### 10. Quality / Blocked Rules

- `fatal > 0`：必须 blocked，不展示正式报告文件。
- `high > 0`：默认 blocked，除非规则明确标记为 warning-only。
- `medium`：不阻断，但进入 audit summary。
- blocked 时保留 `appendix_b.json`、`audit_report` 和 debug 文件，不返回正式阅读稿。

必须检查：

- 四章标题结构。
- 正文不得出现 `world_0`、`tick`、`stance_score`、`polarization_index` 等内部字段。
- 第一章不得出现"模拟/推演/模型/AI"等暴露系统机制的词。
- 风险标签必须来自 `risk_mapping.yaml`。
- 对策必须绑定 confirmed risk。
- 含附录版本必须包含完整附录 A 和完整附录 B。

### 11. Error Contract

| code | 场景 |
|------|------|
| `NO_COMPLETED_WORLDS` | batch 无 completed world |
| `PARTIAL_COMPLETED_WORLDS` | 部分 world failed 且用户未允许 partial |
| `DATASET_MISSING` | completed world 缺 simulation_dataset |
| `REPORT_MODEL_NOT_CONFIGURED` | 未配置报告模型 |
| `REPORT_MODEL_UNAVAILABLE` | 模型服务不可用 |
| `APPENDIX_BUILD_FAILED` | appendix_b 构建失败 |
| `RISK_ASSESSMENT_FAILED` | 风险确认失败 |
| `REPORT_WRITE_FAILED` | 正文生成失败 |
| `REPORT_QUALITY_BLOCKED` | 质量审核阻断 |
| `REPORT_FILE_FORBIDDEN` | 文件下载越权 |

### 12. Frontend Integration

`06-report` 从 v1.5.2a 的最薄真实入口升级为完整工作台：

- A / B / C 多选。
- 附录模式 segmented control。
- SKILL 选择。
- report model slot 展示和跳转配置。
- job 未完成时轮询。
- 页面刷新后用 `client_session_id` 恢复 active report job。
- partial job 顶部显示「数据不完整，基于 N 个 completed worlds 生成」。
- blocked 后展示 audit reason，不显示正式报告文件。
