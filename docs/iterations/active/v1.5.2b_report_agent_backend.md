# v1.5.2b — 内部报告 Agent 后端实现

> 四层工作流。独立归档。
> 在 v1.5.2a 前端 contract 通过后，实现真实后端报告 Agent。
> 不采用 ClaudeCode skill 架构；产品交付物仅作为规则资产来源。

---

## 第 1 层：Owner Brief

**1. 这轮干嘛？**

实现 Adarian 内部报告生成子系统：

- 输入 `batch_id`，只消费 completed worlds 的 `simulation_dataset.json`。
- 生成结构化审计产物 `appendix_b.json`。
- 基于 `appendix_b.json` 按用户选择生成 A/B/C 报告。
- 附录按需输出：不附录 / 含附录 / 两份都要。
- 模型由前端选择或系统配置解析，API key 只在后端。
- 报告生成以 job 形式运行，支持状态轮询、会话恢复、失败/阻断可追踪。

**2. 不做什么？**

- 不使用 ClaudeCode skill runtime。
- 不 spawn 子 agent。
- 不读取 `seed_input_path`。
- 不调用 MCP / 搜索 / 外部事实补全。
- 不使用 LLM 现实知识作为事实来源。
- 不修改 pipeline、phase、parser、llm_client、simulation_dataset schema。
- 不默认生成所有版本。
- 不默认生成含/无附录双文件。

**3. 为什么现在做？**

v1.5.1 已把报告页降级为占位，v1.5.2a 将验证前端体验。v1.5.2b 负责让报告真正从 dataset 生成，闭合 Adarian 的产品报告能力。

**4. 谁调度？谁执行？**

- 调度：Hermes / Owner
- 执行：Codex CLI single_node

### 2. Input Boundary

唯一正式输入：

```ts
interface ReportRequest {
  batch_id: string;
  versions: Array<'A' | 'B' | 'C'>;
  appendix_mode: 'none' | 'included' | 'both';
  gateway_id?: string;
  model_id?: string;
  temperature?: number;
  max_tokens?: number;
}
```

后端数据源：

- SQLite batch/world rows。
- completed worlds 的 `simulation_dataset.json`。
- dataset 内字段：`run_info.seed_text`、`source_context.event_summary`、`source_context.event_entities`、`source_context.opinion_spreaders`、`simulation_result.*`。

禁止数据源：

- 外部 `seed_input_path`。
- 浏览器上传的原始材料。
- 模型自带现实知识补事实。
- MCP / 搜索。
- 非 completed world 的臆造产物。

### 4. Appendix B Contract

`appendix_b.json` 必须始终生成，作为结构化审计产物。

顶层 key：

```json
{
  "meta": {},
  "evolution_analysis": {},
  "source_evidence": {},
  "risk_assessment": {},
  "countermeasures": {}
}
```

规则：

- `meta.event_name` 来自 dataset 内 `run_info.event_name` 或 `source_context.event_summary` 的安全摘要；不得来自外部 input json。
- `evolution_analysis` 由多 world 聚合确定性生成。
- `source_evidence` 只保留白名单字段。
- `risk_assessment` 基于候选层 + 证据层确认 0-3 条风险。
- `countermeasures` 必须逐条绑定已确认风险。
- 如果无确认风险，必须写 `no_confirmed_risks_reason`，且 `measures=[]`。

### 5. Report Version / Appendix Output

版本：

| 版本 | 用途 | 字数目标 |
|------|------|----------|
| A | 自由生成，通读润色 | 不限 |
| B | 便捷速览 | 正文 1400-1500 字 |
| C | 详细阅读 | 正文 3800-4000 字 |

附录模式：

| appendix_mode | 输出 |
|---------------|------|
| `none` | 每个已选版本只输出 `_无附录.md` |
| `included` | 每个已选版本只输出 `_含附录.md` |
| `both` | 每个已选版本输出 `_无附录.md` + `_含附录.md` |

`appendix_b.json` 始终输出，但作为数据审计文件，不受 `appendix_mode` 控制。

### 6. Model Config Contract

前端可传：

- `gateway_id`
- `model_id`
- `temperature`
- `max_tokens`

后端解析优先级：

1. `POST /api/report` payload 中的 `gateway_id` / `model_id` / 参数。
2. 系统设置中的 report 默认模型：
   - `settings.report_gateway_id`
   - `settings.report_model_id`
   - `settings.report_temperature`
   - `settings.report_max_tokens`
3. 环境变量：
   - `ADARIAN_REPORT_MODEL`
   - `ADARIAN_REPORT_BASE_URL`
   - `ADARIAN_REPORT_API_KEY`
   - `ADARIAN_REPORT_TEMPERATURE`
   - `ADARIAN_REPORT_MAX_TOKENS`
4. 都缺失则返回：
   - `REPORT_MODEL_NOT_CONFIGURED`

安全边界：

- 前端不传 API key。
- API key 不返回给前端。
- gateway 的 `base_url` / `api_key` 由后端从 settings/env 解析。
- 错误信息只说明缺什么配置，不泄露密钥。

新增或调整端点：

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/report/jobs` | POST | 创建真实报告 job |
| `/api/report/jobs/<job_id>/status` | GET | 轮询 job 状态 |

### 8. Frontend Integration

v1.5.2b 将 v1.5.2a fake job 替换为真实 API：

- `POST /api/report/jobs`
- `GET /api/report/jobs/<job_id>/status`
- `GET /api/report/jobs/active?client_session_id=...`

前端必须：

- 页面刷新后恢复 report job。
- job 未完成时继续轮询。
- completed 后展示真实文件。
- blocked 后展示 audit reason，不显示正式报告文件。
- failed 后展示错误类型和下一步。

### 9. Error Contract

稳定错误码：

| code | 场景 |
|------|------|
| `NO_COMPLETED_WORLDS` | batch 无 completed world |
| `DATASET_MISSING` | completed world 缺 simulation_dataset |
| `REPORT_MODEL_NOT_CONFIGURED` | 未配置报告模型 |
| `REPORT_MODEL_UNAVAILABLE` | 模型服务不可用 |
| `APPENDIX_BUILD_FAILED` | appendix_b 构建失败 |
| `RISK_ASSESSMENT_FAILED` | 风险确认失败 |
| `REPORT_WRITE_FAILED` | 正文生成失败 |
| `REPORT_QUALITY_BLOCKED` | 质量审核阻断 |
| `REPORT_FILE_FORBIDDEN` | 文件下载越权 |
