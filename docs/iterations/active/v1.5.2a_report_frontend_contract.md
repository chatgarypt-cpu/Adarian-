> 四层工作流。独立归档。

> 本轮不接真实报告 Agent，不调用 LLM，不生成正式报告。

## 第 1 层：Owner Brief

**1. 这轮干嘛？**

把 `06-report` 从 v1.5.1 的"报告占位 + 已有文件下载"升级为可核对的报告工作台 fake 体验：

- 用户从已有 batch / active batch 中选择报告来源。
- 前端只展示 dataset 可消费边界，不出现 `seed_input_path` 上传或外部事实补全。
- 用户按需选择 A / B / C 报告版本。
- 用户按需选择附录模式：不附录 / 含附录 / 两份都要。
- 用户选择报告使用的模型服务、模型和参数，但前端不接触 API key。
- fake 一个报告 job 运行流：dataset 校验 → appendix_b 构建 → 风险确认 → 对策生成 → 正文生成 → 质量审核 → 文件输出。
- 展示 `appendix_b.json` 摘要、质量审核结果、报告文件列表和 blocked 状态。
- 为 v1.5.2b 定义稳定前后端 contract。

**2. 这轮不做什么？**

- 不实现真实后端报告 Agent。
- 不调用任何真实模型。
- 不读取 `seed_input_path`。
- 不使用 LLM 现实知识补事实。
- 不默认生成 A/B/C 全版本。
- 不默认生成含/无附录双文件。
- 不修改 pipeline、phase、parser、llm_client。

**3. 为什么先做前端 fake？**

报告生成体验包含大量产品决策：版本选择、附录开关、模型参数、状态流、质量审核、产物展示、失败阻断。先用 fake contract 验证体验，避免真实 Agent 开发后再返工 UI 和 API 形状。

### 2. Product Boundary

报告工作台必须显式遵守：

- 输入来源是 batch / completed worlds 的 `simulation_dataset.json`。
- 第一章概要也只能来自 dataset 内已有字段，例如 `run_info.seed_text`、`source_context.event_summary`、`source_context.event_entities`。
- 禁止出现 `seed_input_path` 上传、外部 URL、MCP 搜索、联网补事实、"LLM 对现实事件的了解"等入口。
- 如果 dataset 信息不足，前端显示"数据不足"，不能 fake 成外部事实补全。

### 3. Frontend Contract

#### 3.1 请求模型

```ts
type ReportVersion = 'A' | 'B' | 'C';
type AppendixMode = 'none' | 'included' | 'both';

interface ReportRequest {
  batch_id: string;
  versions: ReportVersion[];
  appendix_mode: AppendixMode;
  gateway_id?: string;
  model_id?: string;
  temperature?: number;
  max_tokens?: number;
}
```

规则：

- `versions` 至少 1 个，支持多选。
- `appendix_mode=none`：只输出无附录阅读稿。
- `appendix_mode=included`：只输出含附录阅读稿。
- `appendix_mode=both`：同一版本输出含附录 + 无附录两份。
- `appendix_b.json` 始终作为结构化审计产物保留，但不等同于用户选择的阅读报告。

#### 3.2 Job 状态模型

```ts
type ReportJobStatus =
  | 'idle'
  | 'validating'
  | 'building_appendix'
  | 'assessing_risk'
  | 'building_countermeasures'
  | 'writing'
  | 'auditing'
  | 'completed'
  | 'blocked'
  | 'failed';

interface ReportJob {
  job_id: string;
  batch_id: string;
  status: ReportJobStatus;
  current_step: string;
  progress: number;
  selected_versions: ReportVersion[];
  appendix_mode: AppendixMode;
  model: {
    gateway_id?: string;
    model_id?: string;
    temperature?: number;
    max_tokens?: number;
    resolved_from: 'payload' | 'settings' | 'env' | 'missing';
  };
}
```

#### 3.3 输出模型

```ts
interface ReportFile {
  id: string;
  version: ReportVersion;
  appendix: 'none' | 'included' | 'data';
  name: string;
  url?: string;
  fake?: boolean;
}

interface ReportAuditSummary {
  fatal: number;
  high: number;
  medium: number;
  passed: number;
  blocked_reasons: string[];
}

interface ReportResponse {
  report_id: string;
  batch_id: string;
  status: 'completed' | 'blocked' | 'failed';
  files: ReportFile[];
  appendix_b: {
    available: boolean;
    worlds_count: number;
    confirmed_risks: number;
    preview: Record<string, unknown>;
  };
  audit_summary: ReportAuditSummary;
}
```

### 4. UX Scope

#### 4.1 页面布局

`06-report` 应包含：

- 批次来源区：当前 active batch / 历史 batch。
- 数据可用性区：completed worlds 数量、缺失 dataset 数量、风险标签概览。
- 报告版本区：A / B / C 多选。
- 附录模式区：不附录 / 含附录 / 两份都要。
- 模型配置区：gateway、model、temperature、max_tokens、配置来源提示。
- 生成状态区：阶段式进度流，模拟轮询更新。
- 结构化数据区：`appendix_b.json` 摘要预览。
- 质量审核区：fatal/high/medium/passed、blocked reason。
- 产物区：只展示用户选择对应的 fake 文件。

#### 4.2 Empty / Error / Blocked 状态

- 无 batch：提示先运行推演或从历史任务选择 batch。
- 无 completed world：不能生成报告。
- completed world 无 dataset：显示 dataset 缺失，不 fake 数据。
- 未选择版本：按钮禁用。
- 模型配置缺失：显示 `REPORT_MODEL_NOT_CONFIGURED` 预警，但本轮 fake 可继续预览 UI。
- 质量审核 blocked：不显示正式阅读稿，只显示 blocked reason 和 debug 占位。

### 5. Polling / Session Requirements

即使是 fake，也要模拟真实 1.5.2b 形态：

- 前端生成 `report_job_id` 并持久化到 localStorage。
- 页面刷新后恢复 fake job 状态，不重头播放。
- fake job 进度通过 store 定时器推进，结构上等价未来 `GET /api/report/jobs/<job_id>/status` 轮询。
- 如果用户切换页面再回来，仍展示当前 job 最后状态。
- 不依赖当前 tab 的临时内存作为唯一状态。

### 6. Verification

必跑：

```bash
cd frontend && npm test -- --run
cd frontend && npm run build
```

浏览器 smoke：

- 打开 `/report`，无 active batch 时 empty state 正确。
- 有 fake completed batch 时，选择 B 版 + 不附录，只出现 B 版无附录文件。
- 选择 A+C + 两份都要，出现 A/C 的含附录和无附录文件，不出现 B。
- 刷新页面后 fake job 不重头播放。
- 模型配置缺失时有明确提示，不暴露 api key 输入框。
