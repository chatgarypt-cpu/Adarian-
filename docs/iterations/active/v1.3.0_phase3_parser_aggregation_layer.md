## 第 1 层：Owner Brief（人话摘要）

**1. 这轮干嘛？**  
把 Phase 4 中本不该属于报告层的 code-owned 模拟分析能力，一次性抽离 / 独立重建到 Phase 3；然后保留旧版 Phase 4 与新增新版 Phase 4 两条消费路径，用同一输入产出两份结果，做 bypass 对比，判断抽离是否成功。

**2. 为什么现在做？**  
现在 Phase 4 已完成报告生成层解耦，但 risk、inflection、stance、metrics 等确定性分析逻辑仍有部分停留在 Phase 4。后续要封锁 Phase 4 能力，让 Phase 4 只作为接收容器 / 生成器，就必须先把这些上游结构化数据能力放回 Phase 3。

**3. 谁调度？谁执行？**  
- 调度：Hermes PM Runtime
- 执行：Codex（主执行，单工作区串行或小 DAG 均可）
- 审查：Reviewer Team / DS Agent Team 只读审查
- 收口：Owner-Control

**4. 单节点还是多节点？**  
建议采用 controlled multi-node / small DAG。  
但本轮不是“分阶段慢慢打开接口”，而是：一次性完成 Phase 3 抽离，再用 Phase 4 双版本消费做验证。

**5. 会碰哪些文件？**  
预计新增：
- `src/phase3/risk_analyzer.py`
- `src/phase3/inflection_detector.py`
- `src/phase3/stance_analyzer.py`
- `src/phase3/parser.py`
- `src/phase4/legacy_consumer.py` 或等价旧消费包装层
- `src/phase4/structured_consumer.py` 或等价新消费包装层
- 对应测试文件

原则上不改：
- Phase 1 / Phase 2 主链
- Phase 3 现有推演引擎
- Phase 4 prompt / narrative / normalizer / title 语义
- `main.py` 主流程

**6. 做完我看什么？**  
- `simulation_dataset.json` 或等价结构化数据产物
- old Phase 4 output 与 new Phase 4 output 的对比报告
- bypass validation report：关键字段一致 / 差异 / 是否抽离成功

**7. 什么情况必须停？**  
- 执行器直接改了 Phase 4 prompt 或报告文案能力
- 新版 Phase 4 仍在自行计算 risk / inflection / stance / metrics
- 旧版 Phase 4 被新版 Phase 3 接口污染
- 新版 Phase 4 无法消费 Phase 3 新结构化接口
- bypass 关键字段无法比对或差异无解释

## 4. Architecture Decision：Phase 4 双版本消费验证

### 4.1 核心策略

```text
抽离不是靠“感觉代码搬完了”判定成功。
抽离成功必须通过双版本消费验证。
```

### 4.2 双版本定义

#### 旧版 Phase 4 Consumer

```text
旧版 Phase 4 Consumer 消费旧接口。

它保持原有 Phase 4 行为：
- 从原始 tick_logs / x_t_sequence / extraction_output / phase2_output 中自行走旧路径；
- 不读取新版 simulation_dataset；
- 不调用 Phase 3 新增 risk_analyzer / inflection_detector / stance_analyzer / parser；
- 作为 baseline output。
```

#### 新版 Phase 4 Consumer

```text
新版 Phase 4 Consumer 消费新版 Phase 3 structured interface。

它只从 simulation_dataset / Phase 3 新结构化接口中读取：
- risk_verdict
- inflection_points
- emotion_trajectory / metrics_snapshot
- agent_stance_matrix
- risk_type_classification

新版 Phase 4 不允许自行重新计算上述字段。
它只是接收容器 / 生成器。
```

### 4.3 接口屏蔽规则

```text
对旧版 Phase 4：
- 新版 Phase 3 structured interface 必须屏蔽；
- 旧版 Phase 4 不能访问 simulation_dataset；
- 旧版 Phase 4 输出作为 baseline。

对新版 Phase 4：
- 新版 Phase 3 structured interface 完全开放；
- 原本在 Phase 4 中自行计算的字段必须改为只读消费；
- 新版 Phase 4 输出作为 candidate。
```

### 4.4 成功判据

```text
若同一输入下：
1. old output 与 new output 的关键 code-owned 字段一致或差异在允许范围；
2. new output 不缺字段；
3. new output 不回退为 LLM-owned 风险判断；
4. new output 不自行重新计算 Phase 3 字段；
5. simulation_dataset 可独立解析；
则判定抽离成功。

否则判定抽离失败，进入 repair。
```
