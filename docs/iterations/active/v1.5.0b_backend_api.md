> 四层工作流。独立归档。后端服务前端。

## 第 1 层：Owner Brief

**1. 这轮干嘛？**

把 v1.5.0a 的前端从 mock 数据切到可验证的后端真实数据源，完成最小真实链路：

贴 seed → 保存配置 → 选择真实模型/网关 → 启动 batch → 查询状态 → 审查结果 → 生成报告 → 历史可见 → 设置可持久化。

**2. 这轮不再做什么？**

五份审查确认：原计划把进程取消、world 级 retry、`_run_world` Popen 改造和全部页面真实化混在一起，风险过高。本版 b 计划明确降级：

- 不做 batch/world cancel。
- 不做 world retry / 换模型重跑。
- 不改 `src/adarian/batch.py` 已有函数体。
- 不把 mock-only 产品设想包装成真实能力。
- 不写回 `.env`。

cancel/retry 进入 v1.5.1 或后续独立迭代。v1.5.0b 只负责把“能真实接起来的链路”接稳。

**3. 这轮为什么现在做？**

v1.5.0a 已经完成 Vue SPA 原型，但除 `/api/ping` 外仍主要依赖 `frontend/src/api/mock.ts`。v1.5.0b 的价值是建立真实 API contract、状态库和前端接入边界，让后续 E2E 不再用 mock 绿灯冒充真实完成。

**4. 当前审查结论已内化**

来自 `tasks/active/v1.5.0b-inventory-investigation/outputs/` 的五份审查指出的 P0 已纳入本计划：

- 后端 `success` 与前端 `completed` 状态值不一致。
- `settings.saveSettings()` 调错为 GET。
- 前端 `ticks=40` 与后端 `MAX_TICKS=5` 冲突。
- API key 存储方案缺失。
- Phase 4 report API 缺少 batch 输出路径映射。
- `docs/api_contract.md` 缺失。
- `StateTools`、mock note、mock-only UI 必须在生产验收中被明确处理。

### 2. Goal & Boundary

#### 2.1 目标

1. **先写 contract**：新增 `docs/api_contract.md`，明确所有真实端点、字段、错误码、mock-only 降级点、状态映射。
2. **建立 SQLite 状态库**：`batches`、`worlds`、`settings`、`model_gateways` 四表。
3. **建立 API schema**：Pydantic 或等价校验模型，统一 snake_case JSON 字段。
4. **接通模型网关**：`.env` 默认网关只读展示，用户新增网关写入 SQLite，discover/health 由后端执行。
5. **接通 seed/config/run/status/history**：能用真实输入启动 batch，并能从真实状态库或真实产物回读。
6. **接通 review/report/settings**：review 复用 `inspect.py`；report 封装 Phase 4 入口但不改 Phase 4；settings GET/PUT 持久化。
7. **前端替换 mock**：有真实 API 的 store 改为 fetch；没有真实能力的 UI 显示 disabled/pending/mock-only。
8. **测试覆盖**：每个 API 至少覆盖成功、错误结构、关键边界。

### 3. Architecture Decisions

#### 3.1 状态值映射

后端内部可以保留现有 batch 语义，API 出口必须统一成前端可理解的状态：

```python
WORLD_STATUS_MAP = {
    "success": "completed",
    "completed": "completed",
    "failed": "failed",
    "running": "running",
    "pending": "pending",
}
```

所有 `/api/run/<batch_id>/status`、`/api/history`、`/api/review/<batch_id>` 返回给前端前必须走映射。未知状态返回 `pending`，并在响应中保留 `raw_status` 便于调试。

#### 3.2 ticks / config 对齐

- 前端默认 `ticks` 从 40 改为 5。
- v1.5.0b 不修改 `batch.py` 去新增 ticks 参数。
- `/api/config` 可以持久化 `ticks`，但 `/api/run` 必须在 `docs/api_contract.md` 中写明：本轮只接受 `ticks<=5`，是否真正影响 batch 由现有后端能力决定。
- 如果后端不能消费某字段，UI 必须标为 pending，不得显示为已生效。

#### 3.3 API key 存储

- API key 前端可提交，但 GET 只返回 `has_api_key: true/false`。
- 生产/验收环境必须通过 `ADARIAN_ENCRYPTION_KEY` 提供 Fernet key。
- 没有 `ADARIAN_ENCRYPTION_KEY` 时：
  - dev/test 可使用进程内临时 key；
  - 不允许声称密钥具备可重启持久解密能力；
  - contract 必须写明该降级。
- 禁止把 master key 自动生成后存入同一个 SQLite 数据库。

#### 3.4 模型列表语义

必须拆成两类：

| 来源 | 端点 | 说明 |
|---|---|---|
| 内置 catalog | `GET /api/models` | 从现有 `batch.available_models()` 或等价只读入口读取。 |
| 用户网关 discover | `POST /api/model-gateways/<id>/discover-models` | 请求该 gateway 的 `/models` 或兼容端点。 |

前端模型调度页展示 gateway 分组列表，不得把 mock 模型当作真实可用模型。

#### 3.5 run/status 策略

- `POST /api/run` 在后台线程中调用现有 batch 启动能力，避免 Flask 请求阻塞。
- SQLite 先写 `running` 状态；任务完成后回写 `completed/failed`。
- 如无法做到 world 级实时状态，contract 必须写明 v1.5.0b 的 status 粒度。
- 不做 SIGTERM/SIGKILL 取消，不保存 proc handle。

#### 3.6 report 输入映射

`POST /api/report` 必须以 `batch_id` 为输入，从 SQLite worlds/batches 表或真实 run directory 找到 Phase 4 所需 `simulation_dataset`。如果无法找到：

- 返回 404 或 409；
- 不生成 mock report；
- 响应必须包含可操作错误码，如 `REPORT_SOURCE_NOT_FOUND`。

### 4. API Scope

#### 4.1 第一阶段：基础 + 模型

| 端点 | 目标 |
|---|---|
| `GET /api/ping` | 保留现有健康检查 |
| `GET /api/models` | 返回内置 catalog 可用模型 |
| `POST /api/models/health` | 对内置模型做 hello/latency 检测 |
| `GET /api/model-gateways` | 返回 `.env` 默认网关 + 用户网关 |
| `POST /api/model-gateways` | 新增用户网关，API key write-only |
| `PUT /api/model-gateways/<id>` | 更新/禁用用户网关 |
| `POST /api/model-gateways/<id>/discover-models` | 动态发现模型 |
| `POST /api/model-gateways/<id>/health` | 网关健康检测 |

#### 4.2 第二阶段：seed/config/run/status/history

| 端点 | 目标 |
|---|---|
| `POST /api/seed` | 保存 seed text，返回 seed_id 和真实/降级检查结果 |
| `GET /api/config` | 读取当前推演配置 |
| `POST /api/config` | 保存配置，未消费字段标 pending |
| `POST /api/run` | 启动真实 batch |
| `GET /api/run/<batch_id>/status` | 查询 batch/world 状态，状态映射后返回 |
| `GET /api/history` | 从 SQLite batches 返回历史任务，空库返回 `[]` |

#### 4.3 第三阶段：review/report/settings

| 端点 | 目标 |
|---|---|
| `GET /api/review/<batch_id>` | 复用 `inspect.py` 或真实产物聚合风险对比 |
| `POST /api/report` | 封装 Phase 4 报告管线 |
| `GET /api/settings` | 读取设置 |
| `PUT /api/settings` | 保存设置 |

#### 4.4 明确不提供的端点

这些端点不得在 v1.5.0b 里用假实现占位：

- `POST /api/cancel/<batch_id>`
- `POST /api/cancel/<batch_id>/<world_id>`
- `POST /api/run/<batch_id>/worlds/<world_id>/retry`

import ast, subprocess, hashlib, sys
old = subprocess.check_output(['git', 'show', 'HEAD:src/adarian/batch.py'], text=True)
new = open('src/adarian/batch.py', encoding='utf-8').read()
old_tree = ast.parse(old)
new_tree = ast.parse(new)

def hashes(tree):
    out = {}
    for n in ast.walk(tree):
        if isinstance(n, (ast.FunctionDef, ast.AsyncFunctionDef)):
            out[n.name] = hashlib.sha256(ast.unparse(n).encode()).hexdigest()

old_h = hashes(old_tree)
new_h = hashes(new_tree)
changed = [name for name, h in old_h.items() if name in new_h and new_h[name] != h]
deleted = [name for name in old_h if name not in new_h]
if changed or deleted:
