## Goal 1 — probe_scheduler 从 `tools/` 迁出

**变更原因**：bypass 验证通过后，probe_scheduler 是产品功能不是工具脚本，应放在项目根目录下。

**Scope**：
- 将 `tools/probe_scheduler/` 整体搬迁到项目根目录的 `scheduler/` 
- 保留 `tools/` 下的旧路径不变（兼容），或清理（看 Gary 意愿）
- 确保 `scheduler/` 独立可运行，不依赖 `tools/` 路径

**文件变更**：

| 文件 | 改动 |
|------|------|
| `tools/probe_scheduler/` | 保留（或迁移后清理） |
| `scheduler/` | **新建** — 从 `tools/probe_scheduler/` 搬迁 |
| `scheduler/__init__.py` | 调整 import 路径 |
| `scheduler/scheduler.py` | 入口封装，不依赖 tools/ 路径 |

**验收**：
- `python -m scheduler` 或 `python scheduler/__main__.py` 能启动
- 调度器能调用主项目 `src/` 下的代码
- import 路径正确

## Goal 2 — config_ui 完善（含全链路展示 + 种子输入）

**变更原因**：基础前端需要能展示完整推演链路（种子→Phase1→Phase2→Phase3→分析→dataset），并支持直接在网页上输入种子文本，不依赖本地文件。

**Scope**：
- `config_ui.py` 完善 API endpoint（已有 hello test + launch + run）
- `config_ui.html` 完善前端 UI
- 新增种子输入区（文本输入框，替代文件路径）
- 全链路状态展示（每个 Phase 当前状态：等待中/运行中/已完成/失败）
- 链路可视化：种子输入 → 实体提取 → 拓扑构建 → 多轮推演 → 分析 → dataset 产出
- 启动方式统一

**UI 布局示意**：
```
┌─────────────────────────────────────────┐
│  种子输入（文本框 / 预设选择）          │
│  ┌─────────────────────────────────┐   │
│  │ 在这里粘贴事件描述...            │   │
│  └─────────────────────────────────┘   │
│  [x] test1.txt  [x] test8.txt  [自定义]│
│                                         │
│  模型选择                                │
│  [✔] qwen36-35b  [✔] ds  [ ] minimax   │
│                                         │
│  [      开始推演      ]                  │
│                                         │
│  ── 推演链路 ──                         │
│  📝 种子 → ⏳ Phase1 → ⏳ Phase2 →     │
│  ⏳ Phase3 → ⏳ 分析 → 📊 完成          │
│                                         │
│  ── 各世界状态 ──                       │
│  world_0 (qwen36-35b)  ████████░░ 80%   │
│  world_1 (ds)          ██░░░░░░░░ 20%   │
└─────────────────────────────────────────┘
```

**文件变更**：

| 文件 | 改动 |
|------|------|
| `scheduler/config_ui.py` | 完善 API |
| `scheduler/config_ui.html` | 完善前端 UI |

**验收**：
- 浏览器打开能看到模型选择界面和种子输入框
- 能选 1 个或多个模型
- 能粘贴种子文本或选预设种子
- 点运行后能看到全链路状态（各 Phase 进度）
- 各 world 运行状态实时更新

## Goal 3 — N 份 dataset 产出确认

**变更原因**：确认平行世界正确产出 N 份 simulation_dataset.json，供后续 Report Agent 消费。

**Scope**：
- 确认每个 world 目录下有 `simulation_dataset.json`
- 确认 dataset 字段完整（含 v1.3.2 的 risk_type_classification 新字段）
- 确认后续下游（Report Agent）能通过 batch_dir 结构找到所有 dataset

**文件变更**：
- 无代码变更，纯验证

**验收**：
- 跑一次 2 模型调度，确认产出：
  ```
  outputs/runs/YYYY-MM-DD/batch_N/batch_config.yaml
  outputs/runs/YYYY-MM-DD/batch_N/world_0/simulation_dataset.json
  outputs/runs/YYYY-MM-DD/batch_N/world_1/simulation_dataset.json
  ```
- 每份 dataset 含 `risk_type_classification.primary_types`
