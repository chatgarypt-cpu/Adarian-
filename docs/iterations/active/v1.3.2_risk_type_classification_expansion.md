# 迭代计划：v1.3.2 — 风险类型分类体系扩展

## 背景

当前系统仅支持 13 个风险类型（RISK_TYPE_LABELS），且 `classify_risk_types()` 主要基于关键词匹配 + audience mode + 极化阈值，产品侧判定其为"过于泛化，主要风险类型容易变为负向叙事风险"。

产品侧已交付 v0.2 规格文档（`docs/archive/audit/productside_review/政府治理视角舆情风险分层与等级映射清单_v0.2.md`），定义了 20 个二级风险类型、5 个一级风险域，每类含触发线索/等级表现/正反例。

## 红线

1. **不改 `simulation_dataset.json` 的顶层 schema 结构** — 只能在现有 `risk_type_classification` 字段内扩展内容，不新增顶层 key、不改 _schema_version
2. **Agent 打标而非 code-owned 规则** — LLM Agent 基于结构化模拟数据 + 分类标准文档做推理，输出受 Pydantic schema 约束为 20 个类型之一，不做自由文本联想
3. **Phase 4 不做任何分类逻辑** — Pure consumer 原则已落地，Phase 4 只能从 dataset 消费 `risk_type_classification`，不能新增任何分类/重算逻辑
4. **不改变 `risk_level` 判定逻辑** — LOW/MEDIUM/HIGH/CRITICAL 的 `assess_risk()` 逻辑不动
5. **一次迭代只做转译和接入** — 不做"自动化 vs 配置"的开关/插拔设计

---

## Goal 1 — 风险类型定义映射

**变更原因**：将 v0.2 规格文档中的 20 个二级风险类型转译为代码常量，与现有 13 个类型并旧，补全消失的和新增的。

**Scope**：
- 将 20 个风险类型全部注册到 `RISK_TYPE_LABELS` 的 `src/schemas/phase4.py` 中
- 删除不再需要的旧类型（仅代码清理，不涉及逻辑）

**文件变更**：

| 文件 | 改动 |
|---|---|
| `src/schemas/phase4.py` | `RISK_TYPE_LABELS` 从 13 个扩展到 20 个 |
| `spec/dataset_fields.yaml` | 同步更新 `risk_type_classification` 相关字段的枚举值定义 |

**验收**：
- `RISK_TYPE_LABELS` 包含且仅包含 v0.2 文档中的 20 个类型
- 每个类型有对应的中文标签
- 编译通过

---

## Goal 2 — 风险分类 Agent 实现

**变更原因**：现有的关键词匹配规则覆盖不了 20 个类型的语义判断。改为一个专用的 LLM Agent，读取模拟数据 + 分类标准文档，输出 schema 约束的风险类型。

**Scope**：
- 新增一个 Phase 3 子步骤（接在 `InflectionDetector` / `StanceAnalyzer` 之后）：调用 LLM Agent 进行风险打标
- Agent 输入：`simulation_result`（x_t_sequence / emotion_trajectory / inflection_points / agent_stance_matrix）+ `source_context`（event_type / event_scale / event_controversy / entities / spreaders）
- Agent 参考：产品侧 v0.2 规格文档中的 20 个类型的触发线索/正反例/等级映射
- Agent 输出：Pydantic schema 约束，只能从 20 个类型中选 top-3，不能新增类型
- 现有 `classify_risk_types()` 保留为 fallback（keyword 硬规则）

**文件变更**：

| 文件 | 改动 |
|---|---|
| `src/phase3/risk_classifier.py` | **新建** — RiskClassifier，调 LLM，输入结构化数据 + 分类标准，输出 top-3 risk types |
| `src/schemas/phase3.py` 或新建 | **新建** Pydantic schema 约束输出（`RiskClassificationOutput`，含 `primary_types` + `type_labels`） |
| `src/phase3/risk_analyzer.py` | `classify_risk_types()` 保留为 fallback |
| `src/phase3/parser.py` | 在 `parse()` 中新增一步调用 RiskClassifier |
| `spec/dataset_fields.yaml` | 更新 risk_type_classification 字段的来源说明 |

**验收**：
- 对 test8 seed 文本（品牌营销争议），能命中至少 2 个匹配类型（如"平台治理与消费争议"、"负向叙事聚合"）
- 输出不超出 20 个类型范围，不新增非法类型
- 结构化模拟数据 + 分类标准 → 推理 → 打标，整个链路内聚在 Phase 3

**红线**：
- Agent 不做自由文本联想——推理必须基于结构化模拟数据和分类标准文档
- 不改变 `assess_risk()` / `risk_level` / audience_mode 等现有逻辑

## Goal 3 — dataset 消费确认

**变更原因**：确认新增的风险类型能正确进入 `simulation_dataset.json` 的 `risk_type_classification` 字段，且 Phase 4 纯消费端能正确读取。

**Scope**：
- 验证 `parser.py` 的 `risk_types = self._risk_analyzer.classify_risk_types(...)` 调用路径不受影响
- 验证 `_build_phase4_output_from_simulation_dataset()` 通过 `.get()` 读取新增类型

**文件变更**：

| 文件 | 改动 |
|---|---|
| `src/phase3/parser.py` | 确认无需改动（原有调用路径兼容） |
| `src/phase4/report_agent.py` | 确认无需改动（已用 `.get()`） |

**验收**：
- 跑一次 `midPhaseTest.py seeds/test8.txt`
- `simulation_dataset.json` 中 `risk_type_classification.primary_types` 包含新增的类型 ID
- `simulation_dataset_spec.yaml` 同步生成，注释中包含新增类型的说明
- Phase 4 `generate_report_with_llm_narrative` 能正常消费，不崩溃

## 风险评估

| 风险 | 等级 | 缓解 |
|---|---|---|
| 规则转译偏差——代码对"触发线索"的理解与产品侧语义不一致 | 中 | 先写规则，跑 test8 和 test 1 验收，确认类型名匹配后再合入 |
| 某一类型规则过于宽松，导致误判为多种风险 | 中 | classify_risk_types 上限 3 个，超过时按优先级截断；验收时检查是否有过度命中 |
| 现有 test8 seed 不覆盖所有场景，部分类型无法验证 | 低 | 接受——本次迭代只确保现有 seed 下有合理分类，不要求覆盖 20 个类型的全部触发场景 |
