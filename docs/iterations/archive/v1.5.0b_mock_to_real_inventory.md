# v1.5.0b Mock-to-Real 能力盘点与派发清单

> 用途：交给后续执行模型前，先明确 v1.5.0a 前端哪些是真能力、哪些是 mock-only、哪些需要后端新增。
> 当前日期：2026-06-26
> 基线：v1.5.0a Vue 原型 + Flask `/api/ping`

---

## 0. 执行原则

1. 不要把 `frontend/src/api/mock.ts` 的文案直接搬成后端“真实结果”。
2. 每个前端功能必须有真实数据来源、后端代码入口、错误路径和测试证据。
3. 没有真实能力支撑的功能必须在 UI/contract 中标为 `pending`、`disabled` 或 `mock-only`。
4. API key 不允许前端回显明文，不允许前端直接写 `.env`。
5. 禁止修改 `src/adarian/phase*/`、`src/adarian/analysis/`、`src/adarian/parser.py`、`src/adarian/schemas/`、`src/adarian/llm_client.py`；`batch.py` 只允许新增白名单能力。

## 2. 页面级盘点

### 01-seed 事件录入

| UI/字段 | 当前状态 | 真实化目标 | API/后端入口 | 验收 |
|---|---|---|---|---|
| textarea seed text | 前端真实输入 | 保存为当前 session/batch seed | `POST /api/seed` | 空文本 400；有效文本返回 seed id |
| 任务名称 | 前端 mock 状态 | 写入 batch metadata | `POST /api/seed` | history 可见名称 |
| 材料来源：手动录入 | 可用 | 保留为 v1.5.0b 最小真实来源 | `POST /api/seed` | source=`manual` |
| 材料来源：本地材料文件 | mock-only | v1.5.0b 先 disabled 或 pending | 后续上传 API | UI 不可误导为已上线 |
| 材料来源：历史事件复用 | mock-only | 等 history/reuse API 后启用 | 后续 reuse API | UI 不可误导为已上线 |
| 事件背景已填写 | 前端可真实判断 | 保留前端校验 + 后端二次校验 | `POST /api/seed` | 空文本错误路径 |
| 核心主体已识别 | mock-only | 调用现有实体/主体抽取能力或降级 pending | 待代码映射 | 返回主体列表或明确 pending |
| 时间线可补充 | mock-only | 后端分析 seed 是否含时间节点，或降级 pending | 待新增轻量分析 | suggestion 可解释 |

### 02-config 推演配置

| UI/字段 | 当前状态 | 真实化目标 | API/后端入口 | 验收 |
|---|---|---|---|---|
| 平行推演轮数 | 前端 mock | 映射 batch worlds 数量 | `GET/POST /api/config`, `POST /api/run` | run 创建 N 个 world |
| 每轮模拟步数 | 前端 mock | 映射真实 ticks 参数；若当前 batch 不支持则 pending | `POST /api/run` | 参数写入 session |
| 输出批次名称 | 前端 mock | 写入 batch tag/name | `POST /api/run` | outputs/runs 路径可追踪 |
| 推演重点 chips | mock-only | v1.5.0b 先 pending，除非后端有明确消费点 | contract 标注 | 不影响真实结果时不得显示为已生效 |
| 输出内容 StepLine | mock-only | 按真实产物可用性展示 | status API | 数据/日志/报告分别真实判断 |

### 03-models 模型调度

| UI/字段 | 当前状态 | 真实化目标 | API/后端入口 | 验收 |
|---|---|---|---|---|
| API 服务管理 | 前端临时 mock | 保存用户新增网关到后端 settings/SQLite | `POST /api/model-gateways` | 新增后刷新仍存在 |
| `.env` 默认网关 | 当前只在后端配置 | 后端读取为默认只读网关 | `GET /api/model-gateways` | 标注 source=`env` |
| API Key | 前端 mock input | 后端 write-only 保存，不回显明文 | `POST/PUT /api/model-gateways` | GET 只返回 `has_api_key` |
| 识别模型 | mock-only | 后端访问 `/models` 或兼容端点 | `POST /api/model-gateways/<id>/discover-models` | 返回真实模型列表 |
| 健康检测 | mock-only | hello/latency 检测 | `POST /api/model-gateways/<id>/health` | ok/fail/timeout 明确 |
| 模型选择 | 前端状态 | 选择真实 discover 出来的模型 id | store + run request | run 使用所选模型 |

### 04-run 运行监控

| UI/字段 | 当前状态 | 真实化目标 | API/后端入口 | 验收 |
|---|---|---|---|---|

| retry world | 未接 | 只新增 `batch.rerun_world()` | `POST /api/run/<batch_id>/worlds/<world_id>/retry` | 不修改 batch.py 旧函数体 |

## 4. 最小派发顺序

1. 后端基础：`db.py` / `schemas.py` / blueprint 注册 / `docs/api_contract.md`
2. 模型网关：`.env` 默认网关 + 用户新增网关 + discover/health
3. Seed/config/run：打通最小真实推演链路
4. Status/history/review：从真实 batch 产物回读
5. Report/settings：接 Phase 4 和持久化设置
6. 前端 stores：替换 mock，未上线能力 disabled/pending
7. 测试：pytest API + vitest + smoke

---

## 5. 禁止误判为完成

- 只看到页面能切换，不算完成
- 只返回 mock JSON，不算完成
- 没有错误路径测试，不算完成
- API key 明文回显，不算完成
- 未上线能力显示为“通过/正常/可用”，不算完成
