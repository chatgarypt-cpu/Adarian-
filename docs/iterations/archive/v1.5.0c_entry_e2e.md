## 第 1 层：Owner Brief

**1. 这轮干嘛？**

入口整合（`adarian.sh serve` → Flask，删除 `_legacy_serve.py`），E2E 验收 8 场景（S1-S8），`make rebuild` 规则，版本标记。v1.5.x 正式收口。

**2. 为什么现在做？**

v1.5.0a + v1.5.0b 交付了完整的前端 + 后端。但用户还是不能用 `adarian.sh serve` 启动新界面，旧 `_legacy_serve.py` 还占着位置，没有自动化的验收保障。这轮做完就是可发布的完整产品。

**现实边界补充（2026-06-26 Codex 调查后修正）：**

v1.5.0c 不能只验证"页面能点通"。调查发现以下关键依赖和遗漏：

- **S6 完全阻塞**：`GET /api/review/<batch_id>` 必须在 v1.5.0b 实现后才能验证，c 计划不应假设此端点可用。
- **S8 依赖风险**：review/report 必须以 v1.5.0b 的真实 API 为准；cancel/retry 已从 v1.5.0b 移出，不属于 v1.5.0c E2E 通过条件。
- **StateTools 生产可见性**：`?debugStates=1` 在开发构建中可激活调试控件，生产构建（`npm run build`）必须屏蔽。
- **`_legacy_serve.py` 清理归属**：v1.5.0b 保留 legacy 文件，v1.5.0c 在确认新入口稳定后再清理。
- **smoke 统一为内联 Python**：不依赖 `scripts/smoke_api.sh`，使用内联 Python + Flask test client 做 API smoke。
- **S1-S8 验收标准不够具体**：每个场景需要显式的断言（状态码、返回结构、字段值），而非仅描述"通过"。
- **01-seed 的 mock-only 降级**（本地材料文件、历史事件复用）需在 E2E 中验证其显示为 disabled/pending，而非硬编码数据。
- **本地 seed 路径恢复**：旧控制台已有 `seed_path` 能力。v1.5.0c 前置恢复 `source=file` + `seeds/test8.txt` 路径链路；历史事件复用仍为 disabled/pending。

### 2. Goal & Boundary

**做什么：**

1. **入口整合** — `adarian.sh serve` → `python -m adarian serve`（Flask 模式）；`start.command` 同步更新；`__main__.py` 确认从 `adarian.serve` 导入 `run()` + `create_app()`
2. **清理 `_legacy_serve.py`**（如尚未删除）— `git grep -l "_legacy_serve"` 全仓库检查无引用；干净环境 `python -m adarian serve` 跑通 ≥3 次后删除文件
3. **验收 8 场景（S1-S8），每场景含显式断言：**
   - **S1: 1 模型正常推演**
     - `POST /api/run` → 202，返回 JSON 含 `batch_id`、`worlds` 数组长度=1；重复幂等命中可返回 200
     - `GET /api/run/<id>/status` → 200，`worlds[0].status ∈ {'running','completed','failed'}`
     - 8 步侧边栏均可切换，各页无白屏
   - **S2: 幂等重复提交** → 同 seed/seed_path+models+tag+base_url 第二次返回同 `batch_id`，返回 200，非 429
   - **S3: 2 模型中 1 失败** → `GET /api/run/<id>/status` 中，失败 world 的 `status='failed'` + `error_message` 非空；成功 world 的 `status='completed'`；`all_completed=true`
   - **S4: 零模型** → 400 + `{"error": "...", "code": "NO_MODELS"}`
   - **S5: 非法 JSON** → 400
   - **S6: 未知 batch_id on `/api/review`** → 404。**注意**：此场景依赖 v1.5.0b 的 review API 实现，如 b 阶段未完成 review API，此场景标记为 `blocked`
   - **S7: 空 `outputs/runs/`** → `GET /api/history` 返回 `[]`。前置条件：`outputs/runs/` 目录存在但不含任何 batch 子目录
   - **S8: 完整链路** → seed → run → status 轮询至完成 → review → report → history 出现条目。**降级方案**：如 v1.5.0b 明确将 review/report 标为 blocked，S8 验证到 status 完成 + history 出现，并在 closeout 中记录 blocked 原因；不得用 mock report/review 代替。
4. **Mock 残留审计** — E2E 前检查：
   - `frontend/src/api/mock.ts` — 生产验收路径不得依赖 mock 数据
   - `frontend/src/stores/*.ts` — 硬编码的 mock seed 数据（如 seed.ts 的 StepCheck、run.ts 的 selectedModels）
   - `frontend/src/pages/*.vue` — `status-note` 只允许说明真实/pending 状态，不允许 mock 绿灯
   - `?debugStates=1` 在生产构建（`npm run build`）中必须无效
   - `frontend/src/components/StateTools.vue` — 生产环境默认隐藏
   - `frontend/src/api/types.ts` — 枚举值（status 等）与后端保持一致
5. **烟测（内联 Python，不依赖 shell 脚本）** — 使用 Flask test client：
   - 内联 Python 覆盖 S1/S2/S4/S5/S6/S7
   - S1/S8 手工在浏览器验证 UI 渲染
6. **版本标记** — 每节点 `git tag v1.5.0a-nodeN` / `v1.5.0b-nodeN` / `v1.5.0c-nodeN`
7. **`make rebuild` 规则** — `rm -rf frontend/dist && npm run build && python -m adarian serve`

**不做什么：**
- 不改前端组件结构或页面布局
- 不改 `batch.py`（除非紧急 bug）
- 不改 `phase*/` / `analysis/` / `parser.py` / `schemas/`
- 不接受 mock 数据驱动的“绿灯”作为真实 E2E 通过证据
