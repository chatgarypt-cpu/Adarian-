## 三、归盘分析核心提取（Task B 审查结论）

### 3.1 第三次作业已验证的 8 条设计原则

1. **三层委托模型** — 策略层(Owner)→方案层(Hermes)→执行层(Claude Code)
2. **一张样张原则** — 样张被批准前不进入全量执行
3. **30 秒判断原则** — Owner 决策信息量控制在 30 秒内
4. **进度汇报三元素** — 进度条 + 已完成产出 + 等待决策
5. **不要假定原则** — 所有"我认为"都应配数据或样张
6. **信息层级四层设计** — 一眼/扫读/细读/查阅
7. **拒绝的勇气制度化** — Owner 不需要先附理由打回
8. **先整理再归盘** — workspace 清理是 closeout 的一部分

### 3.2 6 个可复用的生产范式

- **MCP 探针式采集范式**：平台探测 → 字段可得性判断 → 小样本 → 脚本 → 批量 → 质量闸门
- **样张 Gate 范式**：方向 → 样张 → Owner Gate → 定稿（实测 7 次全部走通）
- **三层委托模型**：策略→方案→执行
- **图文解释型 PDF 模板**：reportlab + 70-80% 图 + 20-30% 文字
- **归盘五问模板**：交付了什么/流程跑通/卡点复用/错误避免/反哺工作流
- **Hermes × Claude Code DAG 执行架构**：四角色分工

### 3.3 关键警戒

- 时间感知缺失 → 必须强制执行 MCP time
- 质量闸门不可跳过（title 字段缺失教训）
- 先可判断→再可复用→最后自动化

- **v0.3 是最完整、抽象层级最高的文件**，涵盖上下文补齐、任务等级、AI 修 AI、记忆隔离、渐进式披露等 v0.1/v0.2 没有的特性
- **v0.3 有明确的迭代路线**（v0.3→v1.0），可作 roadmap
- **v0.3 模板最完整**（最小任务书 + AI Fix Issue Packet + Node Receipt）
- 但 v0.3 **缺少 v0.2 §12 的架构图和角色分工表**，且 **完全没有目录协议**
- 能力蓝图提供 v0.3 缺失的 skill 层和工具层参考
- 归盘文件提供 8 条已验证的设计原则，是工作流的实践背书
