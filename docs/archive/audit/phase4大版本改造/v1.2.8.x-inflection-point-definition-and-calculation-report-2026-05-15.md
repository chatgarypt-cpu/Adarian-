## 3. 产品侧定义

### 3.1 定义

**模拟关键变化点**是指在多轮舆情推演过程中，系统基于模拟立场、群体分化、风险等级、风险类型与关键群体行为变化，识别出的具有解释价值的演化节点。

该节点不代表现实舆情中的真实传播拐点，而代表在本轮模拟设定下，舆情结构出现明显变化的时间点。

**当前代码中的实际定义**（`src/phase4/report_agent.py:759-762`）：
> 1. 计算每轮的极化指数变化
> 2. 极化指数变化最大的轮次为模拟关键变化点
> 3. 找出该轮次中立场变化最大的 Agent

**差距**：当前实现仅覆盖"群体分化"（polarization_delta）一个维度，未覆盖"模拟立场""风险等级""风险类型""关键群体行为变化"四个维度。

### 3.2 业务用途

模拟关键变化点服务以下业务问题：

1. **辅助分析师快速定位模拟轨迹中的关键轮次**：在多轮推演中，哪些轮次发生了值得关注的群体状态变化，避免逐轮阅读全部 tick 数据。
2. **支撑政府侧舆情研判**：为"讨论在什么时候开始转向""群体何时开始分化""风险是否升级"等治理问题提供可追溯的技术依据。
3. **为多平行世界分析提供可比对的结构化节点**：跨 run 统计高频变化点，识别鲁棒性信号 vs 随机波动。

### 3.3 与现实舆情拐点的边界

| 维度 | 模拟关键变化点 | 现实舆情拐点 |
|------|-------------|------------|
| 数据来源 | tick_logs 模拟数据 | 真实社交媒体/新闻/搜索数据 |
| 因果性 | 模拟推演设定下的条件性结果 | 真实社会因果 |
| 可验证性 | 可通过重跑模拟复现 | 不可复现 |
| 治理含义 | 预警参考，不等同于现实研判结论 | 可直接指导治理动作 |
| 时间维度 | 模拟轮次（tick） | 真实时间 |

**当前代码中的边界表达**（`src/phase4/report_prompts.py:292`）：
> "模拟关键变化点"表示模拟过程中群体状态出现明显变化的节点，用于辅助定位值得解释的演化阶段。该指标不等同于现实舆情中的真实传播拐点。

**边界执行缝隙**：当前禁止表达高度依赖 `SIMULATION_DISCLAIMER`（`report_prompts.py:11-14`）和 `MARKDOWN_GROUNDING_RULES`（`report_prompts.py:90-101`）中的 LLM prompt 约束。若 LLM 绕过这些约束生成"现实舆情已在第3轮出现拐点"类表述，`_normalize_saved_markdown()` 流程（`report_agent.py:568-579`）中没有针对性的正则拦截规则。

### 3.4 报告表达口径

**有模拟关键变化点时**（当前代码实际表达，`src/phase4/report_agent.py:1271-1283`）：

| 轮次 | 群体 | 模拟变化说明 |
|------|------|--------------|
| 第X轮 | 群体名 | 模拟极化指数变化 X.XX，立场偏移 +X.X |

**无模拟关键变化点时**（当前代码实际表达，`src/phase4/report_agent.py:1273`）：

**建议优化表达**（有变化点时增加自然语言引导句）：
> 本轮模拟显示，第 X 轮附近出现值得关注的模拟关键变化点，主要表现为{群体名}立场偏移 +{delta}，模拟极化指数变化 {pol_delta}。该节点仅代表本轮模拟设定下的演化特征，不等同于现实舆情传播拐点。

### 3.5 禁止表达

以下 5 类禁止表达的当前执行状态：

| 禁止表达 | 执行方式 | 执行强度 |
|---------|---------|---------|
| 1. 禁止写成"现实舆情已经出现拐点" | `SIMULATION_DISCLAIMER`（`report_prompts.py:11-14`）+ `FORBIDDEN_REALITY_PHRASES`（`report_prompts.py:16-23`） | 中等（仅 prompt 约束，无 post-processing 正则检测） |
| 2. 禁止写成"全网舆情发生转折" | `FORBIDDEN_REALITY_PHRASES` 含"全网已经"前缀 | 中等（可部分覆盖但非完整短语检测） |
| 3. 禁止写成"公众态度已经改变" | 无专项短语检测，"公众态度已经改变"不在 `FORBIDDEN_REALITY_PHRASES` 中 | 弱 |
| 4. 禁止把单次模拟节点包装为现实事实 | `SIMULATION_DISCLAIMER` + `MARKDOWN_GROUNDING_RULES` 约束 | 中等（依赖 LLM 遵守 prompt 指令） |
| 5. 禁止无 code-owned 依据时自行生成关键变化点 | 空 inflection_points 时的禁止指令（`report_agent.py:719`）+ placeholder 替换（`report_agent.py:550`） | 强（多层保障） |

**关键发现**：第 1-4 项禁止表达高度依赖 LLM 自觉遵守 system prompt 约束。`_normalize_saved_markdown()` 中不存在针对"拐点现实化表述"的专项 post-processing 正则替换逻辑。建议在 markdown normalizer 中增加 `_replace_reality_claims_about_inflection()` 函数。

## 4. 技术侧定义

### 4.1 当前实现定义

当前 `identify_inflection_points()` 函数（`src/phase4/report_agent.py:756-799`）的技术定义：

```text
IF abs(polarization_index[t] - polarization_index[t-1]) > 0.1
   AND tick_logs[t].entries is not empty
THEN
   标记 tick[t] 为模拟关键变化点
   取该 tick 中 stance_delta 绝对值最大的 Agent 作为代表
   最多返回 3 个（FIFO 顺序，非幅度排序）
```

**使用的信号**：
- `polarization_delta` — 唯一触发信号（`report_agent.py:779-781`）
- `stance_delta`（个体 Agent）— 辅助标识信号（`report_agent.py:786`）

**未使用但数据已就绪的信号**：
- `mean_stance` — GlobalMetrics 中已存储（`src/schemas/phase3.py:64`），每 tick 可用
- `group_stance_delta` — 可通过 AgentEntry 按 group_name 聚合得出
- `x_t_sequence` — 调用方已构建，但函数不接收该参数

### 4.2 优化后建议定义

建议将技术定义从单信号模型升级为多信号复合模型：

> 模拟关键变化点 = 满足以下**任一**条件的 tick：
>
> 1. **极化突变**：`|polarization_index(t) - polarization_index(t-1)| > 0.1`（保留现有逻辑，增加方向性区分）
> 2. **立场均值突变**：`|mean_stance(t) - mean_stance(t-1)| >= 0.3`（新增）
> 3. **关键群体立场跃迁**：任一 group 的 mean stance 变化 `>= 1.0`（新增）
> 4. **风险等级变化**（后续）：`risk_level(t) != risk_level(t-1)`（需逐 tick 风险计算支持）
> 5. **风险类型变化**（后续）：`set(risk_types_t) != set(risk_types_{t-1})`（需逐 tick 风险类型计算支持）
>
> 综合触发分数（建议，不要求当前实现）：
> ```
> inflection_score_t =
>   w1 * normalized_abs(stance_mean_delta_t)
> + w2 * normalized_positive(polarization_delta_t)
> + w3 * key_group_shift_score_t
> + w4 * risk_level_change_flag_t
> + w5 * risk_type_change_flag_t
> + w6 * narrative_shift_score_t
> ```
> 当 `inflection_score_t >= threshold` 且至少一个结构性信号成立时，识别为模拟关键变化点。

### 4.4 code-owned 与 LLM-assisted 边界

**必须 code-owned 的**：
- 触发信号计算（所有数学/统计算法）
- 阈值判断和识别逻辑
- source_metrics 数值
- change_type 枚举选择
- confidence 计算
- InflectionPoint 的基础字段（tick, agent_id, group_name, before_state, after_state, source_metrics）

**可以 LLM-assisted 的**：
- business_explanation（基于 code-owned 数值的业务化转译）
- report_ready_summary（用于 Markdown 正文的摘要句）
- conflict_focus_changed 检测（语义漂移分析）
- negative_narrative_intensity_changed（语义强度分析）

**禁止 LLM 做的**：
- 自行决定是否出现拐点
- 自行决定拐点位置（tick）
- 无 code-owned 依据时自行生成拐点描述
- 将模拟拐点包装为现实舆情拐点

### 5.3 当前计算逻辑

**identify_inflection_points 完整算法**（`report_agent.py:756-799`）：

```
输入: tick_logs (List[TickLog]), phase2_output (Phase2Output)
输出: List[InflectionPoint] (最多3个)

1. 构建 node_map = {node.id: node}（从 phase2_output.nodes）
2. FOR i = 1 TO len(tick_logs) - 1:
     prev_pol = tick_logs[i-1].global_metrics.polarization_index
     curr_pol = tick_logs[i].global_metrics.polarization_index
     pol_delta = abs(curr_pol - prev_pol)        # 绝对值，丢失方向性
     
     IF pol_delta > 0.1 AND tick_logs[i].entries 非空:
         max_entry = tick_logs[i].entries 中 abs(stance_delta) 最大的 AgentEntry
         node = node_map.get(max_entry.agent_id)
         
         创建 InflectionPoint(
             tick = tick_logs[i].tick,
             agent_id = max_entry.agent_id,
             group_name = node.group_name (或 "未知"),
             pivotal_comment = max_entry.comment[:50],   # 截断50字符
             impact_description = "模拟极化指数变化 {pol_delta:.2f}，立场偏移 {stance_delta:+.1f}"
         )
3. RETURN inflection_points[:3]  # FIFO顺序，非按幅度排序
```

## 6. 公式与计算口径

### 6.1 模拟立场均值变化

**公式**：
```
stance_mean_delta_t = mean_stance_t - mean_stance_{t-1}
```

**当前实现状态**：未实现。`identify_inflection_points()` 不使用 `mean_stance`。但数据已就绪——`GlobalMetrics.mean_stance` 在每 tick 的 `tick_logs[i].global_metrics` 中可用。

**建议阈值**：`abs(stance_mean_delta_t) >= 0.3`（在 1-10 立场量级上约 3% 的变化，对应显著的态度转向）。

**说明**：`stance_mean_delta_t` 为负值时表示整体态度向更批评/质疑方向移动，正值表示向更支持/认可方向移动。方向性比绝对值更具业务解释价值。

### 6.2 模拟极化指数变化

**公式**：
```
polarization_delta_t = polarization_index_t - polarization_index_{t-1}
```

**当前实现状态**：已实现但使用绝对值。`report_agent.py:781` — `pol_delta = abs(curr_pol - prev_pol)`。

**建议**：同时保留带符号版本和绝对值版本。带符号 delta 用于业务解释（极化加剧 vs 极化缓和），绝对值用于触发判断。

**说明**：`polarization_delta_t` 显著升高时（如 > 0.1），可能表示群体分化或对立增强。显著降低时（如 < -0.1），可能表示群体立场趋于一致或讨论热度消退。

### 6.3 关键群体立场迁移

**公式**：
```
group_stance_delta_{g,t} = stance_{g,t} - stance_{g,t-1}
```

其中 `stance_{g,t}` 为群体 g 在 tick t 的所有 Agent 的 `current_stance` 均值。

**当前实现状态**：部分实现。`_build_code_owned_agent_stance_matrix()`（`report_agent.py:667-693`）按 Agent 维度计算了全程 `delta = final - initial`（tick[1] 到 tick[-1]），但未做逐 tick 的群体聚合。

**建议阈值**：`abs(group_stance_delta_{g,t}) >= 1.0`（在 1-10 量级上代表显著立场迁移）。

**说明**：关键群体的显著迁移比整体均值变化更具有解释价值。例如，当"质疑方"群体立场从 5.0 降至 3.5 时，即使整体均值仅轻微下降，也代表核心风险群体的态度已发生实质变化。

### 6.4 风险等级变化

**逻辑表达**：
```
risk_level_changed_t = (risk_level_t != risk_level_{t-1})
```

**当前实现状态**：**未实现，当前不具备逐 tick risk_level_changed**。

原因：`assess_risk()`（`report_agent.py:829-920`）仅在整个模拟结束时调用一次（LLM路径：`report_agent.py:1046-1050`，fallback路径：`report_agent.py:1093-1097`）。不存在逐 tick 的 `risk_level` 序列。

**后续需要**：新增 `compute_risk_signals_per_tick()` 函数，复用 `assess_risk()` 中的信号计算逻辑（`report_agent.py:839-894`），对每个 tick 的前缀序列计算 risk 信号值，当信号组合跨越 MEDIUM/HIGH/CRITICAL 边界时标记 `risk_level_changed`。

### 6.5 风险类型变化

**逻辑表达**：
```
risk_type_changed_t = (set(risk_types_t) != set(risk_types_{t-1}))
```

**当前实现状态**：**未实现，且实现难度高于 risk_level_changed**。

原因：`select_primary_risk_types()`（`report_agent.py:132-170`）依赖 `audience_mode`（静态）和 `risk_assessment`（LLM 生成的字符串），无法在无 LLM 参与的情况下逐 tick 重建风险类型。

**建议**：不作为 code-owned 触发信号，作为 LLM-assisted 补充指标。在 Markdown 叙事中提及风险焦点转移时，由 LLM 基于 tick 间 `select_primary_risk_types` 的关键词变化进行判断。

### 6.6 综合触发分数草案

**公式**（建议口径，当前未实现）：
```
inflection_score_t =
    w1 * normalized_abs(stance_mean_delta_t)
  + w2 * normalized_positive(polarization_delta_t)
  + w3 * key_group_shift_score_t
  + w4 * risk_level_change_flag_t
  + w5 * risk_type_change_flag_t
  + w6 * narrative_shift_score_t
```

**权重建议**（待数据驱动校准）：
- `w1 = 0.20`（立场均值变化）
- `w2 = 0.25`（极化指数变化，保留现有逻辑的权重优势）
- `w3 = 0.25`（关键群体立场迁移，最具解释价值）
- `w4 = 0.15`（风险等级变化）
- `w5 = 0.05`（风险类型变化，LLM-assisted，权重较低）
- `w6 = 0.10`（叙事焦点变化，LLM-assisted）

**触发条件**：`inflection_score_t >= threshold` 且至少一个结构性信号（w1、w2、w3、w4 中至少一个）成立。

**注意**：
- 该公式为建议口径，不要求当前代码已实现。
- 权重需要在实际数据上校准，上述数值仅为初始建议。
- `normalized_*` 函数需要根据各信号的实际分布设计（例如除以标准差或预设 scale factor）。
- `narrative_shift_score_t` 依赖 LLM-assisted 信号，需单独评估其可靠性后再决定是否纳入。

### 6.7 阈值与误判控制建议

| 参数 | 建议默认值 | 调节方向 | 误判控制 |
|------|----------|---------|---------|
| `polarization_delta_threshold` | 0.1 | 高敏场景降低至 0.08，低敏场景提高至 0.15 | 误报（低波动噪音） |
| `stance_mean_delta_threshold` | 0.3 | 随 stance 量级调整 | 漏报（同步移动掩盖分化） |
| `group_stance_delta_threshold` | 1.0 | 按群体敏感度分级 | 漏报（小幅累积迁移被忽略） |
| `inflection_score_threshold` | 0.5 | 数据驱动校准 | 综合误报/漏报平衡 |
| `max_inflection_points` | 3 | 建议改为5，按score降序取top-N | FIFO遗漏后续更显著拐点 |

**误判风险**（当前已存在）：
1. **漏检（False Negative）**：立场均值大幅下降但极化指数稳定时，当前算法不触发。
2. **过度依赖单一指标**：`polarization_index = std/mean`，在 mean 和 std 同向变化时可能保持稳定，掩盖真实结构性变化。
3. **方向性丢失**：`abs(pol_delta)` 无法区分"极化加剧"（风险升级）和"极化缓和"（风险消退）。

## 9. 与风险计算补丁的关系

1. **风险计算补丁完成前**：本报告只能作为定义与设计依据。当前 `identify_inflection_points()` 不依赖 `assess_risk()`，因此风险补丁的完成不影响当前拐点识别逻辑。但本报告建议的多信号扩展（risk_level_changed、risk_type_changed）必须在风险补丁完成后才能实现。

2. **风险计算补丁完成后**：应复审代码是否符合本报告的产品定义与技术定义。重点复审：
   - `assess_risk()` 是否仍只在最终阶段调用
   - 是否存在逐 tick 的 risk 信号序列
   - `InflectionPoint` schema 是否已扩展至包含 change_type 和 source_metrics

3. **如果风险等级/风险类型仍只在最终阶段计算**：则关键变化点不能声称具备逐 tick 风险升级识别。产品侧问题"哪一轮风险升级""哪一轮风险性质变化"的回答只能标注为"不具备"。

4. **后续若要支持 risk_level_changed / risk_type_changed**：需要 per-tick 或 derived trace 级别的风险计算结果。建议新增 `compute_risk_signals_per_tick()` 函数，复用 `assess_risk()` 中的信号计算逻辑（`report_agent.py:839-894`）。

5. **不应让 LLM 直接决定风险等级或关键变化点**：当前架构中，`risk_level_label` 和 `risk_type_labels` 已在 `_build_code_owned_report_contract_block()`（`report_agent.py:221-242`）中作为 code-owned contract 注入 user prompt。关键变化点同理——`_format_code_owned_inflection_points()`（`report_agent.py:715-732`）作为 code-owned grounding block 注入。这一设计原则应在后续版本中保持和加强。
