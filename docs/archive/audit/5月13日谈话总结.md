## 一、报告结构从四章升级为五章

讨论确认最终舆情报告的正文章节从 **4 章扩展为 5 章**：

| 章节 | 名称 | 核心内容 | 数据源 |
|------|------|----------|--------|
| 一 | 舆情概要 | 真实事件背景与当前舆情现状概述 | 事件材料 |
| 二 | 舆情数据分析（**新增**） | 当前时间切片的声量、热度、情感分布、话题聚类、KOL、网络结构 | 微博等真实社交平台数据 |
| 三 | 演化分析 | 基于多智能体推演的阶段叙事、机制归纳、关键洞察（不呈现原始指标） | 模拟推演（压缩） |
| 四 | 风险研判 | 结合现状+演化发现，归纳可能发生的结构化风险 | 现状 + 多轮演化聚合 |
| 五 | 对策建议 | 面向政府决策者的治理动作建议 | 风险研判结论 |

**核心变化**：在传统"概要→风险→对策"之间插入两个支撑层（数据分析→演化分析），形成 **态 → 势 → 判 → 策** 的完整逻辑链路。

## 二、核心方法论：态势感知 = 态 + 势

这是本次讨论最底层的概念框架，是整个产品的理论基石。

### 定义

- **态（State）**：当前舆情现状 —— 声量、热度、情感分布、讨论话题、关键传播者、网络结构。**传统舆情系统只做这一步。**
- **势（Trend/Future）**：未来可能如何演化、存在哪些风险。**势必须通过模拟/推演获得，不能靠拍脑袋或经验猜测。**

### Adarian 的差异化定位

```
传统舆情产品：有态无势
Adarian：    态（真实数据）→ 多智能体模拟 → 势（风险可能性）
```

- 市场上绝大多数舆情产品只提供"当前数据仪表盘"
- Adarian 的核心竞争力 = **基于多智能体推演的"势"的研判能力**
- 报告中的第一、二章 = 态；第三章 = 态到势的桥接；第四章 = 势的结论

## 三、模拟数据在最终报告中的使用边界

讨论中反复打磨的核心规范——什么数据可以进入面向用户的最终报告？

### 禁止出现的数据

- Tick 级别的立场数值变化（如"反方立场从 5.0 断崖式降至 1.5"）
- 单次模拟中的具体百分比或精确数值
- 模拟过程的原始指标（个体 stance、逐轮 polarization 等）
- **原因**：这些是实验室过程数据，对真实决策者无意义，反而降低报告可信度

### 允许出现的数据

- 多次运行中一致出现的风险统计（如"5 次独立推演中，该风险类型出现 4 次"）
- 聚合层面的归纳性结论（如"六轮推演中该风险高度存在"）
- **判别标准**：能帮决策者理解"为什么这个风险值得关注"的数据保留；描述"模拟内部怎么跑的"的数据去掉

### 给 AI 的指导原则

- **不做二元规则**（"报告中绝对不能出现数据"），AI 容易走向极端
- **明确告诉 AI**：过程数据不出现、聚合结果可以出现
- **直接指定**哪些数据可用、哪些不可用，而非让 AI 自行判断

## 四、三层 AI Pipeline 架构

讨论形成了清晰的"多次推演 → 结构化中间产物 → 聚合归纳 → 最终报告"流水线：

```
                        ┌──────────────────────────────┐
                        │   Layer 3: 最终报告 Agent      │
                        │   输入：真实现状 + 聚合风险     │
                        │   输出：五章人类可读报告        │
                        └──────────────┬───────────────┘
                                       │
                        ┌──────────────▼───────────────┐
                        │   Layer 2: 聚合归纳 Agent      │
                        │   输入：N份结构化风险分析       │
                        │   输出：压缩归纳 + 标签聚合     │
                        └──────────────┬───────────────┘
                                       │
        ┌──────────┬──────────┬───────┼───────┬──────────┐
        ▼          ▼          ▼       ▼       ▼          ▼
      Run 1     Run 2     Run 3    ...    Run N-1    Run N
        │          │          │               │          │
    单次推演   单次推演   单次推演         单次推演   单次推演
    + 结构化   + 结构化   + 结构化         + 结构化   + 结构化
    风险输出   风险输出   风险输出         风险输出   风险输出
```

### Layer 1：单次推演 Agent（现有）

- 每次独立运行产出：演化数据 + 结构化风险分析
- 输出格式：**JSON / 结构化（给 AI 消费，非人类阅读）**
- 风险部分必须携带结构化标签（风险类型、影响群体、触发条件等）

### Layer 2：聚合归纳 Agent（新增）

- 输入：N 次独立推演的风险研判结果
- 任务：跨运行发现——哪些风险反复出现、哪些群体始终被涉及、哪些演化路径一致
- **核心洞察逻辑**：随机初始化的多次模拟中出现高度一致的风险 → 该风险具有结构性必然性，不是偶然产物
- 输出：压缩后的风险聚合报告（仍然是给 Layer 3 的输入）

### Layer 3：最终报告 Agent

- 输入：真实数据现状分析 + Layer 2 的风险聚合结果
- 任务：以政府决策者为读者，撰写融合真实背景与推演发现的风险研判报告
- 输出：面向人类的五章结构报告

### 规模化叙事

- 当前 MVP：5 次独立运行，每轮 5 tick
- 有了更多算力后：N 次独立运行（N 可扩展到 50/100/200）
- 算力增加 → 运行次数增加 → 聚合统计更可靠 → 风险发现更准确
- **"我们现在能做但不是不能做更多，是算力限制"——这是对甲方有利的叙事**

## 五、结构化风险标签体系

为了让 Layer 2 能做跨运行聚合，每份中间风险输出必须结构化：

### 单风险点标准字段

- 风险类型标签（标准枚举值）
- 受影响关键群体
- 触发条件/机制
- 升级路径
- 缓释条件
- 严重程度/影响广度

### 风险类型标签（示例）

意识形态渗透、国家形象受损、社会内部对立、执法公信力风险、监管责任质疑风险、群体极化风险

### 聚合逻辑

- AI 扫描 N 份结构化输出 → 统计每类标签出现频次
- 高频标签 = 高概率在未来真实发生的风险
- 模拟的随机性反而成为优势：随机初始化下仍反复出现的模式 = 结构性信号

## 七、之前的报告问题诊断与纠正方向

### 当前 v1.2.8 报告的问题

- 风险研判是基于模拟数据的"就数据写风险"——模拟出来什么就写什么
- 缺乏与真实现状的关联——读起来像"实验室诊断报告"而非"现实风险预警"
- 演化数据过度呈现——过程指标（立场从 X 变 Y）出现在最终报告中

### 纠正方向

- 风险研判必须**回归现实**：结论是"基于推演发现，未来真实世界可能存在的风险"
- 演化分析的数值用于**挖掘风险、扩展深度**，而非直接展示
- 最终报告的写法：**"我们进行了多轮推演，发现在多种情境下某类风险持续出现，因此判断该风险在未来真实舆情中极有可能发生"**
- 用"模拟中反复出现的行为模式"翻译为"真实社会中的风险编码"

## 八、产品开发与商业化策略

### 当前进展评估

- 已**超出预期**——五章框架清晰，态势感知概念成立
- Phase 4（报告生成）= "最后一公里"——决定了产品能不能用、好不好用
- 可投入 1-3 周打磨，不急上线

### 开发原则

- MVP 最小化：框架打牢，细节逐步填充
- 不追求一步到位的完美产品（这不现实）
- 约束条件下的最优解：现有算力、现有能力下把架构做对
- **迭代是必然的**：任何产品面对甲方都是迭代交付，不是一次性完美交付

### 商业化叙事

- 甲方（政府）现状：人工写舆情报告，人力成本高
- Adarian 价值主张：AI 逐步替代人工，释放人力
- 讲故事要点：态势感知概念（态+势）、模拟推演方法论、规模可扩展
- **客户不需要知道技术实现细节**（怎么做推演、Agent 怎么通信）
- **客户需要看到**：报告质量、风险预判准确度、与传统报告的差异
- 方法论细节在汇报时讲，日常交付中放在附录

## 九、风险等级计算逻辑问题（同日发现）

**在本次讨论后的 smoke testing 中发现**：`assess_risk()` 函数（`src/phase4/report_agent.py:729-761`）的阈值体系存在方向偏差。

### 当前逻辑

```
final_x > 7.5 或 (final_x > 7.0 且 trend > 1.0) → CRITICAL
final_x > 6.5 或 (final_x > 5.5 且 pol > 0.5)  → HIGH
final_x > 5.0 或 (final_x > 4.5 且 trend > 0.5) → MEDIUM
其他所有情况                                      → LOW
```

### 问题

- 阈值完全单向（只检测 x(t) 偏高），x(t) 下降到 4.1 以下不触发任何升级
- trend 也是单向（只检测正向上升），负向恶化反而不算风险
- 极化仅在 HIGH 档参与，MEDIUM 档不参考
- 三个不同事件类型（执法争议、校园事故、食品安全）全部被判为 LOW，缺乏区分度
- **疑似最初为品牌声誉场景校准**（高关注 = 高风险），与政府视角的语义相反

### 待解决

- 是否需要引入双向阈值（x(t) 偏低也是风险信号）
- 是否根据 `audience_mode` 切换风险计算策略
- 极化指数是否应在 MEDIUM 档参与判断
