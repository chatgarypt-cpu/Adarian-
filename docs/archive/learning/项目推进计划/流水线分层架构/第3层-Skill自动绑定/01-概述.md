# 01 - Auto-Binder 概述

## 在流水线中的位置

Auto-Binder（Skill 自动绑定器）位于流水线第 3 层，处于 **Plan Compiler（第 2 层 compile / canonicalize）之后、Materializer（第 4 层 DAG 物化）之前**。

```
Planning Agent 输出 WorkflowDraftPlan
        |
        v
Plan Compiler / canonicalize_workflow_plan()
        |  （规范化 node id、解析显式 skill 引用）
        v
Skill Auto-Binder / auto_bind_workflow_plan_skills()
        |  （自动绑定时仅对 allowed_mode="open" 生效）
        v
DAG Materializer / build_generated_dag()
        |  （物化为 GeneratedDAG → DAGNode/DAGEdge → 容器启动）
        v
Agent 容器执行
```

调用入口有两处，均通过 `auto_bind_workflow_plan_skills()`：

1. **plan_validator.py**（`canonicalize_workflow_plan()` 第 54 行）——Plan Compiler 在完成 id 规范化和显式 skill 解析后，立即调用 Auto-Binder，将结果 Plan 传给后续校验。
2. **workflow_materializer.py**（`validate_plan_dag()` 第 60 行、`build_generated_dag()` 第 461 行）——Materializer 在 DAG 校验和物化阶段，通过 `auto_bind=True`（默认）再次调用，确保所有 semantic node 获得最终 binding。

## 为什么需要 Auto-Binder

Planning Agent 在 `allowed_mode="open"` 模式下被允许生成**注册表不存在的 node_id**（semantic node）。典型场景：

- 用户提问涉及具体选区，如"分析台北市北区选情"——Planning Agent 可能生成 `district_race__taipei_north`，而该 id 在 `skills_registry.yaml` 中不存在。
- 用户提问涉及非标准议题组合，如"原住民选区 + 地方派系交互"——Agent 可能生成 `indigenous_faction_cross_analysis`，这是一种复合语义 id。

这些 semantic node 在物化到 DAG 前必须绑定到一个已知的 skill，否则容器启动时无法加载对应的 `SKILL.md` 和运行时配置。Auto-Binder 的职责就是在**不调用 LLM** 的前提下，通过确定性规则将 semantic node_id 映射到注册表中的 skill。

## 触发条件

Auto-Binder 的核心守门逻辑在入口函数第一行（`skill_auto_binder.py` 第 65 行）：

```python
if allowed_mode != "open":
    return plan
```

仅在 `allowed_mode="open"` 时执行绑定。其他模式（如 `skills_only`、`skills_plus_custom`）下，Planning Agent 被限制只能使用注册表内已知的 node_id，因此无需自动绑定，直接返回原 plan。

## 整体设计原则

Auto-Binder 是一个**纯正则规则引擎**，设计约束：

| 属性 | 说明 |
|------|------|
| **无 LLM 调用** | 所有匹配通过字符串比较和正则完成，确定性执行，零延迟 |
| **无副作用** | 不修改 SkillRegistry，不写文件，仅操作 WorkflowPlan 的 Python 对象 |
| **不可变输出** | 若所有 node 绑定均未变化，返回原 plan 对象（`skill_auto_binder.py` 第 70-71 行）；否则通过 `node.model_copy()` 返回新 WorkflowPlan |
| **优先显式** | 若 Planning Agent 已显式设置 `skill_id` / `skill`，直接采用，不覆盖 |
| **降级兜底** | 所有层都匹配失败时，node 保持未绑定状态，由 Materializer 统一降级为 `GENERIC_AGENT_SKILL_ID`（`"__generic__"`） |

## 入口函数

`auto_bind_workflow_plan_skills()`（`skill_auto_binder.py` 第 59-78 行）的签名和流程：

```
auto_bind_workflow_plan_skills(
    plan: WorkflowPlan,
    *,
    allowed_mode: str,
    skills: dict[str, dict] | None = None,
) -> WorkflowPlan
```

参数说明：
- `plan`：已经过 Compiler 规范化的 WorkflowPlan
- `allowed_mode`：由上游 `WORKFLOW_ALLOWED_NODE_MODE` 环境变量控制
- `skills`：可选的外部注入 skills 字典（测试用）；为 None 时调用 `_runtime_skills()` 从 `SkillRegistry.SKILLS` 获取

内部流程：

```
1. 若 allowed_mode != "open" → 返回原 plan
2. 获取 skill 注册表（来自参数或 SkillRegistry.SKILLS）
3. 初始化 used_single_use = set() （追踪已占用的 single_use skill）
4. 遍历 plan.nodes，对每个 node 调用 _auto_bind_node()
5. 若所有 node 均未变化 → 返回原 plan（避免不必要的对象拷贝）
6. 否则构造新 WorkflowPlan 返回
```

## 匹配流程图

```
  _auto_bind_node(node, used_single_use, skills)
              │
              v
   _is_executable_agent(node)?
      (kind=AGENT && enabled=True)
         │no              │yes
         v                v
    return node     _candidate_skill_id(node, skills)
    （不处理）              │
                           v
                    candidate 为空字符串？
                      │yes          │no
                      v             v
                  return node   _is_single_use_skill(candidate)?
                                  │yes               │no
                                  v                   v
                            candidate 已被占用？   _bind_node(node, candidate)
                              │yes    │no          （直接绑定）
                              v       v
                       _genericize_node  used_single_use.add(candidate)
                       （降级为通用）    _bind_node(node, candidate)
                                       （首次占用 single_use）
```

`_candidate_skill_id()` 内部按优先级执行四层匹配（详见文档 02）：

```
Layer 1: 显式 skill 赋值 (node.skill_id / node.skill)
   │命中 → 返回 skill_id
   │未命中 ↓
Layer 1b: 注册表精确匹配 (node.id in skills)
   │命中 → 返回 node.id
   │未命中 ↓
Layer 2: 双下划线前缀匹配 (node_id = "<family>__<detail>")
   │命中 → 返回匹配的 skill_id
   │未命中 ↓
Layer 3: 关键词正则降级 (_NODE_ID_SKILL_FALLBACKS)
   │命中 → 返回第一个正则命中的 skill_id
   │未命中 ↓
返回 "" （由 Materializer 降级为 __generic__）
```
