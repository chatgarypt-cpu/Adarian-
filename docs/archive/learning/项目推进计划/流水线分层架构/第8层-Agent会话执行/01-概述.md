# 01 - 概述

## Agent Session 在流水线中的位置

第 8 层 "Agent Session 执行" 是 ElectionSim-Lab 三层架构 (Frontend -> Orchestrator -> Agent) 的末端执行层。在 Orchestrator 完成 DAG 规划与调度后，节点任务通过 Docker 容器启动。每个 DAG 节点对应一个独立的 Agent 容器实例，容器启动后即进入本层所描述的 Agent 会话执行阶段。

Agent Session 执行层负责：
- 在隔离的 Docker 容器内加载任务上下文
- 组装系统提示词与运行时控制指令
- 通过 Claude Code CLI (`claude`) 或旧版 SDK (`claude-agent-sdk`) 驱动 LLM 推理
- 产出业务文件 (`result.json`、`report.md` 等) 并写回工作区

## 容器内执行入口

Agent 容器的唯一 Python 入口是 `agent/election_agent.py` 中的 `main_async()` 函数。根据节点类型的不同，执行路径有显著区别。

### Native Terminal Runner（主要执行路径）

自 2026 年重构后，所有非确定性节点（常规推理节点）统一走 **Native Terminal Runner**。入口文件为 `agent/native_terminal_runner.py`，其 `main_async()` 执行流程如下：

1. 解析 `--node-id` 命令行参数（`_parse_args()`）
2. 定位工作区目录 `_workspace_dir()` (环境变量 `CLAUDE_WORKSPACE`)
3. 确保协议目录存在 (`ensure_protocol_dirs`)
4. 加载 task prompt (`_load_task_prompt(ws)`)
5. **确定性节点判断**：若当前节点是 `deterministic_export` 或 `deterministic_appendix`，直接委托回 `election_agent.main_async()`
6. 获取模型名（环境变量 `CLAUDE_MODEL`，必须非空）
7. 写入运行时会话初始状态 (`_write_runtime_session(state="starting")`)
8. 预埋 CLI 配置文件 (`_seed_cli_config`)
9. **启动 Claude Code CLI 子进程** (`_run_cli`)：通过 `asyncio.create_subprocess_exec` 执行 `claude --print --output-format stream-json ...`
10. 将 task prompt 写入子进程 stdin，异步读取 stdout 流
11. 等子进程退出后，调用 `_finalize_non_deterministic` 收尾

### 确定性导出节点

`agent/export_runtime.py` 中的 `is_deterministic_export_skill()` 和 `is_deterministic_appendix_skill()` 用于检测节点是否为确定性导出节点。此类节点不走 LLM 推理，而是通过 `run_deterministic_export_only()` 和 `run_deterministic_appendix_only()` 直接执行确定性逻辑，通常用于转换/合并已有产出为最终报告格式。

## 核心执行循环

无论 Native Terminal 路径还是旧版 SDK 路径，Agent 执行循环本质相同：

1. **加载 task prompt**：从 `meta/task_prompt.md` 读取任务描述（包含上游事实交接、progress CSV 关联等）
2. **注入系统提示词**：组装时间基准 + 运行时控制指令，通过 `--append-system-prompt` 传给 CLI
3. **LLM 推理阶段**：CLI/SDK 将系统提示词 + task prompt 发送给模型，模型返回 assistant response
4. **工具调用阶段**：若 assistant response 包含 tool_use（如 `Read`、`Write`、`Bash`、`Grep` 等），Agent 执行工具并返回 tool_result
5. **继续推理**：模型收到 tool_result 后继续推理，可能再次发起工具调用
6. **产出阶段**：模型完成所有推理后，写出业务文件（如 `report.md`、`chart_manifest.json` 等）
7. **收尾阶段**：`election_agent._write_outputs()` 收集 artifacts、提取 summary、写入 `result.json`

## Native Terminal Runner 与 SDK 的差异

| 维度 | Native Terminal Runner | 旧版 SDK 路径 |
|------|----------------------|-------------|
| 入口 | `native_terminal_runner.py:main_async()` | `election_agent.main_async()`（已废弃） |
| 通信方式 | subprocess stdin/stdout JSON 流 | `claude-agent-sdk` Python API |
| 进程模型 | `asyncio.create_subprocess_exec` 拉起 CLI 子进程 | SDK 库内管理 |
| 输出格式 | `stream-json`（逐行 JSON） | SDK 事件对象 |
| 消息记录 | `native_terminal_runner._read_stream` → `_record_cli_line` | SDK event loop → event_recorder |
| 运行时会话 | `meta/runtime_session.json`（含 terminal payload） | `meta/sdk_session.json` + `meta/sdk_sessions.jsonl` |
