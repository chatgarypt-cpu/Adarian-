# 02 - 提示词组装

`build_node_prompt()` 位于 `orchestrator/dag/launcher_prompt.py` 第340-438行，按严格的七层顺序组装最终的 `task_prompt.md` 文本。每层由独立的 helper 函数生成，最终拼接为一个完整的 f-string 模板。

## 组装总览

```
build_node_prompt() 内部执行流程：

  ① task_description_for_skill()        → 任务描述
  ② language_constraint / search_prompt_constraint (外部传入)
  ③ EXECUTION_AUTHORITY_LINES            → 控制权声明
  ④ time_context / node_context 引用      → 文件读取指导
  ⑤ TOOL_SEARCH_LINES                   → 工具纪律
  ⑥ skill_tooling_block                  → Skill 特定工具指导
  ⑦ agenda_setter / candidate_registry scope → 节点级约束
  ⑧ TASK_SCOPE_LINES                    → 范围约束
  ⑨ READ_PROTOCOL_LINES                 → 数据读取协议
  ⑩ public_data_prompt_block            → 公共数据读取
  ⑪ resource_hint_prompt_block          → 资源线索
  ⑫ report_chain_prompt_block           → 报告链专项约束
  ⑬ required_outputs_prompt_block       → 输出合约
  ⑭ 业务文件写入纪律                      → 收尾规则
```

## 第一层：任务描述

**来源**：`node.agent_config.description` 和 `node.label`

**函数**：`task_description_for_skill()`（第267-275行）

```
任务: <description>

控制权顺序：
<execution_authority_prompt_block()>
```

**agenda_setter 特殊处理**：当 `skill == "agenda_setter"` 时，在原始 description 前注入前缀：

```
【起点节点限定】本节点只负责范围界定、候选人口径、下游分工与输出规格；
不要在本节点完成 KMT/DPP/TPP 最终人选盘点、逐人事实核验或最终报告写作。
```

这确保 agenda_setter 不会越界执行下游工作。对于所有其他 skill，description 原文传递。

## 第二层：上游产物摘要

**来源**：来自 prompt 最终写入时，上游产物摘要（`upstream_inputs`）由 DAG 调度器或 launcher executor 在调用 `build_node_prompt()` 之前注入到最终的 prompt 文本中。`build_node_prompt()` 本身不生成上游摘要，但在 prompt 模板中预留了以下指引：

- 上游节点产物只读挂载在 `/workspace/upstream/<node_id>`
- node context 文件中的 `upstream_inputs` 提供上游 workspace 指针（`workspace_path`、`csv_path`、`result_path`）与已验证的 `upstream_file_map`
- 缺失 `csv_path` 视为上游未写出 CSV 的契约错误
- 读取上游文件时必须原样复制索引表中的绝对路径，禁止自行拼接

## 第三层：资源提示

**来源**：`resource_hints.py` 的 `build_resource_hint_lines()`（第55-65行）

**函数**：`resource_hint_prompt_block()`（第263-264行）

从 `resource_audit` 提取 `matchedPaths` 和 `deepExploration.matchedFiles`，去重后取前 `MAX_RESOURCE_HINT_PATHS`（6条）作为 seed_paths。

若无 seed_paths，返回空元组，不产生任何输出行。

有 seed_paths 时生成：

```
- 规划阶段已命中的本地数据线索如下；优先从这些路径开始，不要重复大范围盲搜：
- `/public/02_民调数据/...`
- `/public/01_选举结果数据/...`
- ...
- 如果要读取这些线索，优先把上面的原字符串直接粘贴到 Read(file_path="...")；不要对 /public 使用 head、cat、find 等 Bash 探测。
- 上述路径只是起点；真正读取前仍需确认精确 path，并原样复用确认后的名称。
```

路径提取规则（`extract_resource_seed_paths()`，第68-76行）：
1. 遍历 `resource_audit["matchedPaths"]`
2. 遍历 `resource_audit["deepExploration"]["matchedFiles"]`
3. 通过 `_normalize_seed_path()` 规范化（dict 取 `absolutePath`/`absolute_path`/`path` 字段；前缀统一为 `/public/`）
4. 去重后取前 6 条

## 第四层：数据读取协议

**来源**：`READ_PROTOCOL_LINES`（第36-44行）和 `LOCAL_ONLY_READ_PROTOCOL_LINES`（第55-58行）

**函数**：`read_protocol_prompt_block()`（第245-248行）

分两个版本：

**KNOWLEDGE 版**（`search_enabled=True` 且 node_mcp 的 knowledge profile 启用）：

```
## 数据读取协议（强约束）
1. 本 prompt 已明确列出的 node-local 运行时文件必须直接 Read(file_path="...")
2. /public 是只读文件树；容器挂载成功就是读取边界
3. 读取 /public 时优先复用 resource_hints.seed_paths、upstream_file_map、knowledge MCP 线索
4. 未知路径使用 Glob / Grep 收敛，再用 Read(offset, limit) 分段核验
5. 搜索无结果时显式记录缺口和已尝试关键词/路径
6. 一旦达到最小必要证据必须立即写 output/ 产物
```

**LOCAL-ONLY 版**（`search_enabled=False` 或 knowledge profile 未启用）：

```
## 数据读取协议（强约束）
<READ_PROTOCOL_LINES 的第1-6条（去掉知识库引用）>
```

`LOCAL_ONLY_READ_PROTOCOL_LINES` 通过 Python 解包语法 `*READ_PROTOCOL_LINES[1:]` 跳过第0条（知识库相关的 MCP 引用），保留纯本地读取协议。

## 第五层：工具调用纪律

**来源**：`TOOL_SEARCH_LINES`（第45-54行）

**函数**：`tool_search_prompt_block()`（第237-238行）

核心约束：

- **工具真值顺序**：当前会话 `init` 暴露的工具 > prompt 已渲染的 MCP 别名 > `ToolSearch` 搜索结果
- `ToolSearch` 不是固定预热步骤；已知确切别名时直接调用
- 已知 `tool_reference` 后立即调用，不停在"已搜到工具"层
- 禁止猜参数名：`Read` 必须传 `file_path`，`Write` 必须传 `file_path` + 字符串 `content`
- `Write.content` 必须是字符串：写 JSON 时必须先用 `json.dumps()` 序列化

## 第六层：节点级 SCOPE_LINES（按 skill_id 匹配）

**来源**：`AGENDA_SETTER_SCOPE_LINES`（第59-69行）、`CANDIDATE_REGISTRY_SCOPE_LINES`（第70-76行）

**函数**：`agenda_setter_scope_prompt_block()`（第255-256行）、`candidate_registry_scope_prompt_block()`（第259-260行）

当 `skill == "agenda_setter"` 时注入 agenda_setter 的 9 条约束：
- 职责限定为范围界定而非最终事实核验
- 必须使用 `meta/node_context.json.downstream_nodes` 的真实 node_id
- 下游 CSV 必须通过 `Skill(csv-task-spec)` fork 生成
- 禁止读取超大候选人总表或做人海穷举

当 `skill == "candidate_registry_searcher"` 时注入候选人核验的 5 条约束：
- 以上游 progress CSV 摘要为事实边界
- 禁止人海搜索
- 每位候选人最多一轮精确搜索 + 1-3 个文件读取
- 字段缺失立即标记并写出报告

**通用范围约束**（所有节点生效）：`TASK_SCOPE_LINES`（第30-35行）和 `EXECUTION_AUTHORITY_LINES`（第77-81行）始终注入。

### Skill 特定工具指导

**函数**：`build_tooling_guidance()` 来自 `common/skill_docs.py` 第219行，根据 skill_id 从注册表读取对应的工具使用指导并渲染为 prompt 块。指导内容以 `skill_tooling_section` 变量注入到工具纪律之后。

## 第七层：输出合约

**来源**：`required_outputs` 参数

**函数**：`required_outputs_prompt_block()`（第278-296行）

如果 `required_outputs` 非空：

```
- 本节点本轮至少要真实写出以下具名业务文件：output/report.md、output/evidence_map.json。
- 这些具名业务文件才是本轮主交付；不要再把 output/result.json 当作默认必写项。
- 如果当前节点是 agenda_setter 且 required outputs 中包含 output/task_spec/..._todo.csv，必须通过 Skill(csv-task-spec) fork 生成下游 CSV。
```

如果 `required_outputs` 为空：

```
- 本节点必须真实写出至少一个业务文件；不得只留下协议骨架、空目录或只推进 progress CSV。
- 除非 execution_contract 或显式 required outputs 要求，否则不要把 output/result.json 当作主交付。
```

## 报告链专项约束

**函数**：`report_chain_prompt_block()`（第299-337行）

按 skill_id 精确匹配：

- `report_generator`：13 条约束（初稿职责、章节格式 `一二三`/`（一）（二）（三）`、补充 PNG 图表、evidence_map 的 fact/inference/scenario 三级分类等）
- `report_reviewer_and_polisher`：9 条约束（读上游报告、Improve Don't Replace、补齐附录表格、删除须记录理由等）
- `html_report_builder` 和 `election_visualizer`（`REPORT_CHAIN_VISUAL_NODES`）：3 条约束（标题数字一致、不新增数据、图表资产写出）
- 其他节点：输出 "- 当前节点不在正式报告链内，无额外专项约束。"

## aganda_setter 的特殊豁免

当 `is_agenda_setter=True` 时（第357行判断），三块内容被设为空字符串：
1. `public_data_block` —— 不注入公共数据读取协议
2. `read_protocol_block` —— 不注入数据读取协议
3. 这些豁免是因为 agenda_setter 不需要从 `/public` 读数据，它的工作是以 task_spec 为出发点定义下游范围

## 调试注入

当 `extra_prompt` 非空时，在 prompt 末尾追加（第436-439行）：

```
## 调试注入（仅本次执行生效）
<extra_prompt>
```

`extra_prompt` 仅在 debug session（如 `debug_session_id` 已设置）时由 `launcher_executor.py` 传入，正常生产流程始终保持 `None`。
