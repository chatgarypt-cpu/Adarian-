# 第4层 DAG 物化器 -- 概述

## 1. 定位

DAG 物化器 (Workflow Materializer) 是流水线分层架构的第4层，位于**第3层 Auto-Binder**（`skill_auto_binder`）之后、**第5层 Launcher Prompt** 之前。

核心职责单一：将 LLM Planner 产出的 `WorkflowPlan`（逻辑计划）**编译**为 `GeneratedDAG`（可执行 DAG）。前者是 Planner 输出的"用户意图"级别的 DAG 描述，后者是 Runtime 可直接调度和执行的"机器可读"数据结构。

```
Planner (LLM)
    |
    v
WorkflowPlan (逻辑计划: nodes/edges/rationale)
    |
    v  [第3层: Auto-Binder -- auto_bind_workflow_plan_skills()]
    |    绑定 skill_id / skill / skills 字段
    |    开放模式下按关键词正则回退到已知 Skill
    |
    v  [第4层: DAG Materializer -- build_generated_dag()]
    |    校验 + 搜索子节点注入 + 物化 + 拓扑排序
    |
    v
GeneratedDAG (可执行 DAG: nodes[DAGNode]/edges[DAGEdge]/workflow_id/estimated_duration)
    |
    v  [第5层: Launcher Prompt]
```

## 2. 入口函数

整个物化器的唯一公开入口：

```
orchestrator/dag/workflow_materializer.py :: build_generated_dag()
```

调用方式：

```python
dag = build_generated_dag(
    plan=workflow_plan,
    allowed_mode="open" | "skills" | "skills_plus_custom",
    custom_prefix="...",
    generation_source="planning",
    generation_details={...},
    name_fallback="fallback_name",
    thinking="...",
    thinking_duration_ms=...,
    skill_entries=skill_registry_entries(),
    auto_bind=True,
)
```

## 3. 内部处理流水线

`build_generated_dag()` 内部按以下顺序执行 5 个阶段：

```
WorkflowPlan
    |
    v
1. Auto-Bind (可选, auto_bind=True)
   auto_bind_workflow_plan_skills(plan, allowed_mode, skills)
   输出: prepared_plan (skill_id/skill/skills 已填充)
    |
    v
2. 搜索子节点注入
   _inject_search_sub_nodes(prepared_plan, skill_entries)
   输出: prepared_plan (external_search / requires_knowledge_search 展开为独立节点)
    |
    v
3. 全面校验
   _validate_materialized_plan(...)
      -> validate_plan_dag(...)         # 语义+结构校验
      -> _validate_runtime_plan_size()  # 节点/边数上限
      -> _ensure_unique_node_ids()      # 二次去重
   输出: 校验通过 / 抛 ValueError
    |
    v
4. 物化
   _build_runtime_nodes(plan, ...)
      -> assign_layers_orders(plan)     # 拓扑排序(BFS) + 层级分配
      -> _materialize_node()           # 每个节点 -> DAGNode
   输出: list[DAGNode]
    |
    v
5. 装配 GeneratedDAG
   workflow_id = new_workflow_id()
   name = _resolve_plan_name(plan, name_fallback)
   estimated_duration = _estimated_duration(nodes)
   输出: GeneratedDAG
```

## 4. 关键数据结构对照

| 逻辑层 (输入) | 可执行层 (输出) |
|--------------|----------------|
| `WorkflowPlan` (Pydantic) | `GeneratedDAG` (dataclass) |
| `WorkflowPlanNode` (Pydantic) | `DAGNode` (dataclass) |
| `WorkflowPlanEdge` (Pydantic) | `DAGEdge` (dataclass) |
| `node.kind` (枚举 `WorkflowNodeKind`) | `node.kind` (str: "agent"/"internal") |
| `node.skill_id / node.skill / node.skills` | `node.agent_config["skill"] + ["skills"]` |
| `node.external_search / requires_knowledge_search` | 展开为独立搜索子节点 |

`DAGNode` 相比 `WorkflowPlanNode` 新增的关键字段：
- `layer` / `order` -- 拓扑层级和层内顺序
- `agent_config` -- agent 启动时注入的配置字典
- `block_profile` -- 阻断策略（并发/单实例等）
- `status` -- 运行时状态 ("pending" / "running" / "completed" / "failed")
- `critical` -- 失败后是否阻断下游

## 6. 与上下层的耦合

- **上游依赖**: 调用 `auto_bind_workflow_plan_skills()` (第3层) 做 skill 预绑定。
- **上游依赖**: 调用 `resolve_node_skill_id()` / `resolve_node_skill_ids()` (skill_binding) 解析节点 skill 绑定。
- **下游供给**: 产出 `GeneratedDAG`，其 `nodes` 列表中的 `DAGNode.agent_config` 会被第5层 Launcher Prompt 用作 agent prompt 生成输入。
- **运行时依赖**: `topology.py` 中的 `executable_node_ids()` 和 `topological_layers()` 在 Runtime 调度阶段消费 `GeneratedDAG` 做执行层划分。
