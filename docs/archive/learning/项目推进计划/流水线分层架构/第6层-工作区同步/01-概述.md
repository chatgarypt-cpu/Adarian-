# 01-概述：Workspace Sync 层

## 1. 在流水线中的位置

Workspace Sync 层位于整个 DAG 执行流水线的第 6 层。它处于以下两个关键环节之间：

1. **Launcher Prompt 生成之后**：上游已完成 task_prompt.md、node_context.json、time_context.json 等运行时文件的生成。
2. **Docker Container Launch 之前**：下游即将通过 `AgentLauncher.launch()` 启动 Docker 容器执行节点任务。

流程示意：

```
[第5层: Launcher Prompt 生成]
  -> 写入 input/task_prompt.md, meta/node_context.json, meta/time_context.json
         |
[第6层: Workspace Sync] <-- 本章节
  -> sync_workspace_skills() 将 claude-runtime/ 投影到 .claude/
  -> MCP 模板变量渲染
         |
[第7层: Docker Launch]
  -> 挂载 /workspace/<run_id> 到容器
  -> 容器内 Agent 读取 .claude/skills/ 和 .claude/agents/
```

Workspace Sync 的核心调用点有两处：

- **Planning Agent 启动时**：`planning_agent.py` 第 154 行 `_prepare_planning_agent_workspace()`，在临时目录中执行 sync。
- **DAG 节点 Agent 启动时**：`launcher.py` 第 653 行和第 863 行，在 agent 容器启动前的 workspace 准备阶段执行 sync。

## 2. 核心问题

整个流水线的设计假设是：**宿主机上的 `claude-runtime/` 目录是 Skill 和 Agent 定义的唯一权威源**。但 Agent 容器内运行的 Claude Code SDK 期望在 `.claude/skills/` 和 `.claude/agents/` 下找到这些定义。

因此核心问题是：

> 如何将宿主机项目根目录下的 `claude-runtime/{skills,agents,settings.json}` **准确、可重复地映射**到每个 Agent 容器工作区内的 `.claude/{skills,agents,settings.json}`？

需要解决的关键约束：

| 约束 | 说明 |
|------|------|
| **多节点隔离** | 每个 DAG 节点运行在独立的 workspace 下（`/workspace/<run_id>/<node_id>/`），同步必须是节点级隔离的 |
| **全量覆盖** | 每次启动前全量 `rmtree` + `copytree`，不留残留 |
| **模板变量渲染** | Skill/Agent 文档中的 `{{MCP_*}}` 占位符需要根据当前节点的 MCP 配置替换为具体工具名 |
| **目录结构转换** | 宿主机按 `skills/<category>/<name>/SKILL.md` 的层次存放，容器内扁平化为 `.claude/skills/<name>/SKILL.md` |

## 3. sync_workspace_skills() 的核心逻辑

函数签名（`orchestrator/agent/workspace_skills.py` 第 22-38 行）：

```python
def sync_workspace_skills(
    workspace: Path,
    *,
    source_dir: Path | None = None,
    node_mcp: dict | None = None,
) -> Path:
```

核心流程（4 步）：

```
1. 解析 source_dir
   - 若传入 source_dir → 直接使用
   - 否则调用 default_skills_dir() → common/claude_runtime_assets.py

2. 全量清理旧投影
   - 若 workspace/.claude/skills 已存在 → shutil.rmtree(dest)

3. 4 个子步骤依次执行：
   a) _copy_runtime_skill_projection()  -- 复制 skills/ 树，扁平化
   b) _render_workspace_markdown()       -- 对 .md 文件执行 MCP 模板渲染
   c) _sync_workspace_agents()           -- 同步 agents/ 目录（全量复制）
   d) validate_workspace_agents()        -- 校验 agent 定义合法性

4. 返回目标 skills 目录路径
```

同步后 workspace 内 `.claude/` 的结果布局：

```
workspace/.claude/
  skills/           # 从 claude-runtime/skills/ 投影而来
    <skill-name-1>/     # 扁平化：每个 SKILL.md 的父目录整体复制
      SKILL.md
    <skill-name-2>/
      SKILL.md
    _shared/            # 共享资源目录，原样复制
  agents/           # 从 claude-runtime/agents/ 全量复制
    <agent-name>.md
  settings.json     # 从 claude-runtime/settings.json 复制（root assets 的一部分）
```

## 4. claude-runtime/ 源目录结构

`claude-runtime/` 在项目根目录下的完整结构如下：

```
claude-runtime/
  skills/
    dag/
      entry/          # 入口类 Skill（如 workflow_dag_spec.md）
      analysis/       # 分析类 Skill
      collection/     # 数据采集类 Skill
      synthesis/      # 综合类 Skill
      export/         # 导出类 Skill
      reporting/      # 报告类 Skill
      quality/        # 质量检查类 Skill
    planner/
      framework/      # 规划框架 Skill
    shared/
      runtime/        # 运行时共享 Skill
      quality/        # 质量共享 Skill
      debug/          # 调试共享 Skill
      mechanical/     # 机械性操作 Skill
    external/
      linkly-ai/      # 外部 MCP 工具 Skill
        SKILL.md
    _shared/          # 跨 Skill 共享资源（非 Skill 定义本身）
  agents/
    csv-row-worker.md
    data-explorer.md
    evidence-aggregator.md
    haiku-worker.md
    knowledge-researcher.md
    quality-checker.md
    upstream-reader.md
    web-searcher.md
  settings.json       # Claude Code 全局 settings
  _local/             # 本地缓存和 worktrees（已 git/docker 忽略）
```

关键设计原则：

- **分类子目录**：skills 按功能域分层（dag/planner/shared/external），便于人类维护。
- **SKILL.md 为入口**：每个 skill 的目录下必须有 SKILL.md 作为唯一识别文件。
- **扁平化投影**：同步时按 SKILL.md 的 frontmatter `name` 字段决定目标目录名，忽略源目录层次。
- **agents 直接复制**：agents 目录不扁平化，原样复制到 `.claude/agents/`。
