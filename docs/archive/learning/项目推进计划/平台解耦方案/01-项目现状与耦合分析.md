# 01 — 项目现状与耦合分析

---

## 1. 项目现状

### 1.1 系统概览

ElectionSim-Lab 目前是一个**以台湾选举分析为核心场景的多 Agent DAG 工作流平台**。

| 层 | 技术 | 规模 |
|---|---|---|
| Orchestrator | Python 3.14, FastAPI 0.135, Docker SDK | 525 文件 |
| Agent Runtime | claude-agent-sdk 0.1.63 | 68 文件 |
| LLM Gateway | Anthropic/OpenAI/Gemini 三协议 | - |
| Frontend | React 19, Vite 7.3, ReactFlow 11 | 290 文件 |
| Common | Skills Registry, Report Quality, CSV Progress | 30+ 模块 |
| Infrastructure | Docker Compose (6 服务 + 3 MCP profile) | - |

### 1.2 核心流程

```
用户意图 → Chat API → Planning Agent → DAG Plan Generation
       → Compile → Validate → Repair Loop → Materialize
       → Docker Launch Agent Containers → Execute Nodes
       → Quality Gate → Export → SSE Stream to Frontend
```

### 1.3 DAG 引擎能力

- 35 个可插拔 Skill（YAML 驱动注册表）
- 6 种 DAG 拓扑模板（菱形/双阶段扇出/分治汇聚/瀑布/多菱形/星芒）
- Plan 编译 → 语义校验 → 自动修复 → 物化完整链路
- 沙箱化 Agent 容器（Docker，资源隔离，超时保护）
- CSV 任务批处理（断点续跑、进度追踪）
- 多 Worker 架构（API + Runtime + Maintenance 三进程分离）
- 节点调试双通道（dagctl CLI + REST API）

### 2.2 领域专属层（6 个选举耦合点）

#### A. Skills Registry（技能注册表）

- **文件**: `common/skills_registry.yaml` (1811行, 35个技能)
- **选举专属** (~18 个): `candidate_profile_analyst`, `party_list_threshold_analyst`, `cross_regional_comparator`, `electoral_demography_analyst`, `swing_district_detector`, `district_race_analyst`, `referendum_campaign_analyst`, `issue_impact_analyst`, `electoral_institution_analyst`, `polls_collector`, `history_data_collector`, `candidate_registry_searcher` 等
- **通用可保留** (~14 个): `data_discovery`, `evidence_synthesizer`, `master_analyst`, `report_generator`, `report_reviewer_and_polisher`, `election_visualizer`(→`chart_visualizer`), `web_artifacts_builder`, `csv_task_spec`, `csv_task_runner`, `dag_node_debug`, `pptx`, `xlsx`, `agenda_setter`, `chat_planner_guide` 等
- **共享可保留** (~3 个): `exa_web_researcher`, `library_context_retriever`, `linkly_ai`

#### B. Claude Runtime Skills（源文件）

- **目录**: `claude-runtime/skills/` (4 层: dag/external/planner/shared)
- **选举专属**: `dag/` 下大部分 DAG 节点 skill，`planner/` 下专题分析 skill
- **通用**: `shared/` 下 CSV、导出、质量检查等工具 skill

#### C. Planner Skills（规划层追问模块）

- **目录**: `orchestrator/chat/planning/planner_skills/` (12 个文件)
- **全部选举专属**: `county_mayor_race.py`, `party_list_threshold.py`, `recall_wave.py`, `referendum_impact.py`, `voter_turnout_sensitivity.py`, `council_seat_projection.py`, `cross_strait_scenario.py`, `local_governance_issue.py`, `party_realignment.py`, `poll_methodology_audit.py`, `schema.py`, `__init__.py`

#### D. Agent 选举模型

- **文件**: `agent/` 下 11 个选举专属 py 文件
  - `election_agent.py` (1167行，含选举逻辑)
  - `taiwan_election.py`, `tw_election_core.py`, `tw_election_model.py`
  - `tw_local_2026.py`, `tw_local_common.py`, `tw_local_report.py`
  - `tw_local_report_analysis.py`, `tw_local_report_appendix.py`
  - `tw_local_report_context.py`, `tw_local_report_sections.py`

#### E. Public Data（数据目录）

- **目录**: `public/` (7 个选举数据目录)
  - `01_选举结果数据/`, `02_民调数据/`, `03_清洗后数据/`, `04_资料库/`
  - `candidates/`, `districts/`, `historical/`

#### F. 命名与配置

- 环境变量前缀: `ELECTIONSIM_CLAUDE_RUNTIME_DIR`
- 容器镜像: `election-agent:latest`
- Docker 容器名: `election-orchestrator`, `election-frontend`, `election-runtime-worker` 等
- 项目名: `ElectionSim-Lab`

### 2.3 耦合可视化

```
                    ┌─────────────────────────────────────────┐
                    │     通用 DAG 引擎 + LLM 网关 + 容器调度      │
                    │    routers / export / frontend monitor    │
                    │          ← 0 选举引用，纯粹通用 →           │
                    └────────────────┬────────────────────────┘
                                     │
            ┌────────────────────────┼────────────────────────┐
            │                        │                        │
   ┌────────▼───────┐    ┌──────────▼──────────┐    ┌───────▼──────────┐
   │ skills_registry│    │ planner_skills/     │    │ agent/           │
   │ .yaml (1811行) │    │ 12 选举模块          │    │ tw_*.py (11文件) │
   │ 35 技能        │    │ 全部选举专属          │    │ 台湾选举模型     │
   └───────┬────────┘    └──────────┬──────────┘    └───────┬──────────┘
           │                        │                       │
   ┌───────▼────────┐              │               ┌───────▼──────────┐
   │ claude-runtime/│              │               │ public/          │
   │ skills/ (4层)  │              │               │ 选举数据 (7目录) │
   │ agents/ (8个)  │              │               └──────────────────┘
   └────────────────┘              │
                           ┌───────▼───────────┐
                           │ env: ELECTIONSIM_ │
                           │ CLAUDE_RUNTIME_DIR │
                           └───────────────────┘
```

> **关键发现**：DAG 引擎核心模块对选举零引用。解耦的本质不是重写，而是把 6 个红色耦合点从代码中「拔出来」变成可插拔的领域包。
