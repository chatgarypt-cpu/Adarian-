# 01 — 核心思想

---

## 我们在建什么

> **一个能自我繁殖、自我进化的 Agent 生态系统基座。**
>
> 不是一个工具。不是一套写死的多 Agent 流水线。
> 是一个基座 + 一个主模型 + 持续诞生的领域 Agent 社会。

---

## 三个关键词

### 1. 主模型

一个超大规模主模型。它不写具体的 SKILL.md，不调 DAG 引擎。

它的职责是：
- **理解领域本质**——"金融分析"和"法律审查"的深层结构差异是什么？哪些模式可以跨领域迁移？
- **设计 Agent 社会的宪法**——这个领域的 Agent 之间如何通信？质量评判标准是什么？
- **自我进化**——每完成一个领域包，从结果中抽象出更通用的元模式，反哺回平台
- **跨领域连接**——发现两个截然不同领域的共同骨架（如数据采集→实体标准化→证据推理→报告输出），自动生成跨领域桥接

### 2. Agent 社会

主模型不亲自执行。它孵化「领域架构师 Subagent」，每个领域架构师再去孵化那个领域的技能编写者、模型编写者。

```
主模型
  ├── 领域A架构师 → N个技能 + 追问模块 + 领域模型
  │     ├── 数据采集组
  │     ├── 分析推理组
  │     └── 报告输出组
  ├── 领域B架构师 → M个技能 + 领域模型 + 合规审查
  ├── 领域C架构师 → K个技能 + 量化模型 + 风控系统
  └── 领域D架构师 → ...（下一个）
```

每一套 Agent 社会独立运行在 GenFlow 的 DAG 引擎之上，但共享同一套底层能力：容器调度、LLM 网关、事件流、产物链。

### 3. 自我进化的基座

GenFlow 在三个层面上都是**可被主模型重新编程的**：

| 层面 | 可被改写的内容 |
|---|---|
| **Skills 层** | 全部技能定义、技能间依赖关系、产物协议 |
| **Planner 层** | 追问策略函数、DAG 拓扑模板、节点编排策略 |
| **基座层** | 质量门规则集、LLM 网关配置、容器编排策略、Settings 配置项 |

没有什么东西写死在引擎核心里需要人类手动改。GenFlow 是「空心」的——它的所有领域知识都在外围。

---

## 为什么这事能成

三个前提条件：

1. **GenFlow 的 DAG 引擎对任何领域零感知。** 它只关心节点和边，不关心节点里跑的是什么领域的分析。

2. **领域包的接口格式是固定的。** package.yaml、skills.yaml、SKILL.md 的 schema 是死的——这意味着主模型有一个**封闭的、格式化的操作面**。

3. **每接入一个新领域，不是从零开始。** 主模型从已有的成功案例中抽象出结构模式（ingestion→normalization→validation→reasoning→reporting），新领域只需要填充特化内容。

---

## 与平台解耦的关系

```
平台解耦（Phase 1-4）
  │
  │ 目标：把第一个领域的所有领域逻辑外移，证明平台是真正空心的
  │ 产出：GenFlow 基座 + 2个领域包（领域A + 领域B）
  │
  ▼
主模型入驻（Phase 5-6）
  │
  │ 前提：至少 2 个成功领域包作为参考样本
  │ 目标：主模型孵化第三个领域包（全自动），启动自我迭代循环
  │ 产出：能自我进化的 Agent 生态系统
```

平台解耦是主模型入驻的**前提条件**——只有证明基座真正空心，主模型才有操作空间。
