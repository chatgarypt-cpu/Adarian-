## 第 1 层：Owner Brief（人话摘要）

### 1. 这轮干嘛？

把已经通过 bypass 验证的 `tools/probe_scheduler/` 包装成一个可演示的 **平行世界推演控制台 R0**：用户输入舆情事件、选择多个模型、点击开始运行，系统真实产出多份 `simulation_dataset.json`。

本轮不是完整产品化，而是 **MVP 论证闭环**。

---

### 2. 为什么现在做？

当前多模型平行推演能力已经具备技术可行性，但仍停留在工具脚本 / bypass 验证层。下一步需要把它包装成一个用户能看懂、能点击、能演示、能验证产物的前台雏形。

本轮核心验证问题：

```text
输入一个事件 → 选择多个模型 → 生成多个平行世界 → 产出 N 份 dataset
```

这条产品链路是否成立。

---

### 3. 谁调度？谁执行？

- 调度：Hermes / PM Runtime
- 执行：Codex
- 审查：本轮默认不需要 Team Review；若 Codex 发现 `tools/probe_scheduler/` 路径、依赖或调用链与计划不一致，必须 HOLD 并要求 reality check。

注意：Hermes 不写代码。Hermes 只负责 dispatch、监控和 evidence 回收。

---

### 4. 单节点还是多节点？

`single_node`。

这是一个高约束 MVP 包装任务：入口整理 + 单页前端 + dataset smoke，不需要 Claude Code DAG。

```text

平行世界舆情推演控制台
```

```text
多模型平行推演任务的可视化指挥舱。
```

### UI 风格要求

参考方向：MiroFish-like AI simulation product flow + 数智化单位大屏看板。

视觉关键词：

```text
dark digital cockpit
```


### 页面结构

```text
顶部：
- Adarian Parallel World Console
- 一句话说明：输入事件，生成多个舆情演化平行世界
- batch 状态 / 系统状态 / 当前时间

主输入区：
- 舆情事件文本输入框
- 预设 seed 快捷按钮
- 推演模式提示：快速推演 / 多模型平行推演（本轮可静态展示）

流程预览区：
Seed Event → Model Dispatch → Parallel Worlds → Simulation Dataset → Report Agent Ready

模型区：
- 模型多选
- 默认勾选 2 个可用模型
- 开始生成平行世界按钮

运行区：
- batch_id / batch_dir
- world 总数
- success / failed / running 数量

World Result Cards：
- world_id
- model_name
- status: pending / running / success / failed
- output_dir
- dataset_exists
- risk_type_classification.primary_types 检查结果
- error_summary（失败时）

底部：
- 运行日志
- 产物路径
- 下一步入口：Report Agent Consumer（disabled / coming soon）
```

### 允许 fake 的内容

