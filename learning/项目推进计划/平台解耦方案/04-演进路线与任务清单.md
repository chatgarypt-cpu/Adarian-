# 04 — 演进路线与任务清单

---

## 5. 分阶段演进路线

```
Phase 1 ──────── Phase 2 ──────── Phase 3 ──────── Phase 4
「脱选举化」     「包加载机制」    「Agent 解耦」    「第二领域验证」
  低风险            中风险            中风险            高风险
  ~2天              ~4天              ~5天              ~7天
```

### Phase 1: 脱选举化与命名空间清理（低风险）

**目标**: 将项目中所有硬编码的 "election"/"ElectionSim" 命名替换为通用名，同时保持 100% 功能兼容。

**范围**: 环境变量重命名（兼容旧名）、容器镜像/容器名重命名、Python 包内常量重命名、Frontend 品牌更换、文档更新。

**不改**: 文件目录结构、代码逻辑、数据路径。

**验收**: 全部测试通过，Docker Compose 启动正常。

### Phase 2: 包加载机制（中风险）

**目标**: 实现领域包发现、Skills 合并、Planner Skills 动态加载。

**范围**: 创建 `packages/` 目录结构、实现 Domain Loader、拆分 Skills Registry、搬家 Claude Runtime Skills 和 Planner Skills、新增 Admin Domain 页面和 API。

**不改**: Agent 模型仍然在 agent/ 中，数据仍然在 public/ 中。

**验收**: 选举 DAG 生成与执行功能不变，Admin 面板可看到领域包信息。

### Phase 3: Agent 模型与数据解耦（中风险）

**目标**: 将 Agent 选举模型和 Public 数据移入领域包，Agent 运行时动态加载。

**范围**: Agent 模型搬家、Agent Runtime 通用化、数据层改造、Resource Audit 改造、Docker 构建流程改造、测试迁移。

**不改**: 核心流程、API 接口。

**验收**: 选举 DAG 完整执行（agenda_setter → evidence → synthesis → report），产物一致。

### Phase 4: 第二领域包验证（高风险）

**目标**: 用第二个领域包跑通完整 DAG 执行，验证解耦是否真正干净。

**候选领域**: 法律案例分析 / 金融研究报告 / 科技趋势分析

**范围**: 编写第二领域包全部内容、双领域并发验证、修复耦合残留、编写领域包开发文档。

**验收**: 两个领域包同时安装，各自生成 DAG 互不干扰，产物正确。
