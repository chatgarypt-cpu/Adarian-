# 05 — 风险与验收

## 7. 风险与对策

| 风险 | 阶段 | 概率 | 影响 | 对策 |
|---|---|---|---|---|
| Skills Registry 拆分后 ID 冲突 | P2 | 低 | 中 | 合并逻辑加 ID 前缀（`election-tw.candidate_profile`），启动时校验 |
| Planner Skills 动态加载签名不兼容 | P2 | 中 | 中 | 静态 contract 检查 + unit test |
| Agent 模型 import 路径断裂 | P3 | 高 | 高 | 渐进式迁移：先加 `sys.path` hack，后续清理 |
| 数据路径硬编码在 Skill prompt 中 | P3 | 高 | 中 | Skill prompt 模板化（`{data_root}` 运行时注入） |
| 容器挂载路径权限问题 | P3 | 中 | 低 | Windows Docker Desktop 已知限制，已有 workaround |
| 第二领域验证暴露大面积耦合残留 | P4 | 高 | 中 | 预留 3 天 buffer 专门修残留 |
| 选举 DAG 端到端回归 | P2-P4 | 中 | 高 | 每阶段结束前跑全量选举 E2E |
| Docker 镜像体积膨胀（含 packages） | P3 | 低 | 低 | packages 通过 volume mount，不烤进镜像 |

---

## 8. 验收标准

### 阶段级验收

| 阶段 | 验收标准 |
|---|---|
| P1 | 所有测试通过，Docker Compose 正常启动，前端品牌名显示 "GenFlow" |
| P2 | 选举 DAG 完整执行成功，Admin Domain 页面显示 election-tw 包，Planner 追问正常 |
| P3 | 选举 DAG 产物与搬家前一致（diff 报告），Agent 容器内无 tw_* import error |
| P4 | 法律包 DAG 执行成功，双包并发无冲突，领域包文档可指导新人创建新包 |

### 最终验收

1. **零回归**: 选举 DAG 端到端执行，产物质量与解耦前无差异
2. **第二领域可跑**: 法律分析 DAG 完整执行（意图 → Plan → Execute → Report）
3. **新领域接入 < 1 天**: 按照文档，一名开发者可以在 1 天内完成一个新领域包的基础接入
4. **不改引擎代码**: 新领域包开发者不需要修改 `genflow-core/` 任何代码
5. **多领域隔离**: 两个领域包的 DAG 并发执行互不干扰
6. **测试覆盖**: 核心模块测试覆盖率不低于解耦前水平
