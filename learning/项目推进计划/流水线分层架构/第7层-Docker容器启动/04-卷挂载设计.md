# 04 - 卷挂载设计

## 挂载体系总览

Agent 容器的文件系统通过 Docker volume/bind mount 构建，遵循**最小权限原则**：运行时可写的区域严格限制在 `/workspace/<run_id>/` 子路径下，全局共享数据以只读方式挂载。

整个挂载体系分为三个逻辑层：

```
                     Agent 容器文件系统
                    ┌───────────────────────────────────────┐
                    │                                       │
  读写挂载           │  /workspace/<run_id>/                 │
  (RW)              │    ├── data/         (运行时数据)     │
                    │    ├── input/        (输入文件)        │
                    │    ├── output/       (产物输出)        │
                    │    ├── debug/        (调试文件)        │
                    │    ├── code/         (执行时代码)      │
                    │    ├── .claude/      (Claude SDK 配置) │
                    │    └── meta/         (元数据)          │
                    │                                       │
  DAG 上游只读       │  /workspace/upstream/<node_id>/       │
  (RO)              │    (上游节点的 output 目录，逐节点挂载) │
                    │                                       │
  全局只读数据根     │  /public/                             │
  (RO)              │    (选举数据、公共资源)                 │
                    │                                       │
  开发源码只读       │  /app/agent/                          │
  (RO, 可选)        │  /app/common/                         │
                    │  /app/orchestrator/                   │
                    └───────────────────────────────────────┘
```

## 挂载一：`/workspace`（读写）

每个 Run 在 `/workspace/<run_id>/` 下拥有独立的读写工作区。这个工作区是容器运行时的核心文件系统区域。

### 目录结构初始化：`WorkspaceInitializer`

`orchestrator/workspace_initializer.py` 中的 `WorkspaceInitializer` 类（第 75 行）负责创建标准目录布局：

```python
class WorkspaceInitializer:
    def __init__(self, workspace_root: str | Path = "/workspace") -> None:
        self.workspace_root = Path(workspace_root)

    def ensure_layout(self, run_id: str, *, uid: int = 1000, gid: int = 1000) -> WorkspaceLayout:
        layout = WorkspaceLayout(run_id=run_id, workspace_root=self.workspace_root)
        for p in (
            layout.data_dir,
            layout.input_dir,
            layout.output_dir,
            layout.debug_dir,
            layout.code_dir,
            layout.claude_dir,
            layout.meta_dir,
        ):
            p.mkdir(parents=True, exist_ok=True)
        # 当 orchestrator 以 root 运行时，chown 整个 workspace 给 agent 用户
        if os.geteuid() == 0:
            for root, dirs, files in os.walk(layout.workspace):
                os.chown(root, uid, gid)
                ...
        return layout
```

创建的 7 个子目录及其用途：

| 目录 | 路径 | 容器内路径 | 用途 |
|------|------|-----------|------|
| `data/` | `/workspace/<run_id>/data/` | 同 host 路径 | 运行时产生的中间数据 |
| `input/` | `/workspace/<run_id>/input/` | 同 host 路径 | 任务 prompt (`task_prompt.md`) 等输入文件 |
| `output/` | `/workspace/<run_id>/output/` | 同 host 路径 | 核心产物目录（`report.md`, `result.json`） |
| `debug/` | `/workspace/<run_id>/debug/` | 同 host 路径 | 调试文件 |
| `code/` | `/workspace/<run_id>/code/` | 同 host 路径 | 执行时可能用到的代码 |
| `.claude/` | `/workspace/<run_id>/.claude/` | 同 host 路径 | Claude SDK 配置（settings.json, agents/, skills/） |
| `meta/` | `/workspace/<run_id>/meta/` | 同 host 路径 | 元数据（run_manifest.json, node_runs.json, skills_used.json） |

### `WorkspaceLayout` dataclass

`workspace_initializer.py` 第 38 行定义了 `WorkspaceLayout` frozen dataclass，通过 property 提供类型化的路径访问：

```python
@dataclass(frozen=True)
class WorkspaceLayout:
    run_id: str
    workspace_root: Path

    @property
    def workspace(self) -> Path:    return self.workspace_root / self.run_id
    @property
    def data_dir(self) -> Path:     return self.workspace / "data"
    @property
    def output_dir(self) -> Path:   return self.workspace / "output"
    @property
    def input_dir(self) -> Path:    return self.workspace / "input"
    @property
    def debug_dir(self) -> Path:    return self.workspace / "debug"
    @property
    def code_dir(self) -> Path:     return self.workspace / "code"
    @property
    def claude_dir(self) -> Path:   return self.workspace / ".claude"
    @property
    def meta_dir(self) -> Path:     return self.workspace / "meta"
```

### 权限处理

Agent 容器以 `user: "1000:1000"` 运行。当 orchestrator 以 root 用户运行时（容器化部署的典型场景），`ensure_layout()` 会自动递归 `chown` 整个 workspace 目录树给 uid=1000/gid=1000，确保 Agent 容器内的进程可以写入输出文件。

### `reset_layout()`：重执行时的清理

`WorkspaceInitializer.reset_layout()`（第 110 行）在重新执行时使用。它会清空已有 workspace 的所有子目录和文件，然后重新调用 `ensure_layout()`：

```python
def reset_layout(self, run_id, *, uid=1000, gid=1000) -> WorkspaceLayout:
    workspace = self.workspace_root / run_id
    # 路径遍历安全检查
    resolved = workspace.resolve()
    if not resolved.is_relative_to(self.workspace_root.resolve()):
        raise ValueError(f"Path traversal detected: {run_id}")
    if workspace.exists():
        for child in workspace.iterdir():
            if child.is_dir():
                shutil.rmtree(child, ignore_errors=True)
            else:
                child.unlink(missing_ok=True)
    return self.ensure_layout(run_id, uid=uid, gid=gid)
```

## 挂载二：`/workspace/upstream`（只读，DAG 模式专用）

DAG 调度模式下，下游节点需要读取上游节点的输出。系统通过**逐节点只读挂载**实现这一需求。

### `NodeFilesystemLayout`

`orchestrator/agent/launcher.py` 第 426 行定义的 `NodeFilesystemLayout` dataclass 描述了每个节点的文件系统布局：

```python
@dataclass(frozen=True)
class NodeFilesystemLayout:
    container_writable_root: Path       # /workspace/current
    container_output_dir: Path          # /workspace/current/output
    container_meta_dir: Path            # /workspace/current/meta
    readonly_upstreams: dict[str, Path] # {"node_a": "/workspace/upstream/node_a", ...}
    container_public_root: Path         # /public
    host_writable_root: Path            # host 上的实际路径
    host_output_dir: Path
    host_meta_dir: Path
    host_upstream_roots: dict[str, Path]# host 上的上游节点实际路径
    host_public_root: Path
```

### `build_node_filesystem_layout()`

`launcher.py` 第 458 行。根据 `upstream_node_ids` 参数，为每个上游节点构建对应的 `readonly_upstreams` 映射：

```python
def build_node_filesystem_layout(*, workspace_root, public_path,
                                  parent_run_id, node_id, upstream_node_ids):
    host_writable_root = node_workspace_path(
        workspace_root=workspace_root,
        run_id=parent_run_id,
        node_id=node_id,
    ).resolve()
    host_upstream_roots = {
        upstream_id: node_workspace_path(
            workspace_root=workspace_root,
            run_id=parent_run_id,
            node_id=upstream_id
        ).resolve()
        for upstream_id in upstream_node_ids
    }
    readonly_upstreams = {
        upstream_id: CONTAINER_UPSTREAM_ROOT / upstream_id
        for upstream_id in sorted(host_upstream_roots)
    }
```

容器内常量定义（`launcher.py` 第 420-423 行）：

```python
CONTAINER_WRITABLE_ROOT = Path("/workspace/current")
CONTAINER_CURRENT_ROOT = CONTAINER_WRITABLE_ROOT
CONTAINER_UPSTREAM_ROOT = Path("/workspace/upstream")
CONTAINER_PUBLIC_ROOT = Path("/public")
```

### `_node_workspace_mounts()`

`launcher.py` 第 378 行。将 `NodeFilesystemLayout` 转换为 Docker mount 列表：

```python
def _node_workspace_mounts(*, workspace_mount, workspace_root, layout):
    mounts = [
        # 当前节点读写挂载
        _workspace_target_mount(
            workspace_mount=workspace_mount,
            workspace_root=workspace_root,
            host_path=layout.host_writable_root,
            target=layout.container_writable_root.as_posix(),
            readonly=False,
        )
    ]
    # 逐个上游节点只读挂载
    for upstream_id, host_root in sorted(layout.host_upstream_roots.items()):
        if not host_root.exists():
            continue
        mounts.append(
            _workspace_target_mount(
                workspace_mount=workspace_mount,
                workspace_root=workspace_root,
                host_path=host_root,
                target=layout.readonly_upstreams[upstream_id].as_posix(),
                readonly=True,
            )
        )
    return mounts
```

这种设计使得每个节点：
- 对自己的 `output/` 目录拥有完全读写权限
- 对上游节点的 `output/` 目录仅拥有只读访问权限
- 无法修改或破坏上游节点的输出产物

## 挂载三：`/public`（全局只读数据根）

`/public` 是整个系统的全局只读数据根。所有 Agent 容器以只读方式挂载此目录，确保选举数据的完整性。

### 挂载方式

`launcher.py` 第 364 行 `_public_data_mount()` 从 orchestrator 容器的 mounts 中检测 `/public` 挂载的来源类型（bind mount 或 volume），并以完全相同的配置（但强制 `ReadOnly: True`）传递给 Agent 容器：

```python
def _public_data_mount(public_mount):
    if public_mount.get("Type") == "bind":
        return {"Type": "bind", "Source": public_mount.get("Source"),
                "Target": "/public", "ReadOnly": True}
    if public_mount.get("Type") == "volume":
        return {"Type": "volume",
                "Source": public_mount.get("Name") or public_mount.get("Source"),
                "Target": "/public", "ReadOnly": True}
```

### 容器内数据访问

Agent 通过环境变量 `CLAUDE_PUBLIC_DIR=/public` 获知数据目录位置。workspace contract 中标注：

```python
"shared_data_dir": "(READ-ONLY) /public"
```

### 数据版本验证

`DAGScheduler._warn_if_dataset_version_missing()`（`scheduler.py` 第 326 行）在验证节点输出时检查 `/public/_meta/data_version.json` 中的 `dataset_version` 是否出现在 report.md 中。若缺失则记录 warning 日志。

## 挂载构建总流程：`_build_isolated_mounts()`

`orchestrator/agent/launcher.py` 第 1520 行。这是所有挂载的统一构建入口：

```python
def _build_isolated_mounts(self, docker_client, run_id, *,
                            parent_run_id, node_id, workspace_override, upstream_node_ids):
    # 1. 检查 orchestrator 容器（获取其挂载信息）
    orch = docker_client.containers.get(self.orchestrator_container_name)

    # 2. 提取 /public 和 /workspace 的挂载源
    mounts = orch.attrs.get("Mounts") or []
    public_mount = _mount_by_destination(mounts, "/public")
    workspace_mount = _mount_by_destination(mounts, "/workspace")

    # 3. 组装挂载列表
    out = [_public_data_mount(public_mount)]
    out.extend(_dev_source_mounts(mounts))  # 开发模式：/app/agent 等源码挂载

    # 4. 节点模式：构建精细化的逐节点挂载
    layout = self._node_layout_for_mounts(...)
    if layout is not None:
        out.extend(_node_workspace_mounts(workspace_mount, self.workspace_root, layout))
        return out

    # 5. Run 模式：简单挂载整个 run workspace
    out.extend(_run_workspace_mounts(workspace_mount, run_id, parent_run_id))
    return out
```

### Volume 与 Bind Mount 的兼容处理

`_workspace_target_mount()`（第 336 行）和 `_workspace_subpath_mount()`（第 315 行）同时支持两种挂载类型：

- **Volume**：使用 `VolumeOptions.Subpath` 指定子路径
- **Bind Mount**：拼接 host 路径（处理 Linux/macOS 的 POSIX path 和 Windows 的 `C:\...` 路径）

这一兼容层使得系统既能在 Docker Desktop（通常用 bind mount）也能在纯 Linux Docker（通常用 named volume）环境下正确运行。

## `node_workspace_path()` 路径解析

`orchestrator/dag/run_ids.py` 第 33 行。这是计算节点 workspace host 路径的核心函数：

```python
def node_workspace_path(*, workspace_root: str | Path, run_id: str, node_id: str) -> Path:
    root = Path(workspace_root)
    return (root / str(run_id).strip() / "output" / str(node_id).strip()).resolve()
```

例如，对于 `run_id="abc123"`, `node_id="data_collector"`，返回：

```
/workspace/abc123/output/data_collector
```

对应的容器内路径由 `container_node_workspace()`（同文件第 38 行）计算：

```python
def container_node_workspace(run_id: str, node_id: str) -> str:
    return f"/workspace/{run_id}/output/{node_id}"
```

### `build_node_run_id()`

`run_ids.py` 第 16 行。为每个 DAG 节点生成独立的 node_run_id，用于独立的运行追踪：

```python
def build_node_run_id(parent_run_id: str, node_id: str) -> str:
    raw = f"{parent}_{node}"
    if len(raw) <= 64 and RUN_ID_PATTERN.match(raw):
        return raw
    # 过长时：截断 + MD5 后缀
    digest = hashlib.md5(raw.encode()).hexdigest()[:8]
    return f"{short_parent}_{short_node}_{digest}"[:64]
```

## 开发模式源码挂载

`_dev_source_mounts()`（`launcher.py` 第 495 行）在开发环境下将 orchestrator 的源码目录以只读方式挂载到 Agent 容器中：

```python
_DEV_SOURCE_MOUNT_TARGETS = ("/app/agent", "/app/common", "/app/orchestrator")

def _dev_source_mounts(orchestrator_mounts):
    mounts = []
    for target in _DEV_SOURCE_MOUNT_TARGETS:
        source_mount = _mount_by_destination(orchestrator_mounts, target)
        if source_mount and source_mount.get("Type") == "bind":
            mounts.append({"Type": "bind", "Source": source_mount["Source"],
                           "Target": target, "ReadOnly": True})
    return mounts
```

这使得在 Docker Compose 环境下，Agent 容器可以访问最新的 `agent/`、`common/`、`orchestrator/` 代码（bind mount 实时同步），而不需要重新构建镜像。

## 安全措施

1. **`run_id` 格式校验**：`RUN_ID_PATTERN = re.compile(r"^[a-zA-Z0-9][a-zA-Z0-9_-]{0,63}$")`，防止路径遍历攻击。
2. **路径遍历防护**：`reset_layout()` 和 `cleanup()` 中通过 `Path.resolve().is_relative_to()` 确保操作不超出 `workspace_root` 边界。
3. **只读挂载**：所有共享数据（`/public`、`/workspace/upstream/*`）强制 `ReadOnly: True`。
4. **权限隔离**：Agent 容器以 `user: "1000:1000"` 运行，不拥有 root 权限。
5. **工作区隔离**：每个 run 有独立的 `/workspace/<run_id>/` 子目录，run 之间文件系统隔离。
6. **`no_new_privileges`**：通过 `_agent_container_resource_limits()` 中的安全选项防止权限提升。
