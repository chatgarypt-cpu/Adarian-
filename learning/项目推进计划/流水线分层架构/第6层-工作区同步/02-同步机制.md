# 02-同步机制详解

## 1. sync_workspace_skills() 完整逻辑

`sync_workspace_skills()` 是工作区同步的核心入口函数，位于 `orchestrator/agent/workspace_skills.py` 第 22-38 行。

### 1.1 函数签名与参数

```python
def sync_workspace_skills(
    workspace: Path,            # 目标工作区路径（如 /workspace/<run_id>）
    *,
    source_dir: Path | None = None,  # 可选的源 skills 目录（不传则自动解析）
    node_mcp: dict | None = None,    # 节点的 MCP 运行时配置，用于模板渲染
) -> Path:                           # 返回 .claude/skills 的目标路径
```

### 1.2 执行步骤

```
sync_workspace_skills(workspace, source_dir, node_mcp)
│
├── 1. 解析 source_dir
│   └── source_dir or default_skills_dir()
│       └── common/claude_runtime_assets.py:default_runtime_skills_dir()
│
├── 2. 路径校验
│   └── if not src.exists() → raise RuntimeError
│
├── 3. 计算目标路径
│   └── dest = workspace / .claude / skills
│
├── 4. 全量清理旧投影
│   └── if dest.exists() → shutil.rmtree(dest)
│
├── 5. 复制 skills 投影
│   └── _copy_runtime_skill_projection(src=src, dest=dest)
│
├── 6. 渲染 MCP 模板变量
│   └── _render_workspace_markdown(dest, node_mcp=node_mcp)
│
├── 7. 同步 agents 目录
│   └── _sync_workspace_agents(workspace, skills_source_dir=src, node_mcp=node_mcp)
│
├── 8. 校验 agent 定义
│   └── validate_workspace_agents(workspace)
│
└── 9. 返回 dest
```

### 1.3 步骤详解

#### 步骤 5: _copy_runtime_skill_projection() — 扁平化投影

`workspace_skills.py` 第 41-49 行。这是整个同步机制最核心的函数：

```python
def _copy_runtime_skill_projection(*, src: Path, dest: Path) -> None:
    dest.mkdir(parents=True, exist_ok=True)
    _copy_runtime_root_assets(src=src, dest=dest)  # 复制 _shared/ 和根级文件
    for skill_doc in _iter_source_skill_docs(src):   # 遍历所有 SKILL.md
        skill_name = _skill_runtime_dir_name(skill_doc)  # 从 frontmatter 提取名称
        target = dest / skill_name
        if target.exists():
            raise RuntimeError(f"duplicate runtime skill projection: {skill_name}")
        shutil.copytree(skill_doc.parent, target)   # 复制整个父目录
```

关键行为：

- `_iter_source_skill_docs()`（第 61-66 行）递归扫描 `src` 下所有 `SKILL.md` 文件，**排除** `_shared` 目录下的文件。
- `_skill_runtime_dir_name()`（第 69-73 行）读取 SKILL.md 的 YAML frontmatter，取 `name` 字段作为目标目录名；若 `name` 为空，回退为父目录名。
- **去重检查**：如果两个不同的源目录生成相同的 `skill_name`，会抛出 `RuntimeError`。

#### _copy_runtime_root_assets() — 共享资源复制

`workspace_skills.py` 第 52-58 行：

```python
def _copy_runtime_root_assets(*, src: Path, dest: Path) -> None:
    for child in sorted(src.iterdir(), key=lambda item: item.name.lower()):
        if child.name == "_shared" and child.is_dir():
            shutil.copytree(child, dest / child.name)  # _shared 目录整体复制
            continue
        if child.is_file():
            shutil.copy2(child, dest / child.name)     # 根级文件逐个复制
```

`_shared` 目录被原样复制到 `.claude/skills/_shared/`，供所有 skill 引用共享资源。根级文件（如 `README.md`、`OPTIMIZATION_SUMMARY.md`）也会被复制。

#### 步骤 6: _render_workspace_markdown() — 模板渲染

`workspace_skills.py` 第 87-93 行。扫描目标目录下所有 `.md` 文件，调用 `render_mcp_text()` 替换其中的 `{{MCP_*}}` 占位符。详见文件 `03-MCP模板渲染.md`。

#### 步骤 7: _sync_workspace_agents() — Agent 同步

`workspace_skills.py` 第 76-84 行：

```python
def _sync_workspace_agents(*, workspace, skills_source_dir, node_mcp):
    source_agents_dir = skills_source_dir.parent / "agents"  # claude-runtime/agents/
    dest_agents_dir = workspace / ".claude" / "agents"
    if dest_agents_dir.exists():
        shutil.rmtree(dest_agents_dir)
    if not source_agents_dir.exists():
        return  # 如果源 agents 目录不存在，直接返回
    shutil.copytree(source_agents_dir, dest_agents_dir)
    _render_workspace_markdown(dest_agents_dir, node_mcp=node_mcp)
```

与 skills 同步的区别：agents 目录**不平化**，直接整目录复制。复制后同样对 `.md` 文件执行 MCP 模板渲染。

#### 步骤 8: validate_workspace_agents() — Agent 校验

`agent/custom_agents.py` 第 53-54 行。校验 `.claude/agents/` 下的每个 agent 定义的 YAML frontmatter，确保字段类型正确（model 限制为 `sonnet/opus/haiku/inherit`、tools/skills/mcpServers 为 list 类型、maxTurns 为 int 等）。

## 2. 扁平化投影机制详解

### 2.1 源目录的层次结构 vs 容器内的扁平结构

宿主机上的 skills 按功能域组织为多层子目录：

```
claude-runtime/skills/
  dag/entry/<skill-a>/SKILL.md      →  .claude/skills/<skill-a>/SKILL.md
  dag/analysis/<skill-b>/SKILL.md   →  .claude/skills/<skill-b>/SKILL.md
  shared/runtime/<skill-c>/SKILL.md →  .claude/skills/<skill-c>/SKILL.md
```

扁平化的依据是 SKILL.md 的 YAML frontmatter 中的 `name` 字段：

```yaml
---
name: my-skill-name
description: ...
---
```

如果 `name: csv-task-spec`，则目标目录为 `.claude/skills/csv-task-spec/`，无论其源路径有多深。

### 2.2 去重保护

如果在递归扫描过程中发现两个 SKILL.md 声明了相同的 `name`，会在 `_copy_runtime_skill_projection()` 中抛出 `RuntimeError`，防止不可预知的行为。

### 2.3 _shared 的特殊处理

`_shared` 目录**不参与扁平化**。它被原样复制到 `.claude/skills/_shared/`。`_shared` 下的 SKILL.md 也在 `_iter_source_skill_docs()` 中被显式跳过（通过 `"_shared" not in path.relative_to(src).parts`）。

## 3. 路径解析与 default_runtime_skills_dir()

源 skills 目录的解析链（`common/claude_runtime_assets.py`）：

```
sync_workspace_skills(source_dir=None)
  → default_skills_dir()                          [skill_docs.py]
    → default_runtime_skills_dir()                [claude_runtime_assets.py:27]
      → default_claude_runtime_dir()              [claude_runtime_assets.py:16]
        → claude_runtime_dir_for_repo(repo_root())  [claude_runtime_assets.py:20]
```

`claude_runtime_dir_for_repo()` 的核心逻辑（第 20-24 行）：

```python
def claude_runtime_dir_for_repo(root: Path) -> Path:
    env_dir = os.environ.get(CLAUDE_RUNTIME_DIR_ENV)  # "ELECTIONSIM_CLAUDE_RUNTIME_DIR"
    if env_dir:
        return Path(env_dir)
    return Path(root) / CLAUDE_RUNTIME_DIRNAME  # "claude-runtime"
```

解析优先级：

1. 环境变量 `ELECTIONSIM_CLAUDE_RUNTIME_DIR`（如果设置）→ 直接使用该路径
2. 未设置 → `repo_root() / "claude-runtime"`（项目根目录下的 claude-runtime/）

`repo_root()` 通过 `Path(__file__).resolve().parents[1]` 解析——因为 `claude_runtime_assets.py` 在 `common/` 下，所以 `parents[1]` 回到项目根目录。

## 4. ELECTIONSIM_CLAUDE_RUNTIME_DIR 环境变量

该环境变量提供了一种**在不修改代码的情况下覆盖 claude-runtime 路径**的机制。使用场景包括：

- **多仓库共享**：多个项目共享同一套 skill 定义，通过环境变量指向共享路径。
- **开发/调试**：临时切换到定制版本的 skills 进行测试。
- **CI/CD**：不同的构建环境可能有不同的 claude-runtime 路径。

环境变量的常量定义在 `common/claude_runtime_assets.py` 第 7 行：

```python
CLAUDE_RUNTIME_DIR_ENV = "ELECTIONSIM_CLAUDE_RUNTIME_DIR"
```

如果设置了该环境变量，`default_claude_runtime_dir()` 和 `default_runtime_skills_dir()` 等所有路径解析函数都会直接使用该路径，跳过项目根目录的默认逻辑。

## 5. Planning Agent 的 Workspace 准备

Planning Agent 使用临时目录作为其 workspace，同样需要同步 skills。

`orchestrator/chat/planning_agent.py` 第 144-156 行：

```python
async def _run_sdk_session(*, prompt, config):

    sync_workspace_skills(work_dir, source_dir=default_runtime_skills_dir())
    return work_dir
```

DAG Planner 也有类似的处理，`orchestrator/dag/plan_transport.py` 第 80-82 行：

```python
def _prepare_planner_workspace(workspace: Path) -> Path:
    sync_workspace_skills(workspace, source_dir=default_runtime_skills_dir())
    return workspace
```

两者都**不传 `node_mcp`**（使用默认值 `None`），因为 Planning Agent 和 Planner 使用临时目录且不涉及 MCP 工具调用。

## 6. DAG 节点 Agent 的 Workspace 准备

对于实际执行 DAG 节点的 Agent（`orchestrator/agent/launcher.py`），同步逻辑在容器启动前执行：

```python
# launcher.py 第 653 行 — RunContainerManager._start() 内部
ctx.setup()  # 创建 workspace 目录结构

```

两次调用的区别：

- 第一次（`_start()` 内）：不传 `node_mcp`，在目录结构创建后立即同步基础 skills。
- 第二次（`_generate_workspace()` 内）：传入 `resolved_node_mcp`，确保 skill 文档中的 MCP 占位符被替换为当前节点可用的具体工具名。

## 8. 增量 vs 全量同步策略

当前实现采用**全量同步**策略：

- **全量清理**：每次同步前 `shutil.rmtree(dest)` 删除已有 `.claude/skills/` 和 `.claude/agents/`。
- **全量复制**：`shutil.copytree()` 从源目录完整复制所有内容。

选择全量而非增量的理由：

1. **简单可靠**：避免增量同步的脏状态（如 skill 被删除但旧文件残留）。
2. **文件量小**：skills 目录下的文件总量不大（几十个 Markdown 文件），复制开销可忽略。
3. **不可变性保证**：每次启动前确保容器看到的 skill 定义与宿主机源完全一致。

`shutil.copytree()` 的行为：
- 如果 `target` 已存在 → 抛 `FileExistsError`（所以必须先 `rmtree`）。
- 递归复制所有文件和子目录。
- 保留文件元数据（通过内部的 `copy2` 行为）。
