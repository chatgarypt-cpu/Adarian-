# 04-容器工作区布局

## 1. 整体路径映射

Workspace 的物理存储位于宿主机的 `/workspace/<run_id>/` 下，通过 Docker volume/bind mount 映射到容器内的相同路径。`NodeFilesystemLayout`（`orchestrator/agent/launcher.py` 第 426-455 行）定义了两套路径体系：

- **Host 路径**：宿主机上的实际文件系统路径。
- **Container 路径**：容器内 Agent 看到的路径。

```
宿主机                               容器内
/workspace/<run_id>/          ←→    /workspace/<run_id>/
  <node_id>/                 ←→      /workspace/current/      (CONTAINER_WRITABLE_ROOT)
    input/                   ←→        input/
    meta/                    ←→        meta/
    output/                  ←→        output/
    debug/                   ←→        debug/
    .claude/                 ←→        .claude/
```

关键常量（`launcher.py` 第 420-423 行）：

```python
CONTAINER_WRITABLE_ROOT = Path("/workspace/current")
CONTAINER_UPSTREAM_ROOT = Path("/workspace/upstream")
CONTAINER_PUBLIC_ROOT = Path("/public")
```

容器内的 `/workspace/current` 是当前节点的可写根目录，等价于宿主机的 `/workspace/<run_id>/<node_id>/`。上游节点的输出通过只读挂载映射到 `/workspace/upstream/<upstream_node_id>/`。

## 2. 完整目录布局

以 `/workspace/<run_id>/` 为视角（宿主机与容器内路径一致），完整的目录布局由 `WorkspaceInitializer.ensure_layout()`（`orchestrator/workspace_initializer.py` 第 79-108 行）创建：

```
/workspace/<run_id>/
├── data/                         # 数据文件缓存目录
├── input/                        # 输入文件（只读）
│   └── task_prompt.md            # 任务提示文本
├── meta/                         # 元数据/配置文件（只读）
│   ├── node_context.json         # 节点上下文
│   ├── time_context.json         # 时间基准
│   ├── node_execution_config.json # 执行配置
│   ├── parent_run.json           # 父运行信息
│   ├── batch_runtime_state.json  # 批处理运行时状态
│   ├── execution_budget_usage.json # 执行预算使用
│   └── retry_budget_state.json   # 重试预算状态
├── output/                       # 输出文件（Agent 可写）
│   ├── result.json               # 结果摘要
│   ├── report.md                 # 主报告
│   ├── task_spec/                # CSV 任务规格
│   │   └── <node_id>_todo.csv
│   └── artifacts/                # 其他产出物
├── debug/                        # 调试文件（可写）
│   ├── launcher.json             # Launcher 调试快照

```


## 3. 各目录详解

### 3.1 input/ 目录

| 文件 | 写入方 | 读取方 | 内容 |
|------|--------|--------|------|
| `task_prompt.md` | Launcher（`runtime_files.py:prepare_agent_runtime_files()`） | Agent | 任务提示，含时间基准前缀 |

`task_prompt.md` 的内容包含两部分：
1. **时间基准块**（前缀）：由 `render_time_context_prompt_block()` 生成，告知 Agent 当前的 UTC/本地时间。
2. **任务正文**：由上游的 Launcher Prompt 生成，描述节点需要完成的具体任务。

### 3.2 meta/ 目录

#### 3.2.1 node_context.json

由 `orchestrator/dag/runtime_protocol.py:build_node_context()` 构建（第 111-161 行），字段详解：

```json

  "run_id": "r_20260428_abc123",            // 运行 ID
  "parent_run_id": "r_20260428_parent",      // 父运行 ID（DAG 整体运行）

  "node_id": "node_collect_001",             // 当前节点 ID
  "skill_id": "dag-collection",              // 绑定的 Skill ID
  "capabilities": {                           // 能力开关
    "external_search": true,                  // 是否允许外部搜索
    "knowledge_search": false                 // 是否允许知识库检索

  "time_context_file": "meta/time_context.json",  // 时间基准文件路径
  "resource_hints": { ... },                  // （可选）资源提示
  "mcp": {                                    // （可选）MCP 运行时配置
    "profiles": {
      "knowledge": { ... },
      "web_search": { ... }
    },
    "servers": { ... }
  },
  "execution_contract": { ... },              // （可选）执行契约
  "workspace_contract": {                     // （可选）工作区契约
```

Agent 在容器内看到的是经 `_agent_visible_node_context()` 处理后的版本，其中 `upstream_inputs` 中的宿主机路径指针（如 `host_csv_path`、`host_result_path`）已被移除，只保留容器内可见的路径。

#### 3.2.3 node_execution_config.json

由 `common/node_execution.py:NodeExecutionConfig` 定义，包含节点的执行参数，如 `required_outputs` 列表、超时设置等。Agent 通过 `load_node_execution_config()` 加载。

### 3.3 output/ 目录

Agent 的可写输出目录。核心文件：

| 文件 | 说明 |
|------|------|
| `result.json` | 执行结果摘要（status、artifacts、summary） |
| `report.md` | 主分析报告 |
| `task_spec/<node_id>_todo.csv` | CSV 任务规格文件 |
| `artifacts/` | 其他产出物 |

`result.json` 通过 `common/runtime_files.py:write_result_bundle()` 写入，包含标准化的路径信息和工件列表。

### 3.4 .claude/ 目录

这是 workspace sync 的核心产物，目录结构和内容已在 `01-概述.md` 中详述。关键点：

- **skills/**：由 `_copy_runtime_skill_projection()` 从 `claude-runtime/skills/` 扁平化投影而来。
- **agents/**：由 `_sync_workspace_agents()` 从 `claude-runtime/agents/` 原样复制。
- **settings.json**：由 `_copy_runtime_root_assets()` 从 `claude-runtime/settings.json` 复制。

所有 `.md` 文件中的 `{{MCP_*}}` 占位符已经过 `render_mcp_text()` 替换。

### 3.5 debug/ 目录

调试和审计目录，内容由 Launcher 和 Agent 运行时写入：

| 文件 | 写入方 | 内容 |
|------|--------|------|
| `launcher.json` | Launcher | 启动时配置快照（model、env、MCP 等） |
| `messages.jsonl` | Agent SDK | 逐行记录 SDK 消息 |
| `upstream_outputs.json` | 运行时 | 上游节点输出摘要 |
| `sdk_hook_issues.jsonl` | SDK Hooks | Hook 执行中遇到的问题 |

## 4. NodeFilesystemLayout 结构

`orchestrator/agent/launcher.py` 第 426-455 行的 dataclass 定义了节点的文件系统布局，同时维护宿主路径和容器内路径的对应关系：

```python
@dataclass(frozen=True)
class NodeFilesystemLayout:
    container_writable_root: Path           # /workspace/current
    container_output_dir: Path              # /workspace/current/output
    container_meta_dir: Path                # /workspace/current/meta
    readonly_upstreams: dict[str, Path]     # {upstream_id: /workspace/upstream/<id>}
    container_public_root: Path             # /public

    host_writable_root: Path                # /workspace/<run_id>/<node_id>
    host_output_dir: Path                   # /workspace/<run_id>/<node_id>/output
    host_meta_dir: Path                     # /workspace/<run_id>/<node_id>/meta
    host_upstream_roots: dict[str, Path]    # {upstream_id: /workspace/<run_id>/<upstream_id>}
    host_public_root: Path                  # /public (same as container)
```

该 layout 通过 `env_payload()` 序列化为 JSON 并注入到容器的 `CLAUDE_NODE_FS_LAYOUT` 环境变量中，供 Agent 运行时解析路径。

## 5. 目录的读写权限和生命周期

### 5.1 权限设计

| 目录 | 宿主机权限 | 容器内权限 | 说明 |
|------|-----------|-----------|------|
| `input/` | root/1000 可写 | Agent (1000) 只读 | Launcher 写入后不修改 |
| `meta/` | root/1000 可写 | Agent (1000) 只读 | 同上 |
| `.claude/` | root/1000 可写 | Agent (1000) 只读 | sync 产物，容器内不修改 |
| `output/` | root/1000 可写 | Agent (1000) 可写 | Agent 核心产出目录 |
| `debug/` | root/1000 可写 | Agent (1000) 可写 | 调试日志 |
| `data/` | root/1000 可写 | Agent (1000) 可写 | 数据缓存 |
| `code/` | root/1000 可写 | Agent (1000) 可写 | 工作代码 |

`WorkspaceInitializer.ensure_layout()` 在创建目录后会尝试 `chown` 到 `uid=1000, gid=1000`（即 Agent 容器的默认用户），确保容器内的 Agent 进程可以写入 `output/` 和 `debug/` 等目录。

### 5.2 生命周期

```
Workspace 创建
│
├── ensure_layout()               # 创建目录骨架 + chown
│
├── prepare_agent_runtime_files() # 写入 input/task_prompt.md,
│                                 # meta/time_context.json,
│                                 # debug/launcher.json
│
├── sync_workspace_skills()       # 投影 .claude/skills + agents + settings
│                                 # 渲染 MCP 模板变量
│
├── Docker container launch       # Agent 启动，读写 workspace
│   ├── Agent 读取 input/ meta/ .claude/
│   ├── Agent 写入 output/ debug/
│   └── Agent 退出
│
├── 结果收集                      # Orchestrator 读取 output/result.json
│
└── cleanup() / archive           # 清理或归档整个 workspace
    ├── archive=False → rmtree
    └── archive=True  → move → /workspace/archived/<run_id>__<timestamp>
```

`WorkspaceInitializer.cleanup()`（第 131-173 行）支持两种清理模式：

- **archive=True**（默认）：将 workspace 移动到 `/workspace/archived/` 下，带时间戳后缀。
- **archive=False**：直接 `rmtree` 删除，可选择 `preserve_evidence=True` 来先保存证据快照。

## 6. 容器内 Agent 环境变量

Launcher 向容器注入一系列 `CLAUDE_*` 环境变量，告知 Agent 关键文件路径（`launcher.py` 第 2263-2325 行）：

| 环境变量 | 含义 |
|----------|------|
| `CLAUDE_TASK_PROMPT_PATH` | task_prompt.md 的路径 |
| `CLAUDE_NODE_CONTEXT_PATH` | node_context.json 的路径 |
| `CLAUDE_TIME_CONTEXT_PATH` | time_context.json 的路径 |
| `CLAUDE_HOST_WORKSPACE` | 宿主机 workspace 路径 |
| `CLAUDE_HOST_OUTPUT_DIR` | 宿主机 output 目录路径 |
| `CLAUDE_PUBLIC_DIR` | 公共数据目录（/public） |
| `CLAUDE_SHARED_WORKSPACE` | 共享 workspace 路径 |
| `CLAUDE_NODE_FS_LAYOUT` | NodeFilesystemLayout 的 JSON 序列化 |
| `CLAUDE_NOW_UTC` | 当前 UTC 时间 |
| `CLAUDE_TODAY_UTC` | 当前 UTC 日期 |
| `CLAUDE_SKILLS_DIR` | .claude/skills 路径 |

Agent 容器内的 `common/runtime_files.py` 通过读取这些环境变量（`_env_path()`、`_env_json()`）来还原完整的路径体系。

## 7. 上游节点产物的只读挂载

上游节点的产出通过 Docker 的只读 bind mount 提供给当前节点：

```python
# launcher.py _node_workspace_mounts() 第 378-405 行
readonly_upstreams = {
    upstream_id: CONTAINER_UPSTREAM_ROOT / upstream_id
    for upstream_id in host_upstream_roots
}
# 对每个 upstream 创建一个 readonly bind mount
```

容器内 Agent 通过 `/workspace/upstream/<node_id>/output/` 访问上游产出，无法修改上游数据。

## 8. 关键安全约束

1. **run_id 校验**：`WorkspaceInitializer` 通过正则 `^[a-zA-Z0-9][a-zA-Z0-9_-]{0,63}$` 校验 run_id，防止路径遍历攻击。
2. **路径约束**：`cleanup()` 中通过 `resolved.is_relative_to(workspace_root.resolve())` 确认要清理的路径确实在 workspace_root 之内。
3. **chown 到 Agent UID**：确保 `root` 创建的目录对 `uid=1000` 的 Agent 容器可写。
4. **上游只读**：上游节点的 workspace 以 `readonly=True` 挂载，防止 Agent 越权修改。
