# 01 - 概述

## Launcher Prompt 在整个流水线中的位置

第5层位于流水线中段，承接第4层 DAG 物化器（Materializer）产出的 `GeneratedDAG`，并在第6层工作区同步（Workspace Sync）之前执行。其核心使命是：**将抽象的 DAG 节点描述转化为 Agent 容器内可直接执行的 `task_prompt.md`**。

```
第0-3层                      第4层                      第5层 (本层)              第6层+
意图路由 ─→ 规划器 ─→ 验证    DAG 物化器                Launcher Prompt          工作区同步
修复循环 ─→ Skill 绑定  ─→  GeneratedDAG  ─┬─→ build_node_prompt() ─→ task_prompt.md ─→ 容器启动
                                           │
                                           └── 拓扑排序 + 资源搜索注入
```

本层在所有需要启动 Agent 容器的时机被调用：
- **调度器路径**：`orchestrator/dag/scheduler.py` 的 `_build_node_prompt()` 方法在第462行直接委托给 `build_node_prompt()`；
- **单节点执行路径**：`orchestrator/dag/launcher_executor.py` 在第964行调用 `build_node_prompt()`，传入从 `runtime` 上下文中解析的全部参数。

## 核心职责

本层唯一职责：**为每个 DAG 节点组装一份 `task_prompt.md`**。这份文件被写入容器的 `input/task_prompt.md`（由 `common/runtime_files.py` 第19行定义 `TASK_PROMPT_REL = "input/task_prompt.md"`），是 Agent 会话启动后读取的第一份指令文档。

## 入口函数

`build_node_prompt()` 位于 `orchestrator/dag/launcher_prompt.py` 第340行，签名如下：

```python
def build_node_prompt(
    *,
    node: DAGNode,
    skill: str,
    description: str,
    current_run_id: str,
    parent_run_id: str,
    language_constraint: str,
    search_prompt_constraint: str,
    resource_audit: dict[str, Any] | None = None,
    required_outputs: list[str] | None = None,
    search_enabled: bool = True,
    node_mcp: dict[str, Any] | None = None,
    dag_topology: dict[str, Any] | None = None,
    extra_prompt: str | None = None,
) -> str:
```

函数返回一个完整的长字符串 —— 即 `task_prompt.md` 的全文内容。该函数纯函数式，不产生副作用，所有状态从参数注入。

## 输入来源

`build_node_prompt()` 的输入来自流水线前序阶段的累积产物：

| 输入 | 来源 | 说明 |
|------|------|------|
| `node: DAGNode` | `workflow_models.py` 的 `DAGNode` dataclass | 节点 ID、label、agent_config、block_profile、layer 等 |
| `skill: str` | 第3层 Skill Auto-Binder 的绑定结果 | 决定 SCOPE_LINES 匹配（agenda_setter / candidate_registry_searcher 等） |
| `description: str` | `node.agent_config.get("description")` | 节点任务的自然语言描述 |
| `resource_audit: dict` | 第4层 Materializer 的资源搜索审计结果 | 包含 `matchedPaths`、`deepExploration.matchedFiles`，由 `resource_hints.py` 提取为 seed_paths |
| `required_outputs: list[str]` | 从 DAG 拓扑合约中提取 | 例如 `["output/report.md", "output/evidence_map.json"]` |
| `search_enabled: bool` | 搜索 MCP 配置状态 | 决定 READ_PROTOCOL_LINES 使用 knowledge 版还是 local-only 版 |
| `node_mcp: dict` | MCP 配置管理器 | 控制 knowledge profile 启停、MCP 工具别名注入 |
| `language_constraint` | 规划代理输出的语言偏好 | 注入到 prompt 顶部 |
| `search_prompt_constraint` | 搜索策略约束字符串 | 由 `discovery_policy.py` 的触发策略决定 |
| `extra_prompt` | 调试注入 | 仅在 debug session 时非空，追加到 prompt 末尾 |

额外的手工构造输入：
- `node_context_file`：硬编码为 `/workspace/current/meta/node_context.json`
- `time_context_file`：硬编码为 `/workspace/current/meta/time_context.json`
- `node_execution_config_path`：从 `common/runtime_files` 的 `NODE_EXECUTION_CONFIG_REL` 常量读取

## 与上下游的接口约定

**上游期望**：
- `DAGNode` 的 `skill` 已通过 `resolve_node_skill_id()` 正确绑定（第3层产出）；
- `resource_audit` 已包含有效的 `matchedPaths` 和 `deepExploration` 结果（第4层产出）；
- `required_outputs` 列表已从拓扑合约中提取完毕。

**下游约定**：
- `task_prompt.md` 写入 `input/` 目录后，Agent 容器启动时作为第一条 `user` 消息注入；
- Prompt 中硬编码的 `node_context.json` 和 `time_context.json` 路径必须在工作区同步后真实存在；
- `Skill(csv-task-spec)` 等 skill 调用需要 `claude-runtime/skills/` 已正确投影。
