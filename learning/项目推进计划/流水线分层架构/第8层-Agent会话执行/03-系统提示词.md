# 03 - 系统提示词

## 概览

系统提示词是 Agent 容器的"宪法"——它在每次 LLM 推理之前注入，定义 Agent 的行为框架、工具纪律和输出要求。系统提示词由 `agent/system_prompt.py` 组装，分为两大块：

1. **时间基准提示词** (`build_time_system_prompt`)：告知模型当前的绝对时间基准
2. **运行时控制提示词** (`build_runtime_control_system_prompt`)：注入执行契约、工具纪律、subagent 委派策略等

在 Native Terminal Runner 中，两块提示词通过 `"\n\n"` 拼接后作为 `--append-system-prompt` 参数传给 `claude` CLI。在 SDK 路径中，则作为 `system_prompt_append` 注入 `ClaudeAgentOptions`。

---

## 3.1 时间基准注入

`build_time_system_prompt(ws: Path) -> str` (line 28) 注入运行时时间基准。

### 时间上下文加载

`election_agent._load_time_context(ws)` 按优先级加载时间上下文：

1. **文件** `meta/time_context.json`：由 Orchestrator 在容器启动前写入，包含 `now_utc`, `today_utc`, `now_local`, `today_local`, `local_timezone`, `local_utc_offset`, `unix_timestamp`
2. **环境变量**：若文件不存在，回退到环境变量 `CLAUDE_NOW_UTC`, `CLAUDE_TODAY_UTC`, `CLAUDE_NOW_LOCAL` 等
3. **运行时构建**：若两者都不存在，调用 `common.runtime_files.build_time_context()` 从 OS 时钟构建

### 提示词模板

```
你必须把下面这份运行时时间基准视为当前时间真值来源。
凡是涉及今天、当前、最近、最新、年份、选举批次、时间窗口的判断，都必须以它为准。
如果用户描述的相对时间与该基准冲突，先明确写出你采用的具体日期，再继续执行。

{time_context_prompt_block}

当前节点的时间基准文件真值路径是 `{time_context_path}`；不要改读 /workspace/<run>/meta/time_context.json 或其他猜测路径。
如需再次核对，可直接运行系统命令读取 OS 时钟，例如 `date`。
```

其中 `{time_context_prompt_block}` 由 `common.runtime_files.render_time_context_prompt_block()` 将时间 JSON 转换为自然语言描述。

## 3.2 运行时控制提示词

`build_runtime_control_system_prompt(ws: Path) -> str` (line 323) 是系统提示词的核心，组装了多层控制指令。

### 控制顺序声明

```text
你正在执行 ElectionSim-Lab 工作流节点；必须遵守以下运行时控制顺序。
1. 当前 query prompt 与当前 node context 的 execution_contract。
2. upstream_inputs、只读输入区中的已验证上游产物，以及当前工作区事实。
3. Project skill 文档仅是方法参考与检查表，不能覆盖前两项。
```

三层优先级明确：**execution_contract > 上游事实 > Skill 文档**。

### 控制文件路径

`runtime_control_file_lines(ws)` (line 189) 向模型明确传递两个关键运行时文件的确切路径：

```
- 当前节点 node context 真值路径：`{node_context_file}`。
- 当前节点 time context 真值路径：`{time_context_file}`。
- 这两个文件都是当前 node-local 运行时文件；禁止读取 .../meta/*.json 或任何凭猜测拼出的兄弟目录。
```

### CSV 执行指令

`csv_execution_lines(ws)` (line 206) 当 `node_execution_config.json` 中存在 `progress_csv_path` 时注入：

```
- 当前节点的 progress CSV 真值路径：`{progress_csv_path}`。
- 这份 progress CSV 是 runtime-owned 控制文件：先读取它来确认当前节点范围与执行步序，但不要重建文件、不要改 header、也不要把它当作本轮主交付。
- 允许的状态只有 pending、in_progress、done、blocked、error
```

### 上下文窗口策略

`context_window_runtime_lines()` (line 220) 基于环境变量 `LLM_EFFECTIVE_CONTEXT_WINDOW_TOKENS` 注入预算感知指令：

```text
- 当前项目配置的有效上下文窗口预算为 `{window_tokens}` tokens
- 当上下文变重时，优先做阶段性总结、复用已写入工作区的中间产物
- 处理长报告或长日志时，不要逐段复述原文
- 若主文稿需要整体整理，优先先收敛最终版本再一次性写回目标文件
```

`common/context_window_policy.py` 提供了辅助函数：
- `parse_effective_context_window_tokens()`：解析环境变量
- `context_window_compression_scale()`：计算压缩比例（最不低于 0.25）
- `scale_message_limit()` / `scale_char_limit()`：按比例缩放限制
- `recommended_autocompact_pct()`：计算推荐 autocompact 百分比（72%-95%）

### SDK 缓冲区策略

`common/sdk_buffer_policy.py` 通过环境变量控制 SDK/CLI 的缓冲区大小：

- `CLAUDE_AGENT_MAX_BUFFER_SIZE`：Agent 容器的缓冲区上限（主键）
- `CLAUDE_SDK_MAX_BUFFER_SIZE`：通用 SDK 缓冲区上限（回退键）
- `PLANNING_AGENT_MAX_BUFFER_SIZE`：Planning Agent 专用

`resolve_sdk_max_buffer_size()` 按主键 → 通用键顺序解析正整数环境变量值。

## 3.3 运行时控制函数

### `runtime_required_outputs(ws)` (line 43)

从 `execution_contract` 中提取 `required_outputs` 列表，返回节点必须生成的文件路径。供 `election_agent` 在收尾校验阶段使用，也注入到系统提示词中的必需输出指令：

```text
- 本节点本轮至少要真实写出：`output/report.md`、`output/result.json`
```

若没有 required outputs，则注入通用要求：

```text
- 本节点至少要真实写出一个业务文件；不要用空白协议文件伪装完成。
```

### `runtime_custom_agent_visibility(ws, compact)` (line 59)

检查工作区内自定义 subagent 的同步状态，返回 `AgentVisibility` dataclass：

```python
@dataclass(frozen=True)
class AgentVisibility:
    synced: list[str]     # 已同步到工作区的 agent 名称
    available: list[str]  # SDK 确认可用的 agent 名称
    missing: list[str]    # 同步了但 SDK 不可用的 agent 名称
```

当 SDK 未报告 agents 列表时（常见于非 Anthropic 模型），将所有已同步 agent 视为 available 以避免误判。

## 3.4 工具使用指令

`runtime_tooling_lines(ws)` (line 157) 注入工具使用纪律。核心约束包括：

### 文件操作纪律
```text
- 目录核验优先使用 LS；不要为了确认文件是否存在而先写 Bash(ls ...)。
- CRITICAL: Read / Write / Edit / Agent 只能按当前运行时真实暴露的签名调用；不要假设存在额外的 schema 加载工具
- CRITICAL: 绝对禁止盲猜参数名。Read 用 file_path，Write 用 file_path + 字符串 content，Edit 用 file_path + old_string + new_string
- CRITICAL: Write.content MUST 是字符串。写 JSON 时，先用 json.dumps(...) 把完整 payload 序列化
```

### 上游读取纪律
```text
- 读取上游产物时，优先使用任务 prompt 中"上游产出文件索引表"列出的已验证绝对路径
- 禁止按模板拼接 /workspace/upstream/<upstream_id>/output/... 或凭 node_id 猜路径
- 上游事实交接以 task prompt 上方内联的上游 progress CSV 摘要与 upstream_file_map 为准
```

### knowledge MCP 与外部搜索

```text
- knowledge MCP 可用：用于语义检索、资料库线索和文档定位
- 外部搜索可用：用于外部数据检索
- /public 是只读挂载文件树：已给出精确绝对路径时直接 Read
```

MCP 配置来自 `node_context.json` 中的 `mcp.profiles`，通过 `common/mcp_manifest.py` 的 `profile_prompt_context()` 渲染为自然语言。

## 3.5 Agent Teams 协作指令

当 `node_context.json` 包含 `team` 字段时，`_runtime_team_lines(ws)` (line 90) 注入团队协作指令：

```text
- 当前节点处于 agent teams 协作运行态，team_id=`xxx`，我的节点 id=`yyy`
- 这不是 subagent 机制；不要尝试把队友模拟成 subagent
- 开始处理共享 work item 前，先用 get_team_task_board 看现状，再用 read_team_inbox 读取队友消息
- claim_team_task 只用于新建或认领自己可接手的任务，不要用它抢占队友名下任务
- 需要 peer review 时，用 request_team_review
```

标准 team event 列表（7 个）：
1. `task_started` —— 同步分工、范围与 planned_output 文件名提示
2. `evidence_ready` —— 共享可复用证据或阶段结论
3. `risk_flag` —— 同步口径冲突、风险或阻塞
4. `review_requested` —— 请求队友评审
5. `handoff_ready` —— 通知队友可接手产物
6. `task_completed` —— 任务完成
7. `task_blocked` —— 任务受阻

## 3.6 Subagent 委派策略指令

`_runtime_subagent_strategy_lines()` (line 245) 是系统提示词中最长的指令块，约 100 行。核心策略：

### 初始化委派清单
```text
1. 在思考阶段识别所有"需要查找/搜索/读取大文件/外部检索"的信息需求。
2. 在文本输出中先列出一个委派计划表格。
3. 确认清单覆盖所有信息需求后，在同一条回复中一次性发出所有对应的 Agent/Skill 调用。
4. 禁止先发 1 个 Agent/Skill，等结果回来再发第 2 个——除非第 2 个的输入完全依赖第 1 个的输出。
```

### 强制委派规则
```text
- 任何需要搜索/查找/检索数据的操作，必须委托给对应 subagent/Skill
- 禁止主线程自己执行 Bash / Glob / Grep / WebSearch / WebFetch
```

### 各 subagent 职责速查表
| subagent | 职责 |
|----------|------|
| `data-explorer` | 发现工作区或 `/public` 中的数据文件并快速理解 schema |
| `upstream-reader` | 读取上游节点 output，提取当前任务需要的事实 |
| `evidence-aggregator` | 在 2+ 个上游之间做交叉校验、冲突检测 |
| `knowledge-researcher` | 搜索内部知识库，输出完整 evidence pack |
| `web-searcher` | 外部搜索，标注与内部基线差异 |
| `quality-checker` | 已废弃；改用 `Skill(skill="node-output-quality-check")` |

## 3.7 系统提示词层级结构（总结）

```
系统提示词 (--append-system-prompt)
│
├── [第 1 层] 时间基准 (build_time_system_prompt)
│   ├── 时间真值声明
│   ├── 时间 JSON → 自然语言
│   └── 时间文件路径引用
│
└── [第 2 层] 运行时控制 (build_runtime_control_system_prompt)
    ├── 控制顺序声明（execution_contract > upstream > skill）
    ├── 控制文件路径 (node_context, time_context)
    ├── Primary skill 声明
    ├── 可用 Skill 集合
    ├── Subagent 委派策略（含职责表 + 调用示例 + 并发模式）
    ├── 共享输入/输出目录声明
    ├── 上游文件读取纪律
    ├── CSV 执行指令
    ├── 工具使用指令（知识库、外部搜索、文件工具）
    ├── Agent Teams 协作指令（条件注入）
    ├── 上下文窗口预算与压缩策略
    └── 必需输出声明
```
