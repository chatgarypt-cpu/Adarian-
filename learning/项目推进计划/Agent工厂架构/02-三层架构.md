# 02 — 三层架构

---

## 总览

```
┌──────────────────────────────────────────────────────────────────┐
│                    第三层：主模型                         │
│                                                                    │
│   超大规模主模型。                                                 │
│   职责：理解领域本质 · 设计 Agent 宪法 · 自我进化 · 跨领域连接     │
│   它不执行具体任务，它决定「这个领域应该有什么样的 Agent 社会」     │
│                                                                    │
│   输入：已有领域包的元模式 + 新领域需求 + 质量门反馈                │
│   输出：领域蓝图 + 宪法 + 孵化指令                                  │
└────────────────────────────────────┬─────────────────────────────┘
                                     │
                                     │ 设计蓝图 + 元模式
                                     ▼
┌──────────────────────────────────────────────────────────────────┐
│                  第二层：Agent 社会（Agent Society）                │
│                                                                    │
│   主模型孵化出的领域架构师 + Subagent 集群。                      │
│   每个领域一个独立的 Agent 社会，有自己的 Skills、Planner、Models。 │
│                                                                    │
│   领域A社会   领域B社会   领域C社会   领域D社会   ...              │
│   N技能       M技能       K技能       ?技能                       │
│                                                                    │
│   每个 Agent 社会独立运行，共享底层 DAG 引擎                        │
└────────────────────────────────────┬─────────────────────────────┘
                                     │
                                     │ 运行在
                                     ▼
┌──────────────────────────────────────────────────────────────────┐
│                   第一层：GenFlow 基座（Platform）                  │
│                                                                    │
│   DAG 引擎 · LLM 网关 · 容器调度 · 事件流 · 产物注册表 · 导出引擎   │
│                                                                    │
│   对任何领域零感知。只提供「Agent 执行」的物理能力。                 │
│   暴露完整的可编程接口——Skill 注册、拓扑模板、质量门、Planner。      │
│   就像一个操作系统——不知道上面跑的是浏览器还是数据库。               │
└──────────────────────────────────────────────────────────────────┘
```

---

## 第一层：GenFlow 基座

### 它是什么

一个纯工程系统。提供 Agent 执行所需的所有物理能力。

### 它做什么

| 能力 | 实现 |
|---|---|
| DAG 编排 | 意图 → Plan → 编译 → 校验 → 物化 → 执行 |
| 容器调度 | Docker 创建/销毁、资源限制（CPU/内存/PID）、超时保护 |
| LLM 网关 | Anthropic/OpenAI/Gemini 三协议转换、限流、重试、SSE |
| 事件流 | Redis Streams → SSE → 前端实时渲染 |
| 产物链 | 上游输出注册 → 下游引用 → 生命周期管理 |
| 导出 | Markdown/HTML/DOCX/XLSX/PDF |
| 调试 | dagctl CLI + REST API 双通道 |

### 它暴露什么接口给主模型

主模型不直接调这些。它通过**改写 GenFlow 的配置层**来间接控制：

| 可编程表面 | 格式 | 主模型能做什么 |
|---|---|---|
| `skills_registry.yaml` | YAML | 替换全部技能定义 |
| `skills/*/SKILL.md` | Markdown + frontmatter | 重写每个技能的执行指令 |
| `planner/*.py` | Python | 重写追问策略和 DAG 生成逻辑 |
| `models/*.py` | Python | 重写领域数据模型 |
| `workflow_topology.py` | Python | 追加新的 DAG 拓扑模板 |
| `quality_gate/*.py` | Python | 追加新的质量检查规则 |
| `settings.py` | 环境变量 | 调整模型路由、超时、并发等参数 |

## 第二层：Agent 社会

### 它是什么

一个领域包 + 它的运行时实例。概念上，是「政策分析」或「金融风控」这类领域专属的 Agent 集群。

### 结构

```
Agent 社会（packages/<domain>/）
├── 宪法（package.yaml）        ← 社会的基本法
├── 技能注册（skills.yaml）      ← 这个社会有哪些职业
├── 技能手册（skills/*/SKILL.md） ← 每个职业的 SOP
├── 追问策略（planner/）         ← 需求澄清时的对话逻辑
├── 领域模型（models/）          ← 这个社会的知识体系
└── 数据（data/）               ← 社会运行所需的原材料
```

### 社会内部的组织

```
┌─────────────────────┐
│  领域架构师 Agent     │  ← 主模型孵化，负责这个领域的整体设计
└────────┬────────────┘
         │
   ┌─────┼─────┬─────────┬──────────┐
   ▼     ▼     ▼         ▼          ▼
Entry  Evidence Synthesis Output  Review
阶段组  阶段组   阶段组    阶段组    阶段组
(1-2)  (3-5)   (2-4)    (1-2)    (1-2)
```

每个阶段组内是并行执行的 Agent 节点。阶段之间是 DAG 拓扑的边。

### Agent 社会之间的隔离

```
领域A社会          领域B社会          领域C社会
  │                  │                  │
  ▼                  ▼                  ▼
DAG Run #1         DAG Run #2         DAG Run #3
独立容器池          独立容器池          独立容器池
独立 Redis stream   独立 Redis stream   独立 Redis stream
独立产物链          独立产物链          独立产物链
```

同一个 GenFlow 实例可以同时运行多个 Agent 社会的 DAG，互不干扰。

## 第三层：主模型

### 它是什么

一个超大规模主模型。它是整个系统的「大脑」。

### 它不做什么

- 不亲自写 SKILL.md
- 不调 DAG 引擎
- 不管理容器
- 不处理用户实时请求

### 它做什么

| 职责 | 具体内容 |
|---|---|
| **理解领域本质** | 分析用户对新领域的需求，找出它与已有领域在结构上的异同 |
| **设计宪法** | 决定这个领域的 Agent 之间用什么契约通信、质量评判标准是什么 |
| **孵化架构师** | 生成领域架构师 Subagent 的任务单，派发孵化指令 |
| **审查裁决** | 接收质量门反馈，决定通过还是驳回 |
| **抽象元模式** | 每完成一个领域包，从中提取可跨领域复用的结构模式 |
| **反哺基座** | 把新的元模式写入 GenFlow 的配置层（模板、规则、策略） |

### 它的上下文管理

主模型的上下文不累积。按轮裁剪：

```
第 N 轮主模型收到的内容：
  ✓ Blueprint（领域蓝图，~10K tokens）
  ✓ 本轮失败清单（结构化 JSON，~2K tokens）
  ✓ 失败相关文件片段（~5K tokens）
  ✓ 参考领域包的元模式摘要（~3K tokens）

  ✗ 全文 SKILL.md
  ✗ 完整历史对话
  ✗ 所有 Subagent 的完整输出
  ✗ engine.py / launcher.py（它不需要知道底层实现）
```

## 三层之间的数据流

```
主模型层
  │
  │ 产出: 领域蓝图 + 宪法 + 孵化指令
  ▼
Agent 社会层
  │
  │ 产出: 领域包文件 + 质量门反馈 + 运行时指标
  ▼
GenFlow 基座层
  │
  │ 产出: 容器状态 + 事件流 + 产物注册表
  ▼
主模型层（接收质量门反馈和运行时指标，开始下一轮迭代）
```

**这是一个闭环。** 主模型不是一次性的——它在每轮迭代中变得更聪明，因为它看到的不是"这个文件对不对"，而是"这个领域的社会结构需不需要调整"。
