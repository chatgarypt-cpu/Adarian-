# 谈话要点总结（人工整理）

> 以下基于上述录音转写，按主题归纳，消除口语重复和转写错误，保留全部实质性结论。

## 一、报告五章结构最终定稿

讨论确认最终舆情报告应由 **5 个正文章节 + 附录** 组成：

| 章节 | 名称 | 内容定位 | 数据来源 |
|------|------|----------|----------|
| 一 | 舆情概要 | 真实事件背景与当前现状介绍 | 真实事件材料 |
| 二 | 舆情数据分析（新增） | 当前时间切片的真实数据分析：声量、热度、正负面情感分布、主要话题/观点聚类、KOL识别、社交网络结构 | 微博等真实社交平台数据 |
| 三 | 演化分析 | 基于多智能体推演的过程与发现，但只呈现阶段叙事、机制归纳、关键洞察，不呈现 tick 级原始指标 | 模拟推演结果（压缩后） |
| 四 | 风险研判 | 结合现状 + 演化发现，归纳未来可能发生的风险，给出结构化风险点 | 现状 + 多轮演化聚合 |
| 五 | 对策建议 | 面向政府决策者的治理动作建议 | 风险研判结论 |

**关键变化**：在传统四章（概要→风险→对策）之间，插入"真实数据分析"和"演化分析"两个支撑层，形成**态→势→判→策**的完整链路。

## 二、态势感知核心方法论：态与势的区分

**这是本次讨论最底层的概念框架：**

- **态（State）** = 当前舆情现状。包括：声量、热度、情感分布、讨论话题、关键传播者、网络结构。**传统舆情系统只做到这一步。**
- **势（Trend/Future）** = 未来可能如何演化、存在哪些风险。**势不能靠拍脑袋或经验猜测得出，必须有模拟/推演作为方法论支撑。**

```
态（真实数据切片） → 输入推演引擎 → 势（模拟涌现的风险可能性）
```

- 现在市场上大多数舆情产品"只有态没有势"
- Adarian 的核心差异竞争力 = **基于多智能体模拟的"势"的研判能力**
- 报告中的第一章（舆情概要）+ 第二章（数据分析）= 态；第三章（演化分析）= 从态到势的桥接过程；第四章（风险研判）= 势的结论

## 三、模拟数据在最终报告中的使用边界

**这是一个反复讨论的核心问题——什么数据可以出现在面向用户的最终报告中？**

### 不可以出现的数据（过程数据）
- Tick 级别的立场数值变化（如"反方从 5.0 断崖式降至 1.5"）
- 单次模拟中的具体百分比或精确数值
- 模拟过程的原始指标（个体 stance、逐轮极化指数等）
- **原因**：这些是实验室数据，对真实世界决策者无意义，反而降低报告可信度

### 可以出现的数据（结果数据）
- 多次运行中一致出现的风险类型（如"5 次独立推演中，执法公信力风险出现 4 次"）
- 聚合层面的统计结论（如"六轮推演中该风险高度存在"）
- 用于支撑"该风险可能真实发生"的归纳性数据
- **判别标准**：能帮决策者理解"为什么这个风险值得关注"的数据可以放；描述"模拟怎么跑的"的数据不要放

### 给 AI 的规则指导
- 不要做二元规则（"报告中绝对不能出现数据"），而是明确告诉 AI：**过程数据不出现、聚合结果可以出现**
- 给 AI 指定"哪些数据要讲、哪些不讲"，而不是让它自己判断

## 四、三层 AI Pipeline 架构（多跑聚合方案）

**讨论形成了清晰的"多次推演 → 结构化中间产物 → 聚合归纳 → 最终人类可读报告"流水线：**

### Layer 1：单次推演 Agent（现有）
- 每次运行产出：演化数据 + 结构化风险分析
- 输出格式：**JSON/结构化（给 AI 看，不是给人看）**
- 风险部分必须打上结构化标签（风险类型、影响群体、严重程度等）

### Layer 2：聚合归纳 Agent（新增）
- 输入：N 次独立推演的风险研判结果（N 份结构化中间报告）
- 任务：跨运行归纳——哪些风险反复出现、哪些群体始终被涉及、哪些演化路径具有一致性
- 核心洞察：**随机初始化的多次模拟中出现高度一致的风险 → 说明该风险具有结构性必然性，不只是偶然**
- 输出：一份压缩后的风险聚合报告（仍然是给 AI 的）

### Layer 3：最终报告 Agent
- 输入：①真实数据现状分析 + ②Layer 2 的风险聚合结果
- 任务：以政府决策者为读者，撰写融合真实背景与推演发现的风险研判报告
- 输出：人类可读的五章结构报告

```
           ┌──────────────────────────────────────┐
           │           Layer 3: 最终报告           │
           │    (真实现状 + 聚合风险 → 五章报告)    │
           └──────────────┬───────────────────────┘
                          │
           ┌──────────────▼───────────────────────┐
           │        Layer 2: 聚合归纳 Agent        │
           │   (N份结构化风险 → 压缩归纳 → 标签化)  │
           └──────────────┬───────────────────────┘
                          │
    ┌──────────┬──────────┼──────────┬──────────┐
    ▼          ▼          ▼          ▼          ▼
  Run 1     Run 2     Run 3     ...      Run N
(Layer 1: 单次推演 + 结构化风险输出)
```

## 五、结构化风险标签体系

**为了让 Layer 2 能做跨运行聚合，每份中间风险输出必须结构化：**

- 每个风险点携带标准化字段（类型标签、受影响群体、触发条件、升级路径、缓释条件）
- 风险类型标签示例：意识形态渗透、国家形象受损、社会内部对立、执法公信力、监管责任质疑
- AI 看到结构化标签后可以自动发现：10 份报告中 8 份提到同一标签 → 这就是高概率风险
- 当前代码中已有 `schemas/phase4.py` 定义的风险类型枚举，后续需扩展
