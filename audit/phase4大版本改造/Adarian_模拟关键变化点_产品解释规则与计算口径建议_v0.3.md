## 1. 任务结论摘要

本任务建议将“模拟关键变化点”从当前单一 `相邻轮次模拟极化指数变化绝对值 > 0.1` 的触发口径，升级为**多维信号共同支撑的产品解释规则**。

推荐结论如下：

1. **模拟关键变化点不是现实舆情真实拐点**，而是 Adarian 模拟系统中由代码侧确定性指标或可追溯日志证据支持的状态变化节点。
2. 当前单一 `|ΔP| > 0.1` 规则只适合识别“单轮突发型极化”，容易漏掉“多轮连续恶化”“关键群体迁移”“中立群体流失”和“解释框架转换”。
3. 产品侧建议保留“极化跃升型”作为一类变化点，但不应把它作为唯一变化点。
4. MVP 阶段建议采用 5 类产品类型：**极化跃升型、负向迁移型、缓冲层流失型、解释权转移型、累积恶化型**。
5. 技术侧可在后续转译时将每类变化点映射为可计算信号，但产品侧不直接设计 Python 函数、不设计 JSON 字段、不决定 tick_logs 读取方式。
6. 阈值应采用“初始候选阈值 + 小样本回放标定 + 白盒证据复核”的方式确定，不应声称某一论文直接给出了 Adarian 可照搬的阈值。
7. 报告表达应遵循“正式变化点保守、趋势提醒敏感”的原则：没有变化点不代表低风险，有变化点也不单独决定风险等级。

## 2. 模拟关键变化点的产品定义

### 2.1 稳定定义

> **模拟关键变化点**是指在 Adarian 多轮 LLM 多智能体舆情模拟过程中，由代码侧确定性指标或可追溯日志证据显示，群体立场、分化程度、关键群体态度、事件解释框架或风险承压对象在相邻轮次或连续窗口内发生具有业务解释价值的显著变化，并可能影响后续模拟风险研判的状态节点。

### 2.2 定义拆解

| 构成要素 | 产品含义 | 技术侧可转译方向 |
|---|---|---|
| 多轮模拟过程 | 必须发生在 tick 序列中，不是单条发言的主观判断 | 使用 tick 序列或滑动窗口 |
| 代码侧确定性指标或可追溯日志证据 | 变化点不能由 LLM 自行编造 | 来自 final_report / tick_logs / whitebox evidence |
| 群体状态变化 | 关注群体立场、极化、关键群体、框架、承压对象 | 构造多类候选信号 |
| 相邻轮次或连续窗口 | 同时覆盖突发型与累积型变化 | 支持单轮差值和多轮累计 |
| 业务解释价值 | 能说明“为什么值得治理侧关注” | 报告中必须解释触发原因 |
| 模拟边界 | 不等同现实舆情事实 | 模板中必须提示“模拟观察” |

### 2.3 不应这样定义

不建议将模拟关键变化点简单定义为：

> “某轮模拟极化指数变化超过阈值的节点。”

理由：

1. 该定义把变化点缩窄为单一数值事件，无法覆盖关键群体迁移、缓冲层流失和解释框架变化。
2. 该定义忽略多轮连续恶化，正是当前 test8 类漏报的根源。
3. 该定义容易让报告读者误以为“未超过阈值 = 风险平稳”。

## 3. 文献与技术参考：本方案的真实依据

> 重要说明：现有论文不能直接给出 Adarian 可照搬的“模拟关键变化点公式”或具体阈值。论文提供的是理论方向、指标合理性和方法论启发；阈值需要在 Adarian 自身样本中标定。

### 3.1 核心文献依据矩阵

| 参考方向 | 代表文献 / 技术参考 | 研究者主要结论 | 对本项目的可用结论 | 不能直接提供什么 |
|---|---|---|---|---|
| LLM 多智能体观点动力学 | Chuang et al., 2024, *Simulating Opinion Dynamics with Networks of LLM-based Agents* | LLM agents 可用于模拟意见动力学；研究关注 opinion trajectories、bias、diversity；LLM agents 也存在内生偏差，需谨慎解释 | 支撑用“模拟立场均值、分化程度、意见轨迹”观察多轮变化 | 不提供 Adarian 的变化点阈值 |
| LLM 社会模拟方法论 | Horton, 2023, *Large Language Models as Simulated Economic Agents* | LLM 可作为模拟主体探索社会科学情境，但更适合假设生成和机制探索，不应替代真实人群数据 | 支撑“模拟关键变化点是模拟观察信号，不是现实事实” | 不提供舆情风险等级或变化点公式 |
| 极化测量 | Esteban & Ray, 1994, *On the Measurement of Polarization* | 极化是群体内部认同与群体间疏离共同作用的分布结构问题，不等同于简单均值变化 | 支撑同时观察“极化指数”和“中立群体流失 / 两端聚集” | 不提供 LLM 模拟系统阈值 |
| 离线变化点检测 | Truong, Oudre & Vayatis, 2020, *Selective Review of Offline Change Point Detection Methods* | 变化点检测通常包括 cost function、search method、number-of-changes constraint；可处理多变量时间序列 | 支撑未来可将极化、立场、群体比例、框架分布组成多变量变化点识别 | 不要求产品侧设计算法 |
| 小幅持续变化检测 | NIST/SEMATECH CUSUM Control Charts | CUSUM 相较 Shewhart 控制图更适合检测过程均值的小幅持续漂移 | 支撑增加“多轮累计变化”以修复单轮阈值漏报 | 不直接给出极化阈值 |
| 信息扩散阶段 | Wu et al., 2023, Activate–Decay 信息传播模型 | 信息传播常表现为激活—峰值—衰减过程，早期峰值与长期传播规模相关 | 支撑“传播 / 风险框架可能存在阶段性节点” | 主要针对传播量，不直接针对立场变化点 |
| 情绪 / 态度驱动传播 | Li & Hu, 2025, enhanced SEIR-based public opinion dissemination model | 公共态度影响传播强度、峰值时机和扩散强度 | 支撑“立场负向迁移可作为风险节点辅助信号” | SEIR 与 Adarian 机制不同，不能直接套用公式 |
| 认知—情绪级联 | Huang et al., 2026, *DualMind* | 公关危机中短期情绪与长期认知信念共同影响 opinion trajectories | 支撑区分“短期突发变化”和“长期累积转向” | 不能直接提供本项目阈值 |
| 集体行为阈值 | Granovetter, 1978, *Threshold Models of Collective Behavior* | 群体行动可能因关键比例跨越阈值而改变 | 支撑“关键群体迁移”和“中立缓冲层流失”的业务意义 | 不提供本项目具体百分比阈值 |

### 3.2 文献综述转译为产品原则

由上述研究可形成 5 条产品原则：

1. **多轮轨迹原则**：变化点应从多轮 opinion trajectory 中识别，而不是只看单轮文本。
2. **多维证据原则**：极化指数、立场均值、群体比例、解释框架应共同支撑判断。
3. **突变与渐变并重原则**：单轮大幅跳变和多轮小幅累计都可能具有解释价值。
4. **模拟观察边界原则**：LLM agent 结果用于模拟研判，不能直接等同现实公众态度。
5. **可追溯证据原则**：正式写入报告的变化点必须能回溯到指标或日志证据。

## 4. 为什么当前单一 `|ΔP| > 0.1` 规则不够

### 4.1 它只能覆盖一种变化：单轮突发型极化

当前规则适合识别：

> 第 t 轮相较第 t-1 轮，模拟极化指数突然大幅上升或下降。

这类变化通常对应：

- 新证据曝光；
- 权威主体发声；
- 某类 Agent 突然转向强烈质疑；
- 原本中立群体被迅速卷入对立。

### 4.2 它会漏掉四类对业务有价值的变化

| 被遗漏场景 | 为什么会被漏掉 | 为什么业务上重要 |
|---|---|---|
| 多轮连续恶化 | 每轮变化都低于 0.1，但累计变化显著 | 报告会把“温水煮蛙式极化”写成无变化点 |
| 关键群体迁移 | 总体极化未大变，但重点群体转负 | 治理沟通对象已经变化 |
| 缓冲层流失 | 中立群体减少，但两端增幅分散 | 舆论回旋空间收窄 |
| 解释框架转换 | 数值变化不大，但叙事从个案转向制度质疑 | 处置重点和回应口径可能需要变化 |

### 4.3 对报告的直接风险

如果继续只看 `|ΔP| > 0.1`，报告可能出现三类问题：

1. **假阴性**：持续恶化却写成“未出现显著变化点”。
2. **解释不足**：只说明数值变化，不说明“哪类群体、哪种框架、哪类风险”发生变化。
3. **读者误解**：政府/公安读者可能把“无变化点”误读为“风险不高”。

因此，产品侧建议从单一极化阈值升级为多信号解释框架。

## 5. 建议的变化点类型

v0.3 建议采用任务卡中更易被产品和报告读者理解的 5 类主类型，并为技术侧保留“时间形态标签”。

### 5.1 类型总表

| 类型 | 业务含义 | 主要证据 | 时间形态标签 |
|---|---|---|---|
| A. 极化跃升型 | 群体分化突然加剧，立场对立明显增强 | 模拟极化指数单轮跃升、立场分布两端化 | 突变型 / 阈值跨越型 |
| B. 负向迁移型 | 关键群体或整体态度快速转向批评、不信任、质疑 | 立场均值下降、负向比例上升、关键群体 stance 转负 | 突变型 / 反转型 |
| C. 缓冲层流失型 | 中立/观望群体减少并向负向阵营流动 | neutral share 下降、negative share 上升 | 累积型 / 阈值跨越型 |
| D. 解释权转移型 | 事件主导解释框架发生变化 | top frame 改变、治理/制度/责任框架占比上升 | 激活型 / 转换型 |
| E. 累积恶化型 | 单轮变化不大，但多轮连续恶化形成显著趋势 | 连续同向变化、累计极化上升、累计负向迁移 | 累积型 |

### 5.2 为什么不再把“累积恶化型”和其他类型强行互斥

“累积恶化型”本质上是时间形态，而“极化跃升型”“负向迁移型”等是主导证据类型。为了兼容任务卡的 5 类要求，v0.3 保留“累积恶化型”作为产品类型；但在技术转译中建议将其同时标注为：

> 主导证据类型 + 时间形态标签

例如：

- 累积恶化型 / 极化结构累积上升；
- 累积恶化型 / 关键群体持续转负；
- 累积恶化型 / 中立缓冲层持续流失。

## 6. 每类变化点的触发解释、报告表达与误判边界

### A. 极化跃升型

**业务含义**  
群体分化在某一轮附近明显加剧，说明模拟舆论从相对分散或温和状态进入更强对立状态。

**可能触发条件（候选口径，非最终代码）**

- 单轮模拟极化指数 `abs(ΔP)` 达到强变化水平；
- 或极化指数进入更高业务分区；
- 或极化指数上升同时伴随两端立场 Agent 占比增加。

**建议初始阈值**

| 等级 | 候选阈值 |
|---|---|
| 强证据 | `abs(ΔP) >= 0.10` |
| 中证据 | `abs(ΔP) >= 0.08` |
| 弱候选 | `abs(ΔP) >= 0.05`，但必须有其他信号共振 |

**报告表达方式**

> 本轮模拟在第 X 轮附近出现极化跃升型模拟关键变化点，主要表现为模拟极化指数由 X.XX 升至 X.XX，群体立场分化明显增强。该节点仅反映当前模拟条件下的群体分化变化，不代表现实舆情已经同步转折。

**不应误判的情况**

- 单轮极化变化达到弱候选值，但随后迅速回落；
- 只有 1–2 个 Agent 发言激烈，但整体分布未变化；
- 极化指数变化来自样本过少或随机波动，缺少文本或群体证据。

---

### B. 负向迁移型

**业务含义**  
整体态度或关键群体态度从中性、观望、支持转向批评、不信任、质疑，说明风险基调发生变化。

**可能触发条件（候选口径，非最终代码）**

- 模拟立场均值明显向负向移动；
- 负向 Agent 占比明显上升；
- 重点群体 stance 发生方向性反转；
- 关键群体负向比例上升且持续至少两个轮次。

**建议初始阈值**

若 stance 取值为 `[-1, 1]`：

| 等级 | 候选阈值 |
|---|---|
| 强证据 | 整体立场单轮迁移 `abs(ΔM) >= 0.15`，或累计迁移 `>= 0.20` |
| 中证据 | 整体立场单轮迁移 `abs(ΔM) >= 0.10`，且负向比例上升 |
| 群体证据 | 重点群体负向比例累计上升 `>= 15 pp` |

若 stance 取值为 `[0, 1]`，建议将上述阈值约减半使用，并以项目内样本标定为准。

**报告表达方式**

> 本轮模拟在第 X 轮附近出现负向迁移型变化，主要表现为【关键群体/整体样本】由【观望/中性】转向【质疑/批评/不信任】。该变化提示当前模拟条件下风险表达主体发生变化，治理侧应关注真实舆情场中同类群体是否出现类似态度转向。

**不应误判的情况**

- 只有个别 Agent 用词负面，但群体均值和负向比例未变化；
- 负向比例上升来自同一角色重复表达，而非群体迁移；
- 负向情绪是短期情绪宣泄，未形成持续立场变化。

---

### C. 缓冲层流失型

**业务含义**  
中立/观望群体减少，舆论缓冲空间缩小。即使极化指数没有单轮大幅跃升，也可能意味着后续对立更难缓和。

**可能触发条件（候选口径，非最终代码）**

- 中立/观望 Agent 占比明显下降；
- 中立群体减少同时负向群体增加；
- 中立比例跌破警戒区间；
- 中立群体连续多轮向负向阵营迁移。

**建议初始阈值**

| 等级 | 候选阈值 |
|---|---|
| 强证据 | 中立比例累计下降 `>= 15 pp`，且负向比例累计上升 `>= 10 pp` |
| 中证据 | 中立比例单轮下降 `>= 10 pp`，且负向比例同步上升 |
| 结构性警戒 | `neutral_share <= 20%` 且 `negative_share >= 40%` |

**报告表达方式**

> 本轮模拟虽未必出现单轮极化跃升，但中立/观望群体占比持续下降，并向负向立场集中，显示模拟舆论缓冲空间收窄。该节点应作为缓冲层流失型模拟变化点进行解释。

**不应误判的情况**

- 中立比例下降但同时转向正向支持，不构成负向风险；
- 中立比例轻微波动，未连续出现；
- Agent 分类标签不稳定，导致中立/负向切换频繁但无实质文本差异。

---

### D. 解释权转移型

**业务含义**  
事件讨论重心从原始事实、个体责任或局部争议，转向制度、监管、公共价值、群体对立或治理能力质疑。该类变化对政府/公安读者尤其重要，因为它影响回应口径和承压对象。

**可能触发条件（候选口径，非最终代码）**

- 主导解释框架发生切换；
- 新风险框架从低占比升至较高占比；
- 承压主体从当事人/企业/平台转向政府、监管、学校、医院等治理主体；
- 责任归因由个体层面转向制度/监管层面。

**建议初始阈值**

| 等级 | 候选阈值 |
|---|---|
| 强证据 | 新主导框架占比 `>= 35%`，且领先第二框架 `>= 10 pp` |
| 中证据 | 某风险框架从 `<10%` 上升至 `>= 25%`，并持续 2 轮 |
| 承压对象信号 | 新 top target 占比 `>= 30%`，并连续 2 轮保持 top 1 或 top 2 |

**报告表达方式**

> 本轮模拟在第 X 轮附近出现解释权转移型变化，讨论重心由【原框架】转向【新框架】，并开始指向【承压主体/风险类型】。该变化不代表现实舆论已完成框架转换，但提示治理侧需关注真实舆情中是否出现类似叙事转向。

**不应误判的情况**

- 新框架只出现一次，未持续；
- 框架标签由 LLM 生成但无代表性文本支撑；
- 只是同义表达变化，不是责任归因或议题重心变化；
- 外部主体发声被提及，但未改变模拟讨论框架。

---

### E. 累积恶化型

**业务含义**  
单轮变化不大，但多轮连续同向恶化，最终形成足以影响风险研判的趋势。该类型是对当前 `|ΔP| > 0.1` 高假阴性问题的直接修复。

**可能触发条件（候选口径，非最终代码）**

- 极化指数连续多轮同向上升；
- 立场均值连续向负向移动；
- 负向比例连续上升；
- 中立比例连续下降；
- 解释框架持续向制度质疑、治理质疑或群体对立转移。

**建议初始阈值**

| 等级 | 候选阈值 |
|---|---|
| 强证据 | 连续 3 轮及以上同向恶化，且累计极化变化 `P_t - P_{t-k} >= 0.12` |
| 强证据补充 | 极化相对增长 `>= 50%` 且 `P_t >= 0.25` |
| 中证据 | 累计极化变化 `>= 0.10`，并伴随负向比例或中立比例变化 |
| 类别跨越 | 从低分化进入中分化，或从中分化进入高分化 |

**报告表达方式**

> 本轮模拟未出现单轮突发式跳变，但从第 X 轮至第 Y 轮，模拟极化指数/负向比例/中立比例呈连续同向变化，形成累积恶化型模拟关键变化点。该结果提示当前模拟更接近渐进式风险累积，而非单点爆发。

**不应误判的情况**

- 多轮变化方向不稳定，涨跌交替；
- 累计变化来自极低基线的百分比放大，但绝对变化很小；
- 只有数值趋势，没有任何群体或文本证据可解释；
- 模拟轮次过少，无法支持“连续趋势”判断。

## 7. 候选计算口径与阈值建议

### 7.1 总体判定逻辑

产品侧不直接设计函数，但可建议技术侧采用以下三层转译逻辑：

```text
候选信号识别 → 证据强度分级 → 报告输出分层
```

### 7.2 候选信号池

| 信号 | 对应变化点类型 | 建议用途 |
|---|---|---|
| 单轮极化变化 `abs(ΔP)` | 极化跃升型 | 识别突发分化 |
| 多轮累计极化 `P_t - P_{t-k}` | 累积恶化型 | 识别渐进极化 |
| 立场均值变化 `ΔM` | 负向迁移型 | 识别整体态度转向 |
| 重点群体 stance 变化 | 负向迁移型 | 识别关键群体变化 |
| 中立比例下降 | 缓冲层流失型 | 识别舆论回旋空间缩小 |
| 负向比例上升 | 负向迁移 / 缓冲层流失 | 识别批评质疑扩大 |
| 主导框架变化 | 解释权转移型 | 识别叙事重心变化 |
| 承压对象变化 | 解释权转移型 | 识别治理对象变化 |

### 7.3 证据强度分级

| 等级 | 判定建议 | 报告使用 |
|---|---|---|
| 强证据 | 任一强阈值信号满足，或两个以上中阈值信号共振 | 可写“出现模拟关键变化点” |
| 中证据 | 一个中阈值信号满足，且有 tick_logs 文本支撑 | 可写“出现值得关注的模拟变化节点” |
| 弱证据 | 只有弱候选信号，或分类不稳定 | 不进入正式变化点，只写趋势提醒 |
| 无证据 | 指标和文本均无明显变化 | 可写“未识别出显著模拟关键变化点” |

### 7.4 MVP 初始阈值表

> 注意：下表是**候选阈值建议**，不是产品侧直接指定的最终工程实现。技术侧应通过回放样本、人工标注和白盒审计进行标定。

| 信号 | 强证据候选阈值 | 中证据候选阈值 | 弱候选 / 辅助条件 |
|---|---:|---:|---|
| 单轮极化变化 `abs(ΔP)` | `>= 0.10` | `>= 0.08` | `>= 0.05` 且需其他信号共振 |
| 累计极化变化 `P_t - P_{t-k}` | `>= 0.12` | `>= 0.10` | 连续 3 轮同向 |
| 极化相对增长 | `>= 50%` 且 `P_t >= 0.25` | `>= 40%` 且 `P_t >= 0.25` | 需类别跨越 |
| 整体立场单轮迁移 `[-1,1]` | `>= 0.15` | `>= 0.10` | 需负向比例支持 |
| 整体立场累计迁移 `[-1,1]` | `>= 0.20` | `>= 0.15` | 连续 3 轮同向 |
| 重点群体累计迁移 `[-1,1]` | `>= 0.20` | `>= 0.15` | 群体 n>=5 或高影响 |
| 负向比例累计上升 | `>= 15 pp` | `>= 10 pp` | 需文本证据 |
| 中立比例累计下降 | `>= 15 pp` | `>= 10 pp` | 且负向比例上升 |
| 新解释框架激活 | 从 `<10%` 到 `>=25%` | 从 `<10%` 到 `>=20%` | 连续 2 轮优先 |
| 主导框架切换 | 新 top `>=35%` 且领先 `>=10 pp` | 新 top `>=30%` | 需解释标签和文本证据 |
| 承压对象切换 | 新 top `>=30%` 且持续 2 轮 | 新 top `>=25%` | 需风险解释支持 |

`pp` 指 percentage points，即百分点。

## 8. 阈值标定方法论建议

### 8.1 为什么不能直接追问“哪篇论文给出 0.1”

不建议继续把问题设定为“哪篇论文能证明 `0.1` 正确”。原因是：

1. 不同研究的极化指标定义不同；
2. Adarian 的极化指数、立场均值和 Agent 参数是项目内定义；
3. LLM agent 的输出会受模型、prompt、角色设定影响；
4. 舆情事件类型不同，合理阈值不可能完全一致；
5. 产品读者对漏报和误报的容忍度不同。

更合理的做法是：

> 文献支持“多维识别和累计检测的必要性”；具体阈值由 Adarian 项目样本标定。

### 8.2 小样本阶段标定流程

建议技术侧和产品侧共同完成以下流程：

1. **建立最小回放样本集**  
   选取不少于 20–30 个已有模拟事件，覆盖高极化、低极化、持续恶化、突发跳变、框架转换和平稳样本。

2. **双人独立标注**  
   至少 2 名产品/业务人员独立标注是否应提示变化点、变化点轮次、类型、证据强度和是否值得写入报告。轮次可允许 ±1 tick 误差。

3. **统计指标分布**  
   统计人工确认变化点和非变化点样本中的 `abs(ΔP)`、累计 `ΔP`、负向比例变化、中立比例变化、框架占比变化。

4. **确定三档阈值**  
   - 保守档：只输出强证据变化点；
   - 平衡档：强证据 + 两个中证据共振；
   - 敏感档：中证据可提示，但报告降级为“值得关注的模拟变化节点”。

5. **回归测试典型案例**  
   至少确认：
   - 现有 `abs(ΔP) > 0.1` 案例仍能识别；
   - test8 类累计极化上升案例能识别；
   - 平稳样本不会产生大量误报；
   - 每份报告正式变化点通常不超过 3 个。

6. **白盒证据复核**  
   每个正式变化点必须能回到指标变化、变化窗口、群体/框架证据和代表性文本。

### 8.3 动态阈值建议

当项目积累足够样本后，可考虑引入两类动态阈值：

**事件内动态阈值**

```text
abs(ΔP_t) > median(abs(ΔP)) + 2 * MAD(abs(ΔP))
```

或：

```text
abs(ΔP_t) > Q3(abs(ΔP)) + 1.5 * IQR(abs(ΔP))
```

适用场景：判断某次模拟内部哪一轮相对异常。  
限制：tick 数较少时不稳定，只适合作为辅助证据。

**项目库动态阈值**

```text
强阈值 = 历史人工确认变化点指标分布的第 75 分位数
中阈值 = 历史人工确认变化点指标分布的第 50 分位数
弱阈值 = 历史人工确认变化点指标分布的第 25 分位数
```

适用场景：积累 20–30 个以上回放样本后进行项目内标定。  
限制：必须同时检查无变化点样本的误触发率。

## 9. 模拟关键变化点与风险等级的关系

### 9.1 边界说明

1. 模拟关键变化点不是风险等级。
2. 模拟关键变化点可以作为风险等级判断的辅助证据。
3. 没有模拟关键变化点不代表低风险。
4. 有模拟关键变化点不一定代表高风险。
5. 多个变化点叠加，并伴随负向迁移、高极化和治理主体承压时，才应提高风险关注级别。

### 9.2 建议报告关系

| 变化点情况 | 风险等级处理建议 |
|---|---|
| 无变化点，核心指标低且稳定 | 可支持风险相对平稳判断，但不能单独作为低风险依据 |
| 无正式变化点，但存在累计趋势 | 不上调风险等级，但应写入趋势提醒 |
| 单个中证据变化节点 | 不单独上调风险等级，作为辅助观察 |
| 一个强证据变化点 | 可作为风险关注增强的依据之一 |
| 多个强证据变化点，且负向迁移 + 高极化 + 治理主体承压 | 可支持风险等级上调或重点关注建议 |

## 10. 报告表达模板

### 10.1 正式变化点模板

> 本轮模拟在第 X 轮附近识别出一处【类型】模拟关键变化点。该节点主要表现为【核心指标/关键群体/解释框架】由【前态】变化为【后态】，并伴随【辅助证据】。该变化说明，在当前模拟参数与 Agent 设定下，群体状态已出现值得解释的结构性变化。需要强调的是，该节点仅为模拟观察结果，不代表现实舆情已经发生同步转折；治理侧可进一步关注真实舆情场中是否出现【现实观察信号】。

### 10.2 关注节点模板

> 本轮模拟未形成强证据意义上的模拟关键变化点，但在第 X 轮附近出现值得关注的模拟变化节点，主要体现为【变化描述】。该节点建议作为趋势观察纳入演化分析，不宜单独作为风险等级上调依据。

### 10.3 无正式变化点但有累计趋势模板

> 本轮模拟未识别出单轮显著变化点，但这并不意味着风险不存在。从连续轮次看，【指标/群体/框架】呈现【持续上升/持续转负/持续流失】趋势，说明当前模拟更接近渐进式累积变化，而非突发式跳变。后续研判应关注该趋势是否在真实舆情数据中获得验证。

### 10.4 无明显变化模板

> 本轮模拟未识别出显著模拟关键变化点，各项核心指标未出现超过识别阈值的单轮跳变或连续累积变化。该结果仅说明在当前模拟参数下，群体立场结构暂未出现明显状态转换，不应直接推论为现实舆情风险较低。

### 10.5 放置位置建议

- “模拟关键变化点”宜放在**演化分析**部分。
- 风险等级部分可以引用变化点作为辅助证据，但不能把变化点本身等同于风险等级。
- 无显著变化点时，应避免写成“风险不存在”“舆情平稳无忧”等绝对化表述。

## 11. 正例

### 正例 1：累计极化上升但无单轮大跳变

**模拟现象**

```text
P0 = 0.19
P1 = 0.23
P2 = 0.27
P3 = 0.31
P4 = 0.36
P5 = 0.40
单轮最大 ΔP = 0.05
累计 ΔP = 0.21
```

**为什么可以标记**

- 单轮变化未超过 0.1，但连续 5 轮同向上升；
- 累计变化 0.21，超过候选累计阈值 0.12；
- 极化程度从低分化进入中等分化；
- 属于“累积恶化型 / 极化结构持续增强”。

**读者应形成的判断**

该模拟不是突发式爆点，而是持续对立累积。报告应提示治理侧关注真实舆情中是否存在持续站队、阵营化讨论和缓冲层减少。

---

### 正例 2：关键群体由观望转向质疑

**模拟现象**

```text
整体极化指数变化不大：0.34 → 0.37
本地居民群体 stance：0.05 → -0.22
本地居民负向比例：30% → 52%
```

**为什么可以标记**

- 总体极化未出现强跳变，但重点群体发生明显负向迁移；
- 负向比例上升 22 pp；
- 治理侧关注对象发生变化；
- 属于“负向迁移型”。

**读者应形成的判断**

报告不应只写“极化变化有限”，还应指出本地居民等关键群体态度转负，提示真实处置中需要关注本地群体诉求与信任修复。

---

### 正例 3：解释框架从个案争议转向监管质疑

**模拟现象**

```text
第 1–2 轮：主要讨论“当事人行为是否失当”
第 3–4 轮：开始集中讨论“平台审核是否失责 / 监管是否缺位”
监管质疑框架占比：8% → 31%，连续 2 轮保持 25% 以上
```

**为什么可以标记**

- 事件解释框架从个体行为转向制度/监管责任；
- 承压对象从当事人转向平台或监管部门；
- 该变化会影响报告建议和回应口径；
- 属于“解释权转移型”。

**读者应形成的判断**

治理侧应关注真实舆情中是否出现责任外溢，避免回应只停留在个案事实层面，而忽略制度质疑和监管承压。

---

## 12. 反例

### 反例 1：单个 Agent 激烈发言但群体指标无变化

**模拟现象**

```text
某 Agent 在第 3 轮发表强烈批评；
整体极化指数：0.31 → 0.32；
负向比例：34% → 35%；
中立比例基本不变。
```

**为什么不能标记**

- 只有单句文本激烈，不代表群体状态变化；
- 核心指标和群体比例未出现明显变化；
- 缺少连续窗口证据。

**如何避免过度解释**

可在文本摘要中提及个别激烈表达，但不应标记为模拟关键变化点。

---

### 反例 2：弱阈值波动后立即回落

**模拟现象**

```text
P1 = 0.30
P2 = 0.36
P3 = 0.31
```

**为什么不能标记**

- 第 2 轮单轮变化为 0.06，仅为弱候选；
- 下一轮迅速回落，未形成持续趋势；
- 没有群体迁移或框架转换证据。

**如何避免过度解释**

应写为“短时波动”，不应写成“出现关键变化点”。

---

### 反例 3：解释框架标签变化但语义未实质变化

**模拟现象**

```text
第 2 轮标签为“公共安全”
第 3 轮标签为“社会治理”
代表性文本仍主要讨论同一事实细节，没有责任主体转移。
```

**为什么不能标记**

- 标签变化可能来自分类器或 LLM 表述差异；
- 没有主导叙事、责任归因或承压对象的实质变化；
- 缺少代表性文本支撑。

**如何避免过度解释**

解释框架转换必须同时满足“框架占比变化 + 代表性文本变化 + 业务含义变化”，不能只看标签名变化。

---

## 13. 验收标准

### 13.1 产品侧交付验收

本规则文档应满足：

1. 清楚解释“模拟关键变化点”是什么；
2. 明确区分模拟变化点和现实舆情拐点；
3. 说明当前单一极化阈值规则的不足；
4. 提出至少 3 类变化点类型，本版提供 5 类；
5. 每类变化点均包含业务含义、可能触发条件、报告表达方式和误判边界；
6. 给出有变化点、关注节点、无正式变化点但有趋势、无明显变化四类表达模板；
7. 给出至少 3 个正例和 3 个反例；
8. 不越界设计 Python 函数、JSON 字段、tick_logs 读取方式或 Codex prompt；
9. 可被技术侧转译为 deterministic logic / whitebox / prompt 规则。

### 13.2 技术侧转译验收建议

技术侧后续转译时，建议至少通过：

1. 现有 `abs(ΔP) > 0.1` 案例仍能识别；
2. test8 类累计极化上升案例能够识别；
3. 平稳小波动样本不应输出大量正式变化点；
4. 每份报告最多输出 3 个正式模拟关键变化点；
5. 每个正式变化点必须包含至少一种指标证据；
6. 只有弱证据时，不进入正式变化点列表；
7. 无正式变化点但有累计趋势时，报告不得写成“风险不存在”；
8. 每个变化点都能被 whitebox 追溯到变化轮次、类型、主指标、辅助指标或代表性文本；
9. LLM 只解释 code-owned change points，不自行编造变化点。

---

## 14. 退回标准

如出现以下情况，应退回修改：

1. 把“模拟关键变化点”写成现实舆情真实拐点；
2. 把变化点直接等同于风险等级；
3. 只讨论阈值多少，没有解释业务意义；
4. 没有正例 / 反例；
5. 没有报告表达模板；
6. 没有无显著变化点时的表达；
7. 把产品任务写成 Python 函数、JSON 字段设计或 Codex 执行 prompt；
8. 要求本阶段接入外部态势感知；
9. 只依赖 LLM 解释，不要求 deterministic logic / whitebox 证据；
10. 对弱候选信号过度解释，导致报告误报风险过高。

## 15. 对技术侧的转译建议

### 15.1 可转译为 deterministic logic 的内容

| 产品规则 | 技术侧可转译方向 |
|---|---|
| 极化跃升型 | 单轮 `abs(ΔP)` 判断 + 极化分区跨越 |
| 累积恶化型 | 滑动窗口累计变化 + 连续同向轮次 |
| 负向迁移型 | stance mean / negative share / group stance |
| 缓冲层流失型 | neutral share 下降 + negative share 上升 |
| 解释权转移型 | frame share / top frame / target entity 变化 |
| 证据强度分级 | strong / medium / weak evidence |
| 报告表达分层 | 正式变化点 / 关注节点 / 趋势提醒 / 无明显变化 |

### 15.2 可转译为 whitebox evidence 的内容

每个正式变化点建议至少记录：

| 证据项 | 是否必要 | 说明 |
|---|---|---|
| 变化轮次或窗口 | 必须 | 第 X 轮或第 X–Y 轮 |
| 变化点类型 | 必须 | 5 类之一，可附时间形态标签 |
| 主指标变化 | 必须 | 如 P 从 0.19 到 0.40 |
| 辅助指标变化 | 建议 | 如负向比例、中立比例、框架占比 |
| 涉及群体 | 建议 | 如本地居民、学生、媒体型节点 |
| 代表性文本 | 建议 | 来自 tick_logs 的短摘录 |
| 证据强度 | 必须 | 强 / 中 / 弱 |
| 报告表达建议 | 建议 | 避免误写为现实拐点 |

### 15.3 不建议技术侧直接做的事

1. 不建议只把阈值从 0.1 改成 0.05；
2. 不建议让 LLM 自行从报告文本中“猜测”变化点；
3. 不建议没有白盒证据就输出正式变化点；
4. 不建议把解释框架转换仅建立在单次 LLM 标签上；
5. 不建议把弱证据变化直接写入“正式关键变化点”。

## 16. 最终推荐版本摘要

建议产品侧向技术侧交付以下结论：

> 本任务建议将“模拟关键变化点”定义为：多轮 LLM 多智能体舆情模拟中，由代码侧确定性指标或可追溯日志证据支持的群体状态变化节点。该节点可能体现为极化跃升、关键群体负向迁移、中立缓冲层流失、解释框架转换或多轮累积恶化。它不是现实舆情真实拐点，也不单独决定风险等级，而是报告演化分析和风险研判中的辅助解释信号。  
>
> 当前单一 `|ΔP| > 0.1` 规则只能覆盖突发型极化，不能覆盖持续缓慢恶化、关键群体首尾迁移、缓冲层流失和解释权转移。建议技术侧后续将变化点识别升级为多信号候选规则，并通过小样本回放、人工标注、敏感性分析和 whitebox 证据复核持续标定阈值。  
>
> 报告表达上，应坚持“正式变化点保守、趋势提醒敏感”的原则：有强证据时写“出现模拟关键变化点”；只有中证据时写“值得关注的模拟变化节点”；无正式变化点但有累计趋势时，应写明趋势风险；无明显变化时，也不得推论为现实风险较低。
