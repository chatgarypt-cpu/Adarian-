## 🎯 本次修复目标

### 问题 3：强制立场分布导致不真实群体
**现象**：
- 高烈度负面事件（如鼠头事件）强制生成"支持者"
- 示例：`❌ 不真实：鼠头事件中出现"校方支持者"（立场 2.5）`

**解决方案**：
- 按事件类型决定群体分布策略
- 高烈度负面事件 + 官方失信行为 → 不生成"支持者"类群体
- 官方及时处置 + 处理得当 → 可生成支持者群体

### 问题 4：负面事件立场变化不符合现实（问题的根源在问题3）
**现象**：
- 官方认错后，"支持者"立场反而上升
- 示例：`❌ 错误：校方支持者 2.2 → 3.7 (+1.5) ↑`

**解决方案**：
- 根源上解决问题3——不应该生成支持者群体
- 如果生成了，演化方向应随官方表现动态调整

## 🔧 详细修改指令

### 任务 1：修改 LLM1 Prompt - 判断群体分布策略

**文件**：`src/phase1_entity_extraction.py`

**LLM1 Prompt 扩展**：增加判断"群体分布策略"字段

**LLM1 输出新增**：

```json
{
  "event_temperature": 0.9,
  "event_intensity": 0.85,
  "event_type": "食品安全危机",
  "has_official_misconduct": true,      // 官方是否有失信行为
  "group_distribution_strategy": "no_supporters",  // "normal" | "no_supporters"
  "strategy_reason": "官方先撒谎后认错，激起民愤，不适合生成支持者群体"
}
```

**判断规则**：

| 条件 | 策略 | 说明 |
|------|------|------|
| 高烈度(≥0.8) + 负面情感 + 官方失信 | `no_supporters` | 不生成支持者 |
| 高烈度(≥0.8) + 负面情感 + 官方及时处置 | `normal` | 可生成理性支持者 |
| 其他 | `normal` | 正常生成 |

**"官方失信行为"定义**：
- 官方激起民愤后被迫认错
- 官方说法前后矛盾
- 官方试图掩盖事实

### 任务 2：修改 LLM2 Prompt - 按策略生成群体

**文件**：`src/phase1_entity_extraction.py`

**LLM2 Prompt 调整**：根据 `group_distribution_strategy` 调整群体生成规则

**`no_supporters` 策略下的群体分布**：

| 群体类型 | 可生成 | 说明 |
|---------|--------|------|
| 批评者 | ✅ | 对官方/机构持批评态度 |
| 中立观察者 | ✅ | 保持中立，客观分析 |
| 调侃者/段子手 | ✅ | 以幽默方式评论 |
| 受害者支持者 | ✅ | 支持受害者，而非支持官方 |
| 法律关注者 | ✅ | 关注法律程序 |
| 专家/媒体评论员 | ✅ | 客观分析事件 |
| 官方支持者 | ❌ | 不生成 |
| 校方支持者 | ❌ | 不生成 |

**`normal` 策略下的群体分布**（官方及时处置）：
- 可生成：理性支持者、官方认可者、法律支持者等
