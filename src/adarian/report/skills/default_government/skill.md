# Default Government Report Skill

将 `appendix_b.json` 转化为面向管理部门的舆情风险研判报告。

## 数据边界

- 只能使用 `appendix_b.json` 内的信息。
- 第一章概要只能来自 `appendix_b.meta` 和 `appendix_b.evolution_analysis.entities` 等 dataset 派生字段。
- 不得使用 `seed_input_path`、外部搜索、联网事实补充或模型自带现实知识。
- dataset 信息不足时，应保守表述为“现有数据未能支持进一步判断”。

## 结构

标题：`# [简短事件名称]舆情风险研判`

- 简短事件名称采用“核心主体 + 核心争议”，不得原样复制长事件摘要。
- 简短事件名称不超过 20 字，完整标题不超过 30 字。

正文四章：

1. `## 一、舆情概要`
2. `## 二、演化分析`
3. `## 三、风险研判`
4. `## 四、对策意见`

章内如有多条风险或对策，使用 `### （一）...`、`### （二）...`。

### 编号

- 章标题使用“一、二、三、四”。
- 节标题使用“（一）（二）（三）”，并从“（一）”连续编号。
- 更细一级措施使用“1. 2. 3.”，不得混用 A/B/C 序号。
- B 版可以少设节标题；如使用节标题，仍须遵守上述编号。

### 篇幅

- A 版自由生成，通读润色并保留 2-3 条核心对策。
- B 版正文 1400-1500 字：概要 200-300 字，演化分析 450-650 字，风险研判 400-600 字，对策意见 180-280 字。
- C 版正文 3800-4000 字：概要 400-600 字，演化分析 900-1300 字，风险研判 1000-1400 字，对策意见 1000-1400 字。
- 写完每章后自查该章篇幅，再继续下一章；不得为凑字数重复结论。

## 各章要求

- 舆情概要：仅概括事件、核心矛盾、相关主体和主要关注点，不得编造日期、处置进展、传播量或现实回应。
- 演化分析：把数据中的传播主体、风险分布和演化迹象翻译为自然语言，不罗列内部指标。
- 风险研判：每项风险说明定性判断、依据、现实传导链条和可能影响主体。
- 对策意见：按风险锚定、责任主体、行动方向和具体措施组织；不得使用“短期/中期/长期”套话结构。

## 风格

- 书面、平实、准确。
- 不使用夸张宣传语。
- 不出现对话残迹。
- 不暴露 Adarian、appendix_b、simulation_dataset、completed world、world 编号、tick 编号、立场分、极化指数等内部语言。
- 避免“值得注意的是”“深入探讨”“至关重要”“标志着”“未来可期”等填充表达。
- 对策必须包含风险锚定、责任主体、行动方向和至少一条具体措施。
